# فضای ابری مدیریت‌شده

## مقدمه

سرویس مدیریت‌شده یعنی دیسک و تعویض هارد با شرکت است و شما endpoint و کلید می‌گیرید. سه حالتی که تیم‌ها کنار این دانشنامه واقعاً استفاده می‌کنند: فضای ابری آروان، Cloudflare R2، و Amazon S3. هر سه از دید برنامه S3 هستند. فرق در نشانی، منطقه، صفحهٔ ساخت کلید، و جایی است که داده فیزیکاً می‌ماند.

این صفحه دکمهٔ پنل را به حافظهٔ یک روز خاص قفل نمی‌کند. کار را به ترتیب معنی می‌گوید. اگر نام منو عوض شد، همان معنی را در پنل پیدا کنید: ساختن صندوقچه، ساختن کلید دسترسی غیر از حساب اصلی، کپی کردن endpoint.

## مفهوم اصلی

هیچ‌کدام از این سرویس‌ها با `apt install` روی سرور شما نصب نمی‌شوند. تهیه یعنی حساب، صندوقچه، و کلید.

آروان محصول را «فضای ابری» می‌نامد و صندوقچه را در پنل می‌سازد. هر صندوقچه به یک منطقه بسته است. نشانی API منطقه در مستند خود آروان به شکل `https://s3.<region>.arvanstorage.ir` است. برای منطقهٔ سیمین که در مستند رسمی با شناسهٔ `ir-thr-at1` آمده، نشانی این است:

```text
https://s3.ir-thr-at1.arvanstorage.ir
```

شکل میزبان مجازی برای دیدن شیء:

```text
https://<bucket>.s3.ir-thr-at1.arvanstorage.ir/<key>
```

اگر پنل منطقهٔ دیگری نشان داد، همان شناسه را در نشانی بگذارید. `ir-thr-at1` را به منطقهٔ دیگر تعمیم ندهید.

Cloudflare R2 صندوقچه را در بخش R2 می‌سازد. API سازگار با S3 نشانی‌اش این شکل را دارد:

```text
https://<ACCOUNT_ID>.r2.cloudflarestorage.com
```

شناسهٔ حساب را از داشبورد Cloudflare کپی می‌کنید. منطقه در SDK معمولاً `auto` است. R2 را با پروکسی نارنجی CDN قاطی نکنید. R2 ذخیرهٔ شیء است. CDN دامنهٔ سایت است و در فصل شبکه آمده. می‌شود دامنهٔ جدا به صندوقچه وصل کرد. آن کار بعد از خصوصی ماندن پیش‌فرض است.

Amazon S3 صندوقچه را در یک منطقهٔ AWS می‌سازد. نشانی معمول:

```text
https://s3.<region>.amazonaws.com
```

اگر endpoint را خالی بگذارید، SDK خودش از منطقهٔ AWS نشانی می‌سازد. برای آروان و R2 و MinIO خالی گذاشتن endpoint یعنی رفتن اشتباه به AWS.

## چرا استفاده می‌شود؟

MinIO دیسک و بکاپ را پیش شما می‌گذارد. سرویس مدیریت‌شده این کار را برمی‌دارد و داده را از عمر یک سرور جدا می‌کند. انتخاب بین آروان و R2 و AWS بیشتر به جای داده، شبکهٔ کاربر، و قرارداد شرکت بستگی دارد تا به شکل کد. کد را یک بار با S3 بنویسید و endpoint را محیطی کنید.

برای فایل کاربر داخل ایران، نزدیک بودن منطقهٔ آروان اغلب دلیل انتخاب است. برای دارایی که باید از شبکهٔ Cloudflare خوانده شود، R2 به همان اکوسیستم نزدیک است. AWS وقتی بقیهٔ زیرساخت همان‌جاست معنی دارد. هر سه را همزمان برای یک صندوقچهٔ زنده قاطی نکنید.

## Architecture

```text
پنل شرکت
    صندوقچهٔ خصوصی
    کلید برنامه، نه کلید صاحب حساب
            │
            ▼
سرور app-1
    /etc/app/s3.env
    S3_ENDPOINT همان نشانی پنل
            │
            ▼
برنامه فقط API را می‌بیند
```

## Installation

روی سرور فقط کلاینت لازم است، و آن هم در [صفحهٔ کلاینت](./clients) است. تهیه در پنل این مراحل را دارد. اسم دکمه ممکن است فرق کند.

آروان:

1. وارد پنل شوید و محصول فضای ابری را باز کنید.
2. یک صندوقچه با نام پایدار مثل `app-uploads` در منطقه‌ای که پنل نشان می‌دهد بسازید. دسترسی را خصوصی بگذارید.
3. از صفحهٔ همان صندوقچه، endpoint را کپی کنید. اگر فقط منطقه را دیدید و نشانی را نه، با الگوی `https://s3.<region>.arvanstorage.ir` بسازید و همان را با یک `aws s3 ls` آزمایش کنید.
4. یک کلید دسترسی برای برنامه بسازید. کلید را همان لحظه ذخیره کنید.

Cloudflare R2:

1. در داشبورد R2 را باز کنید و یک bucket بسازید.
2. Account ID را از همان بخش کپی کنید.
3. یک API token با حق فقط همان bucket بسازید، نه توکن کل حساب.
4. endpoint را به شکل `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` بنویسید. منطقه را `auto` بگذارید.

AWS:

1. با حساب ریشه کلید نسازید. یک کاربر IAM بسازید.
2. سیاست آن کاربر فقط صندوقچهٔ `app-uploads` باشد: فهرست، گرفتن، گذاشتن، حذف. نه `s3:*` روی `*`.
3. صندوقچه را در منطقهٔ انتخاب‌شده بسازید و Block Public Access را روشن نگه دارید.
4. endpoint منطقه‌ای را در یادداشت بگذارید حتی اگر SDK بتواند حدس بزند، تا با محیط‌های دیگر یک شکل بماند.

## Configuration

فایل محیط روی سرور، با مقدارهای کپی‌شده از پنل. نمونه برای آروان در منطقهٔ `ir-thr-at1`:

```text
S3_ENDPOINT=https://s3.ir-thr-at1.arvanstorage.ir
S3_BUCKET=app-uploads
S3_REGION=ir-thr-at1
S3_ACCESS_KEY=از پنل
S3_SECRET_KEY=از پنل
S3_USE_PATH_STYLE=false
```

برای R2، `S3_REGION=auto` و endpoint حساب خودتان. برای MinIO، `S3_USE_PATH_STYLE=true`. این فلگ را بین محیط‌ها کور کپی نکنید.

مجوز فایل `0600` یا `0640` برای گروه `deploy` است. بعد از ذخیره، یک فهرست و یک آپلود آزمایشی با صفحهٔ کلاینت بگیرید. تا آن موفق نشده برنامه را به این endpoint سوئیچ نکنید.

اگر شیء باید از مرورگر با دامنهٔ خودتان دیده شود، دامنهٔ جدا مثل `files.example.com` را به صندوقچه وصل کنید و کش و عمومی بودن را عمداً طراحی کنید. ریشهٔ `app.example.com` را به صندوقچه ندهید. آن نام مال Nginx برنامه است.

## Production Example

تیم فایل جدید را به آروان می‌فرستد و MinIO آزمایشگاه را فقط برای توسعه نگه می‌دارد. روی `app-1` فایل `s3.env` نشانی `s3.ir-thr-at1.arvanstorage.ir` را دارد. یک شیء `health/ok.txt` از سرور آپلود و دوباره دانلود می‌شود. سپس یک آپلود از خود برنامه با کاربر واقعی آزمایشی انجام می‌شود.

کلید آزمایش توسعه‌دهنده حق صندوقچهٔ تولید را ندارد. برای لپ‌تاپ یا صندوقچهٔ `app-uploads-dev` می‌سازید یا اصلاً به MinIO محلی وصل می‌شوید.

## Security Notes

کلید پنل صاحب حساب را روی سرور نگذارید. اگر لو رفت، کل حساب در خطر است نه یک صندوقچه. کلید برنامه را باطل کنید و یکی جدید بسازید. باطل کردن، شیءها را پاک نمی‌کند.

صندوقچهٔ خصوصی را با یک سیاست عجولانهٔ «همه عمومی» برای آزمون تصویر درست نکنید. لینک امضاشده همان آزمون را انجام می‌دهد.

نسخه‌سازی را برای صندوقچه‌ای که بکاپ است روشن کنید. هزینهٔ نسخهٔ اضافی را از جدول قیمت همان روز شرکت بخوانید. این صفحه قیمت ثابت نمی‌نویسد چون عوض می‌شود.

دادهٔ حذف‌شده در بعضی سرویس‌ها چند روز در سطل زباله می‌ماند و در بعضی نه. قبل از اتکا، یک شیء آزمایشی را حذف کنید و ببینید برمی‌گردد یا نه. حدس نزنید.

## Troubleshooting

| نشانه | کار |
| --- | --- |
| Could not connect | endpoint را از پنل دوباره کپی کنید. پروکسی خروجی سرور ممکن است `dl` را باز کند و API را نه |
| 301 به AWS | endpoint خالی است و SDK به AWS رفته |
| 403 | کلید، منطقه، یا نام صندوقچه. ساعت سرور را هم ببینید |
| تصویر در مرورگر باز نمی‌شود | صندوقچه خصوصی است. این خطا نیست. لینک امضا یا عمومی کردن عمدی می‌خواهید |
| آروان شیء را نشان می‌دهد ولی CDN نه | شکل URL میزبان مجازی نیست، یا ابر رکورد خاموش است. مستند دامنهٔ اختصاصی آروان را برای همان صندوقچه بخوانید |
| R2 توکن کار نمی‌کند | توکن به bucket دیگری محدود شده یا Access Key با Secret جابه‌جا کپی شده |

## Best Practices

- endpoint را از پنل کپی کنید و در مخزن رمزنگاری‌شدهٔ تیم بگذارید، نه در گیت برنامه.
- یک صندوقچهٔ تولید و یکی برای آزمایش.
- کلید را قابل تعویض نگه دارید. برنامه باید با reload محیط کلید جدید را بگیرد، نه با تصویر تازهٔ اجباری.
- قبل از خاموش کردن MinIO قدیمی، چند شیء واقعی را از سرویس جدید خوانده باشید.
