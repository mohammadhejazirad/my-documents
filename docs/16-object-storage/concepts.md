# مفهوم S3

## مقدمه

S3 یک قرارداد HTTP برای گذاشتن و برداشتن شیء است. لازم نیست فروشنده Amazon باشد. اگر درخواست را همان شکل بپذیرد، به آن S3-compatible می‌گویند. MinIO، فضای ابری آروان، و Cloudflare R2 هر سه این قرارداد را دارند و در جزئیات منطقه و نشانی فرق می‌کنند.

این صفحه نصب نمی‌کند. اگر فقط دستور می‌خواهید به صفحهٔ نصب همان حالت بروید. بدون این مفهوم، خطای 403 و خطای endpoint مثل هم به نظر می‌رسند.

## مفهوم اصلی

صندوقچه ظرف سطح بالاست. نامش در کل آن سرویس یکتا است، یا دست‌کم در آن حساب و منطقه. داخل صندوقچه، هر شیء یک کلید دارد. کلید می‌تواند `/` داشته باشد. سرویس از این خط پوشه نمی‌سازد. ابزارها برای راحتی آن را درخت نشان می‌دهند.

شیء بدنهٔ فایل است به‌علاوهٔ فراداده، مثل `Content-Type`. اگر نوع را نگذارید، دانلود در مرورگر ممکن است به عنوان باینری ناشناس بیاید. نوع را موقع گذاشتن شیء بفرستید.

درخواست با امضا می‌رود. امضا از کلید دسترسی، کلید مخفی، زمان، و خود درخواست ساخته می‌شود. ساعت غلط امضا را باطل می‌کند. کلید مخفی را در آرگومان خط فرمان نگذارید که در `ps` و در history بماند. فایل مجوز `0600` یا متغیر محیطی که فقط واحد systemd می‌بیند مناسب است.

region برچسب منطقهٔ دیتابیس شیء است. AWS منطقه را جدی می‌گیرد و نشانی را از آن می‌سازد. R2 اغلب منطقه را `auto` می‌خواهد. آروان منطقه را داخل نام میزبان می‌گذارد، مثل `ir-thr-at1`. MinIO تک‌نودی منطقه را زیاد جدی نمی‌گیرد و بسیاری از کتابخانه‌ها با مقدار `us-east-1` راضی می‌شوند، به شرطی که endpoint را خودتان داده باشید.

دو شکل URL:

```text
path-style:        https://endpoint/bucket/key
virtual-host:      https://bucket.endpoint/key
```

آروان در مستند خودش برای دیدن شیء پشت CDN شکل میزبان مجازی را می‌خواهد: `https://<bucket>.s3.<region>.arvanstorage.ir/<key>`. MinIO پشت یک نشانی و یک گواهی اغلب با path-style ساده‌تر است. کتابخانه را با `forcePathStyle` صریح تنظیم کنید تا حدس نزند.

## چرا استفاده می‌شود؟

اگر برنامه فایل را روی دیسک محلی بگذارد، سرور دوم برنامه همان فایل را نمی‌بیند. صندوقچه نقطهٔ مشترک است. اگر فردا از MinIO به آروان بروید و کد به API S3 نوشته شده باشد، جابه‌جایی بیشتر انتقال داده است تا بازنویسی. اگر کد به مسیر `/opt/apps/uploads` چسبیده باشد، این جابه‌جایی یک پروژه است.

قرارداد S3 یعنی ابزار `aws` Official CLI با `--endpoint-url` به غیر از AWS هم وصل می‌شود. لازم نیست برای هر شرکت ابزار جدا یاد بگیرید، هرچند MinIO ابزار `mc` را هم دارد و برای مدیریت خود MinIO راحت‌تر است.

## Architecture

```text
کلید دسترسی + ساعت درست + نام صندوقچه + کلید شیء
        │
        ▼
HTTPS به endpoint
        │
        ├── GetObject
        ├── PutObject
        ├── DeleteObject
        └── ListObjects
        │
        ▼
دیسک سرویس‌دهنده
    یا دیسک شما در MinIO
    یا دیسک شرکت در آروان و R2 و AWS
```

نسخه‌سازی اگر روشن باشد، Delete شیء را نشانه‌گذاری می‌کند و نسخهٔ قبلی می‌ماند تا سیاست عمر آن را پاک کند. بدون نسخه‌سازی، Delete همان نسخهٔ تنها را برمی‌دارد.

## Installation

چیزی نصب نمی‌شود. برای آزمون مفهوم بعد از بالا آمدن یکی از سرویس‌ها، یک شیء کوچک کافی است. نمونه وقتی MinIO محلی بالاست در صفحهٔ کلاینت است. اینجا فقط شکل منطقی کلید را ثابت کنید:

```text
app-uploads/incoming/2026/09/23/report.pdf
```

تاریخ را در کلید بگذارید اگر بعداً می‌خواهید با سیاست عمر، قدیمی‌ها را ارزان یا حذف کنید. تاریخ فایل‌سیستم را سرویس S3 به آن شکل به شما نمی‌دهد که با `find -mtime` کار کنید.

## Configuration

تصمیم‌هایی که باید قبل از اولین شیء واقعی نوشته شوند:

| تصمیم | پیش‌فرض این دانشنامه |
| --- | --- |
| عمومی یا خصوصی | خصوصی |
| نسخه‌سازی | روشن برای صندوقچهٔ بکاپ، خاموش برای کش بازتولیدشدنی |
| منطقه | همان که پنل نشان می‌دهد، کپی شود نه از حفظ |
| سبک URL | برای آروان میزبان مجازی وقتی پای CDN است، برای MinIO path-style |
| نام صندوقچه | حروف کوچک، عدد، خط تیره. زیرخط در بعضی سرویس‌ها دردسر است |

نام صندوقچه را بعد از پر شدن عوض نکنید. کلیدها داخل نام قدیمی می‌مانند و برنامه نام را در پایگاه ذخیره کرده است. اگر باید عوض شود، کپی شیء به صندوقچهٔ جدید یک کار مهاجرت است، نه یک rename ارزان روی همهٔ سرویس‌ها.

## Production Example

کاربر فایل را آپلود می‌کند. برنامه شیء را با کلید `incoming/<uuid>` می‌گذارد و در پایگاه PostgreSQL فقط همان کلید و نام اصلی فایل را ذخیره می‌کند، نه خود بایت‌ها را. دانلود بعدی یا لینک امضاشدهٔ پنج‌دقیقه‌ای است یا پروکسی از خود برنامه اگر نمی‌خواهید کاربر مستقیم به صندوقچه برسد.

اگر فردا دیسک MinIO را به آروان منتقل کنید، ردیف پایگاه همان کلید را دارد. فقط endpoint و کلید دسترسی در محیط سرویس عوض می‌شود، به شرطی که شیءها را با همان کلید کپی کرده باشید.

## Security Notes

لیست کردن صندوقچه برای کاربر ناشناس را خاموش نگه دارید. دانستن نام فایل‌ها خودش داده است.

لینک امضاشده را طولانی‌عمر نسازید. یک ساعت برای دانلود انسان زیاد هم هست. برای فایل حساس پنج تا پانزده دقیقه کافی است.

کلید مخفی را در تصویر Docker و در لایهٔ بیلد نگذارید. متغیر محیط در زمان اجرا، یا فایل روی سرور، نه `ARG` در Dockerfile.

ثبت دسترسی (access log) صندوقچه را اگر سرویس دارد برای صندوقچهٔ حساس روشن کنید. MinIO لاگ سرور را در journald می‌نویسد. آن را با لاگ برنامه قاطی نکنید.

## Troubleshooting

| نشانه | معنی |
| --- | --- |
| PermanentRedirect یا منطقه غلط | region با endpoint نمی‌خواند |
| NoSuchBucket | نام غلط است یا در منطقهٔ دیگری ساخته شده |
| AccessDenied با کلید درست | سیاست، یا ساعت، یا سبک URL که میزبان را عوض کرده و امضا را باطل کرده |
| SlowDown | درخواست زیاد. صف در برنامه، نه حلقهٔ بی‌وقفه |
| فایل صفر بایتی | آپلود قطع شده. اندازه را بعد از Put با Head مقایسه کنید |

## Best Practices

- کلید را در پایگاه ذخیره کنید و مسیر محلی را منبع حقیقت ندانید بعد از مهاجرت.
- نوع محتوا را موقع نوشتن بفرستید.
- ساعت را قبل از دیباگ کلید چک کنید.
- نام صندوقچه را پایدار انتخاب کنید.
