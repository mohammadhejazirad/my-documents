# نقشهٔ فضای ابری

## مقدمه

فایل کاربر، بکاپ، و دارایی ثابت را لازم نیست داخل دیسک همان سرور برنامه نگه دارید. فضای شیء (object storage) فایل را با کلید و از راه API نگه می‌دارد، نه به شکل پوشهٔ مشترک NFS. پروتکل رایجی که همهٔ این صفحه به آن وصل می‌شوند S3 است. Amazon آن را ساخته و بقیه، از جمله MinIO و فضای ابری آروان و Cloudflare R2، همان شکل درخواست را قبول می‌کنند.

این فصل چهار راه تهیه را جدا می‌کند تا با هم قاطی نشوند. MinIO را خودتان روی دیسک سرور بالا می‌آورید. Docker همان MinIO است داخل کانتینر. سرویس مدیریت‌شده را از شرکت می‌خرید و دیسک را خودتان نگه نمی‌دارید. کلاینت، ابزار مشترکی است که به هر کدام از این‌ها وصل می‌شود.

آزمایشگاه: اگر MinIO را برای یادگیری بالا می‌آورید، روی `app-1` (`10.10.1.10`) و فقط روی `127.0.0.1` باشد. داده زیر `/var/lib/minio` است، نه زیر `/opt/apps`، تا استقرار برنامه پوشه را پاک نکند.

## مفهوم اصلی

یک صندوقچه (bucket) نام دارد و شیءها داخلش کلید رشته‌ای دارند، مثل `uploads/2026/09/a.png`. این پوشهٔ واقعی دیسک نیست حتی اگر کلید اسلش داشته باشد. دسترسی با کلید دسترسی و کلید مخفی است، نه با کاربر SSH.

هر سرویس یک نشانی API دارد که به آن endpoint می‌گویند. برای AWS این نشانی منطقه‌ای است. برای آروان شکل `https://s3.<region>.arvanstorage.ir` است، مثلاً منطقهٔ `ir-thr-at1`. برای R2 شکل `https://<accountid>.r2.cloudflarestorage.com` است. برای MinIO محلی `http://127.0.0.1:9000` است. برنامه اگر endpoint را نداشته باشد فرض می‌کند AWS است و درخواست به جای اشتباه می‌رود.

حالت مسیر (path-style) نام صندوقچه را در مسیر URL می‌گذارد. حالت میزبان مجازی نام صندوقچه را در نام میزبان می‌گذارد. آروان برای کش CDN حالت میزبان مجازی را می‌خواهد. بعضی کتابخانه‌ها با MinIO فقط path-style درست کار می‌کنند. این تفاوت را در صفحهٔ کلاینت می‌بینید، نه با امتحان تصادفی در تولید.

## چرا استفاده می‌شود؟

دیسک سرور با بکاپ و آپلود کاربر پر می‌شود و بزرگ کردنش حد دارد. جدا کردن فایل از دیسک برنامه، تعویض سرور برنامه را ممکن می‌کند بدون جابه‌جا کردن ترابایت با `rsync` در همان شب حادثه. سرویس مدیریت‌شده دیسک خراب و تعویض هارد را از تیم برمی‌دارد و در عوض هزینه و وابستگی به آن شرکت را می‌آورد. MinIO همان API را می‌دهد وقتی فایل نباید از شبکهٔ خودتان بیرون برود، یا وقتی می‌خواهید قبل از خریدن سرویس، برنامه را با S3 بنویسید.

پایگاه را در صندوقچه به عنوان تنها نسخهٔ زنده نگذارید. dump پایگاه می‌تواند به صندوقچه برود. خود PostgreSQL باید روی دیسک پایگاه بماند.

## Architecture

```text
برنامه روی app-1
    AWS SDK یا aws cli
            │
            ├── MinIO محلی     127.0.0.1:9000     دیسک /var/lib/minio
            ├── MinIO در Docker   volume نام‌دار
            ├── آروان          s3.<region>.arvanstorage.ir
            ├── Cloudflare R2  <account>.r2.cloudflarestorage.com
            └── AWS S3         s3.<region>.amazonaws.com
```

یک برنامه در هر محیط فقط به یک endpoint وصل است. محیط محلی MinIO، محیط عمومی یکی از سرویس‌های مدیریت‌شده. کلید محیط عمومی را روی لپ‌تاپ توسعه‌دهنده به عنوان کلید تولید کپی نکنید.

## Installation

خود این صفحه نرم‌افزار نصب نمی‌کند. مسیر نصب:

- دیسک خودتان، بدون Docker: [MinIO روی سرور](./minio-server)
- دیسک خودتان، با Docker: [MinIO در Docker](./minio-docker)
- خریدن سرویس: [سرویس مدیریت‌شده](./managed-s3)
- وصل کردن برنامه: [کلاینت S3](./clients)

قبل از هر کدام، ساعت سرور و DNS باید سالم باشد. امضای درخواست S3 به ساعت حساس است. اختلاف چند دقیقه‌ای، خطای امضا می‌دهد که شبیه رمز غلط است.

## Configuration

قرار نام برای آزمایشگاه:

| چیز | مقدار نمونه |
| --- | --- |
| صندوقچه | `app-uploads` |
| کلید شیء | `incoming/<id>` |
| کاربر دسترسی | `app_s3` نه حساب root سرویس |
| فایل راز | `/etc/app/s3.env` با مجوز `0600` و مالک `deploy` |

صندوقچه را عمومی نکنید مگر فایل واقعاً باید بدون امضا در مرورگر باز شود. پیش‌فرض این فصل خصوصی است. لینک موقت با امضا برای دانلود کاربر کافی است.

## Production Example

محصول فایل آپلود را امروز روی `/opt/apps/app/uploads` می‌گذارد و دیسک پر می‌شود. تصمیم این است که آپلود جدید به S3 برود و فایل قدیمی سر جایش بماند تا برنامه هر دو را بخواند. یک صندوقچهٔ خصوصی ساخته می‌شود، یک کاربر با حق فقط همان صندوقچه، و برنامه با متغیر محیط به endpoint وصل می‌شود. تا وقتی خواندن آزمایشی یک فایل و نوشتن آزمایشی یک فایل هر دو موفق نشده، مسیر قدیمی را از کد حذف نمی‌کنید.

اگر فایل نباید از کشور یا از شبکهٔ خودتان خارج شود، MinIO روی دیسک جدا انتخاب می‌شود نه R2. اگر نمی‌خواهید دیسک را خودتان عوض کنید، سرویس مدیریت‌شده انتخاب می‌شود. هر دو از دید کد مشابه‌اند اگر endpoint عوض شود و داده یک بار منتقل شده باشد.

## Security Notes

کلید root کنسول MinIO یا حساب اصلی AWS را داخل برنامه نگذارید. برای برنامه یک کلید جدا با حداقل حق بسازید: `PutObject` و `GetObject` و `DeleteObject` روی یک صندوقچه، نه `*` روی همه.

پورت ۹۰۰۰ و ۹۰۰۱ MinIO را روی `0.0.0.0` به اینترنت ندهید. کنسول مدیریت فقط از SSH tunnel یا از شبکهٔ مدیریت باز شود.

نسخه‌سازی صندوقچه (versioning) را برای بکاپ روشن کنید اگر شرکت یا MinIO آن را دارد، تا پاک کردن تصادفی شیء فوراً تنها نسخه را نبرد. این جای بکاپ خارج از همان سرویس نیست. اگر تنها کپی داخل همان حساب باشد، از دست دادن حساب یعنی از دست دادن بکاپ.

## Troubleshooting

| نشانه | صفحه |
| --- | --- |
| خطای امضا یا RequestTimeTooSkewed | ساعت سرور. `timedatectl` |
| برنامه به AWS می‌رود نه به آروان | endpoint در محیط فرایند نیست. `systemctl show` |
| 403 روی شیء | حق کلید، یا صندوقچهٔ غلط، یا ساعت |
| دیسک MinIO پر است | `df` روی `/var/lib/minio`. بزرگ کردن دیسک، نه پاک کردن صندوقچه |
| از بیرون به کنسول MinIO می‌رسید | فایروال. پورت را به localhost برگردانید |

## Best Practices

- دادهٔ شیء را از پوشهٔ انتشار برنامه جدا کنید.
- یک کلید برای هر برنامه، قابل ابطال بدون خواباندن بقیه.
- قبل از پاک کردن دیسک قدیمی، یک شیء را از مقصد جدید بخوانید.
- عمومی کردن صندوقچه یک تصمیم جدا و نوشته‌شده باشد، نه پیش‌فرض آزمون.
