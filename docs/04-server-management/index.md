# نقشهٔ ابزارهای سرور

## مقدمه

این فصل ابزارهایی است که روی خود سرور می‌مانند و جای DNS و گواهی نیستند. DNS، لبهٔ ابرآروان و Cloudflare، و TLS در فصل شبکه است. فضای شیء S3 و MinIO فصل خودش را دارد. اینجا کار عملی روی خود ماشین است: ساعت اول، به‌روزرسانی بعدی بدون پاک شدن داده، بزرگ کردن دیسک، swap، بسته‌های دیدن و نگهداری، FFmpeg، Chromium، Chrome for Testing از مخزن تیم، و ClamAV.

آزمایشگاه همان است. برنامه `app-1.example.internal` روی `10.10.1.10`، منطقهٔ زمانی `Asia/Tehran`، انسان مدیر `ops`، و حساب سرویس `deploy`. ابزار این فصل را روی پروکسی فقط وقتی نصب کنید که همان میزبان واقعاً فایل رسانه یا PDF می‌سازد. پیش‌فرض، سرور برنامه است.

هر صفحه دستور کپی‌کردنی دارد. شمارهٔ نسخه‌ای که مخزن Ubuntu همان روز می‌دهد را از `apt-cache policy` می‌خوانید. این فصل برای FFmpeg و ClamAV و Chromium شمارهٔ patch اختراع نمی‌کند.

## مفهوم اصلی

سی دقیقهٔ اول، پیکربندی هویت میزبان است: بستهٔ امنیتی، نام، ساعت، کاربر `ops`، و به‌روزرسانی بی‌حضور فقط از جیب امنیت. بدون این‌ها، ابزار بعدی روی میزبانی نصب می‌شود که هنوز با نام پیش‌فرض و منطقهٔ زمانی غلط در لاگ ظاهر می‌شود و فردا کسی نمی‌داند کدام ماشین بوده.

سه ابزار بعدی هر کدام یک کار محدود دارند:

| ابزار | کار در این آزمایشگاه | کاری که عمداً نمی‌کند |
| --- | --- | --- |
| FFmpeg | تبدیل و تصویر بندانگشتی از فایل زیر `/opt/apps` | پخش زنده و میزبان ویدیوی عمومی |
| Chromium بی‌پنجره | PDF از یک صفحهٔ محلی با کاربر جدا | مرورگر روی میز، و `--no-sandbox` روی سرور چندکاربره |
| ClamAV | اسکن زمان‌بندی‌شدهٔ مسیر آپلود، با امضای تازه | قلاب fanotify روی کل دیسک سرور شلوغ |
| به‌روزرسانی امن | `apt upgrade` با دادهٔ `/var/lib` سر جایش | `do-release-upgrade` بی‌بکاپ، و `rm` به نیت آپدیت |
| دیسک و swap | بزرگ کردن حجم و فایل swap | `mkfs` و پاک کردن پارتیشن برای «جا باز کردن» |
| Chrome for Testing | دودویی Puppeteer از مخزن عمومی تیم | جایگزین Chromium توزیع، و اجرای دائمی با root |

هر سه را به حساب `ops` اجرا نمی‌کنیم. FFmpeg با `deploy`، Chromium با کاربر `chrome`، ClamAV با کاربر `clamav` که خود بسته می‌سازد. دلیل جدا بودن حساب در [امنیت کاربر و فایل](/docs/10-security/users-and-files) است.

## چرا استفاده می‌شود؟

تیم برنامه اغلب از مدیر سرور می‌خواهد «فقط یک تصویر کوچک از ویدیو بساز» یا «همین صفحه را PDF کن» یا «فایل آپلود ویروس نداشته باشد». اگر این کارها روی لپ‌تاپ بماند، شب و آخر هفته انجام نمی‌شود و نسخهٔ روی سرور با نسخهٔ روی میز فرق می‌کند. اگر بدون محدودیت روی سرور انجام شود، یک فایل خصمانه CPU را می‌خورد یا جعبهٔ شنی مرورگر را خاموش می‌کنید و یک PDF ساده به راه فرار تبدیل می‌شود.

این فصل وسط این دو است: ابزار رسمی مخزن Ubuntu، کاربر جدا، حد حافظه یا زمان، و مسیر مشخص زیر `/opt/apps`. نرم‌افزار خیالی صف و پنل اضافه معرفی نمی‌شود. صف رسانه یک واحد systemd است. اسکن ویروس یک timer است.

## Architecture

```text
Ubuntu 26.04 تازه
    │
    ├─ 1  سی دقیقهٔ اول
    │     apt full-upgrade
    │     hostname و Asia/Tehran
    │     کاربر ops در گروه sudo
    │     به‌روزرسانی بی‌حضور فقط security
    │     بعداً SSH بدون رمز  →  فصل امنیت
    │
    ├─ 2  FFmpeg
    │     کاربر deploy
    │     /opt/apps/media/incoming
    │     واحد systemd  یک فایل در هر اجرا
    │
    ├─ 3  Chromium
    │     بسته را apt-cache policy معلوم می‌کند
    │     کاربر chrome، خانهٔ خالی از راز
    │     PDF بدون --no-sandbox روی میزبان
    │
    └─ 4  ClamAV
          freshclam برای امضا
          timer شبانه روی مسیر آپلود
          نه clamonacc روی کل سرور
```

ترتیب خواندن همین شمارهٔ سایدبار است. Chromium را قبل از سی دقیقهٔ اول روی میزبان بی‌نام نصب نکنید. ClamAV را قبل از اینکه مسیر آپلود مالک و گروه داشته باشد روشن نکنید، وگرنه یا هیچ فایلی را نمی‌بیند یا مجبور می‌شوید اسکن را با root عادت کنید.

## Installation

بستهٔ مشترک این فصل از مخزن Ubuntu است، نه از یک اسکریپت نصب اینترنتی. شکل کلی، که هر صفحه دقیق‌ترش را دارد:

```bash
sudo apt update
apt-cache policy ffmpeg chromium chromium-browser clamav
```

`apt-cache policy` قبل از `install` می‌گوید بسته اصلاً در آرشیو هست یا نه. برای Chromium این تفاوت مهم است و صفحهٔ خودش توضیح می‌دهد که روی 26.04 نام `chromium-browser` بستهٔ انتقالی به snap است و نام `chromium` ممکن است اصلاً کاندید نداشته باشد. آن را با اضافه کردن یک PPA شانسی حل نکنید.

سی دقیقهٔ اول را روی هر میزبان تازه یک بار انجام دهید: `app-1`، `db-1`، `docker-1`، پروکسی، پایش، و GitLab. FFmpeg و Chromium و ClamAV را پیش‌فرض فقط روی میزبانی بگذارید که فایل کاربر را باز می‌کند. در این آزمایشگاه آن میزبان `app-1` است. `db-1` ویدیو تبدیل نمی‌کند.

بعد از نصب، واحد را با همان نامی که صفحهٔ ابزار نوشته چک کنید. برای صف رسانه و اسکن آپلود این دو کافی است:

```bash
systemctl status media-queue.path --no-pager
systemctl status clamav-daemon.service clamav-freshclam.service --no-pager
systemctl list-timers clamav-uploads.timer
```

`clamav-freshclam-once.timer` را فقط اگر صفحهٔ ClamAV گفته باشد که سرویس دائمی را خاموش کرده‌اید نگاه کنید. روشن بودن هم‌زمان سرویس دائمی و timer یک‌باره خطا است، نه نشانهٔ مراقبت بیشتر. `list-units` برای دیدن چیزهایی که failed مانده‌اند:

```bash
systemctl --failed
```

خروجی خالی یعنی در این لحظه واحد شکست‌خوردهٔ ثبت‌شده ندارید. خالی بودن، جای آزمایش تبدیل و آزمایش EICAR را نمی‌گیرد.

## Configuration

قرارهای مشترک. مسیرها را هم از همین جدول بردارید تا صف رسانه و اسکن آپلود روی یک پوشه نیفتند:

| مسیر | مالک | کار |
| --- | --- | --- |
| `/opt/apps/media/incoming` | `deploy` | ورودی صف FFmpeg، فقط فایل کامل |
| `/opt/apps/media/out` | `deploy` | mp3 و jpg آماده |
| `/opt/apps/app/uploads` | `deploy:clamav` | آپلود کاربر، هدف اسکن شبانهٔ ClamAV |
| `/home/chrome/output` | `chrome` | PDF، جدا از دو مسیر بالا |
| `/etc/apt/apt.conf.d/52unattended-upgrades-security-only` | root | فقط جیب امنیت |

قرارهای مشترک:

- منطقهٔ زمانی `Asia/Tehran` قبل از timerهایی که ساعت محلی دارند. اسکن ساعت ۰۳:۳۰ در صفحهٔ ClamAV به ساعت میزبان است. اگر میزبان هنوز UTC باشد، اسکن نیمهٔ شب تهران نیست.
- کاربر سرویس پوستهٔ ورود ندارد، جز استثناهایی که صفحهٔ SSH با نام گفته. `chrome` و `clamav` در `AllowUsers` نیستند.
- فایل ورودی کاربر اعتماد ندارد. FFmpeg حد زمان و حافظه دارد. Chromium جعبهٔ شنی را روی میزبان خاموش نمی‌کند. ClamAV فایل را اجرا نمی‌کند. اسکن، اجرا نیست.
- پیکربندی بسته را در فایل اصلی توزیع قفل نکنید اگر drop-in یا فایل `.local` وجود دارد. به‌روزرسانی apt همان فایل اصلی را عوض می‌کند.
- به‌روزرسانی بی‌حضور همهٔ بسته‌ها را جلو نمی‌برد. فقط امنیت. جزئیات در صفحهٔ بوت‌استرپ است و عمداً جیب `-updates` را خودکار نمی‌کند.

راز این ابزارها کم است، ولی صفر نیست. خانهٔ `chrome` نباید کلید SSH داشته باشد. لاگ ClamAV نباید جهان‌خوانا باشد اگر نام فایل آپلود حساس است. خروجی PDF را در `/tmp` جهان‌خوانا رها نکنید.

## Production Example

میزبان تازهٔ این هفته `app-1` است. در نیم‌ساعت اول نامش `app-1.example.internal` می‌شود، ساعت تهران است، `ops` با sudo و بدون رمز عبور وارد SSH خواهد شد (خود بستن رمز در فصل امنیت است)، و شب همان روز فقط وصلهٔ امنیتی می‌آید. صبح، `checkrestart` یا فایل `/var/run/reboot-required` می‌گوید reboot لازم است یا نه. تا وقتی آن را ندیده‌اید، میزبان را «به‌روز» حساب نکنید.

همان روز اگر محصول ویدیو دارد، واحد FFmpeg را روشن می‌کنید و یک فایل کوچک واقعی را از `incoming` به تصویر بندانگشتی می‌برید. یک فایل نمونهٔ خودتان، نه فایل ناشناس مشتری، تا واحد را امتحان کنید. بعد مسیر آپلود مشتری را به صف وصل می‌کنید.

اگر محصول PDF گزارش می‌خواهد، کاربر `chrome` را می‌سازید و یک صفحهٔ سلامت محلی را به PDF تبدیل می‌کنید. اگر دستور بدون `--no-sandbox` شکست خورد، پرچم را اضافه نمی‌کنید. صفحهٔ Chromium می‌گوید به کجا نگاه کنید.

اگر آپلود فایل دارید، ClamAV را همان شب با timer روشن می‌کنید و یک فایل آزمون EICAR را فقط برای آزمایش تشخیص می‌گذارید و پاک می‌کنید. اسکن لحظه‌ای fanotify را روشن نمی‌کنید مگر صفحهٔ ClamAV را تا بخش عارضه خوانده باشید و هنوز دلیل جدا داشته باشید.

## Security Notes

ابزار رسانه و مرورگر، سطح حملهٔ تازه‌اند. فایل ویدیو و HTML می‌توانند پیاده‌سازی را غافلگیر کنند. جدا کردن کاربر، حد حافظه، و ندادن sudo به این حساب‌ها بخش اصلی امنیت این فصل است، نه یک نکتهٔ حاشیه.

`--no-sandbox` روی Chromium، روی میزبانی که کاربر دیگری دارد، ممنوع است. استثنا فقط کانتینر یک‌بارمصرف است و در همان صفحه با هشدار آمده. کپی کردن آن پرچم به unit سرویس `app-1` خلاف این فصل است.

به‌روزرسانی بی‌حضور که همهٔ بسته‌ها را بگیرد، شب جمعه Nginx یا کتابخانه را جلو می‌برد بی‌آنکه کسی بیدار باشد. این فصل فقط جیب امنیت را خودکار می‌کند. بقیهٔ به‌روزرسانی‌ها در ساعت اداری و با خبر از reboot است.

ClamAV جایگزین محدود کردن نوع فایل و جدا کردن مسیر آپلود از بقیهٔ دیسک نیست. یک امضا عقب‌افتاده، فایل تازه را سالم اعلام می‌کند. `freshclam` باید واقعاً کار کند و لاگش را ببینید. روشن بودن سرویس کافی نیست.

## Troubleshooting

| نشانه | صفحهٔ مربوط |
| --- | --- |
| `sudo` از `ops` رمز می‌خواهد یا گروه خالی است | سی دقیقهٔ اول، عضویت `sudo`، و یک ورود تازه |
| لاگ‌ها چند ساعت با تهران فاصله دارند | `timedatectl`. timerها را بعد از درست شدن ساعت دوباره معنی کنید |
| فردا صبح هستهٔ کهنه هنوز در حافظه است | `reboot-required` و `checkrestart` در همان صفحه |
| صف رسانه فایل را برنمی‌دارد | واحد path یا timer، و مجوز پوشه برای `deploy` |
| Chromium همان اول می‌گوید sandbox نیست | صفحهٔ Chromium. پرچم را به میزبان اضافه نکنید |
| اسکن ویروس همه را سالم می‌گوید و EICAR را هم سالم می‌گوید | امضا نیامده. `freshclam` و ساعت سیستم |
| بار دیسک بعد از «حفاظت لحظه‌ای» بالا مانده | fanotify را خاموش کنید و به timer برگردید |

عیب‌یابی جزئی هر ابزار داخل همان صفحه است. اینجا فقط مسیر را جدا می‌کند تا FFmpeg را برای مشکل ساعت مقصر ندانید.

اگر چند نشانه با هم آمد، اول ساعت و نام میزبان را ثابت کنید، بعد واحد را. یک timer که «دیشب اجرا نشده» روی میزبان UTC در واقع اجرا شده، فقط در ساعتی که شما پای لاگ نبوده‌اید. `timedatectl` دو خط `Time zone` و `System clock synchronized` را نشان می‌دهد. تا هر دو درست نباشند، به باگ اسکریپت رسانه نرسید.

مسیر فایل‌ها را هم قاطی نکنید. رسانه زیر `/opt/apps/media` است و آپلود اسکن‌شونده زیر `/opt/apps/app/uploads`. یکی کردن این دو پوشه یعنی هم FFmpeg فایل نیمه‌نوشته را برمی‌دارد و هم ClamAV خروجی تبدیل را هر شب دوباره می‌خواند. برنامه فایل آماده را به `incoming` جابه‌جا می‌کند. اسکنر فقط درخت آپلود را می‌بیند. PDF سلامت زیر `/home/chrome/output` می‌ماند و وارد هیچ‌کدام از این دو صف نمی‌شود.

نشانه‌های سالم را همان روز بگیرید. اگر میزبان برنامه است و هر سه ابزار را خواسته‌اید، این‌ها باید سبز باشند. میزبانی که فقط پایگاه است این واحدها را ندارد و نباید داشته باشد:

```bash
hostnamectl --static
timedatectl show -p Timezone --value
systemctl is-enabled media-queue.path
systemctl is-enabled clamav-uploads.timer
systemctl is-enabled clamav-freshclam.service
apt-cache policy ffmpeg clamav chromium-browser
```

نام باید `app-1.example.internal` باشد، منطقه `Asia/Tehran`، و سه واحد `enabled`.

اگر `is-enabled` بگوید `not-found`، واحد را نساخته‌اید. اگر بگوید `disabled`، بسته هست و بعد از reboot کار نمی‌کند. خروجی `apt-cache policy` را در یادداشت تغییر کپی کنید. شماره را از این دانشنامه نقل نکنید.

## Best Practices

- اول هویت میزبان، بعد ابزار. نام و ساعت و کاربر را عقب نیندازید.
- هر ابزار با کاربر خودش. `ops` برای SSH است نه برای تبدیل ویدیو.
- خروجی `apt-cache policy` را اگر شک دارید به خروجی آموزش ترجیح دهید. آموزش‌ها اسم بستهٔ Debian و Ubuntu را قاطی می‌کنند.
- حد منابع را همان روز اول بگذارید. اضافه کردن `MemoryMax` بعد از اولین فایل خصمانه، یعنی همان فایل را قبلاً اجرا کرده‌اید.
- timer را با منطقهٔ زمانی درست معنی کنید. `Asia/Tehran` را در بوت‌استرپ عوض نکنید و در صفحهٔ ClamAV ساعت دیگری فرض نکنید.
- وقتی سرور از سی دقیقهٔ اول درآمد، [سخت‌سازی SSH](/docs/10-security/ssh-hardening) هنوز اجباری است. این فصل به آن لینک می‌دهد و جای آن را نمی‌گیرد.
- واحدها را enable کنید نه اینکه فقط یک بار start کنید. بعد از reboot، `media-queue.path` و `clamav-uploads.timer` و `clamav-freshclam.service` باید بدون دست بالا بیایند. `systemctl is-enabled` را برای همین سه نام چک کنید.
- فایل آزمایشی را از پوشهٔ مشتری برندارید. یک `wav` کوتاه خودتان و یک EICAR که همان ساعت پاک می‌شود کافی است. فایل واقعی مشتری را برای اولین اجرای واحد مصرف نکنید.
- اگر میزبان فقط پایگاه داده است، FFmpeg و Chromium و ClamAV را نصب نکنید. سی دقیقهٔ اول را بکنید و بروید سراغ فصل امنیت. بستهٔ اضافه یعنی سطح اضافه.
