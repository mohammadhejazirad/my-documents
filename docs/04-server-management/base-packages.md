# بسته‌های پایهٔ سرور

## مقدمه

تصویر Ubuntu Server کم است و این درست است. چیزی که کم است را وقتی کار واقعی رسید نصب کنید، نه یک لیست پنجاه‌تایی در روز اول. این صفحه همان مجموعهٔ کوتاهی است که بدون آن، پر بودن دیسک و قطع شدن شبکه و به‌روزرسانی نصفه را دیر می‌فهمید.

نصب این بسته‌ها فایل برنامه و پایگاه را عوض نمی‌کند. بستهٔ تازه کتابخانه و دودویی خودش را می‌گذارد. استثنا بسته‌ای است که سرویس شبکه باز کند. در این فهرست سرویس عمومی اضافه نمی‌شود.

## مفهوم اصلی

ابزار پایه سه دسته است.

دستهٔ دیدن: `htop` برای فرایند، `ncdu` برای اینکه کدام پوشه دیسک را خورده، `iotop` برای دیسکی که مشغول است، `lsof` برای فایلی که هنوز باز است، `mtr` برای مسیر شبکه. بدون این‌ها آدم `rm` می‌زند چون ابزار دیدن را ندارد.

دستهٔ کار تعاملی: `tmux` تا قطع SSH ارتقا را نکشد، `jq` برای مانیفست و API، `unzip` و `rsync` و `git` و `curl` و `ca-certificates`. این‌ها را اسکریپت‌های همین دانشنامه فرض می‌کنند.

دستهٔ بعد از ارتقا: `debian-goodies` که `checkrestart` را دارد، و `needrestart` که بعد از نصب بسته می‌گوید کدام سرویس باید restart شود. `needrestart` را عادت کنید که پیشنهادش را بخوانید. تأیید کور، وسط روز پایگاه را restart می‌کند.

ابزار سنگین مانیتورینگ این صفحه نیست. Netdata و Prometheus فصل خودشان را دارند. اگر فقط گاهی به سرور سر می‌زنید، همین فهرست کافی است و عامل همیشگی نمی‌خواهد.

## چرا استفاده می‌شود؟

حادثهٔ دیسک پر معمولاً با `du` دستی شروع می‌شود و نیم‌ساعت طول می‌کشد تا پوشهٔ مقصر پیدا شود. `ncdu` همان کار را تعاملی می‌کند. حادثهٔ ارتقا با قطع VPN، بدون `tmux`، سیستم را با dpkg نصفه می‌گذارد. هر دو دردسر از نبود یک بستهٔ کوچک‌اند نه از سخت بودن خود کار.

نصب کردن هر چیزی که در یک آموزش دیده شده، سطح حمله و زمان `apt upgrade` را زیاد می‌کند. این صفحه عمداً کوتاه است.

## Architecture

```text
میزبان Ubuntu 26.04
    ├─ دیدن     htop  ncdu  iotop  lsof  mtr
    ├─ کار      tmux  jq  unzip  rsync  git  curl
    └─ بعد از apt   checkrestart  needrestart
هیچ‌کدام پورت عمومی باز نمی‌کنند
```

`iotop` برای دیدن دیسک همهٔ فرایندها معمولاً به امتیاز root نیاز دارد. این یک سرویس نیست. فقط وقتی اجرا شود کار می‌کند.

## Installation

روی `app-1` و روی هر میزبان عملیاتی دیگر، یک بار:

```bash
sudo apt update
sudo apt install -y \
  htop ncdu iotop lsof mtr-tiny \
  tmux jq unzip rsync git curl ca-certificates gnupg \
  debian-goodies needrestart
```

`mtr-tiny` به‌جای `mtr` کافی است و وابستگی گرافیکی نمی‌آورد. اگر `apt-cache policy mtr-tiny` خالی بود، `mtr` را نصب کنید و ببینید بستهٔ پیشنهادی سرور است نه دسکتاپ.

بسته را که نمی‌خواهید بعداً با `apt remove` بردارید. `purge` برای این ابزارها فقط پیکربندی محلی‌شان را هم می‌برد و دادهٔ برنامه را لمس نمی‌کند، ولی باز هم لازم نیست. `remove` کافی است.

## Configuration

`needrestart` به‌طور پیش‌فرض بعد از `apt` سؤال می‌کند. اگر در اسکریپت غیرتعاملی apt می‌زنید و نمی‌خواهید وسط راه بایستد، همان دستور را با محیط غیرتعاملی بزنید و restart را خودتان تصمیم بگیرید:

```bash
sudo DEBIAN_FRONTEND=noninteractive apt-get upgrade -y
sudo needrestart -b
```

خروجی دسته‌ای را بخوانید. restart کردن `ssh.service` نشست فعلی را معمولاً نمی‌کشد، ولی restart کردن پایگاه را در ساعت شلوغ انجام ندهید.

`tmux` پیکربندی اجباری ندارد. عادت این است که کار طولانی را این‌طور شروع کنید:

```bash
tmux new -s maint
```

جدا شدن `Ctrl-b` سپس `d` است. برگشت `tmux attach -t maint`. این را در اسکریپت خودکار نگذارید. برای انسان پشت SSH است.

`ncdu` را روی `/` با رد کردن پوشه‌های مجازی بزنید وگرنه `/proc` را هم می‌شمارد:

```bash
sudo ncdu -x /
```

فلگ `-x` روی همان فایل‌سیستم می‌ماند و دیسک‌های دیگر را قاطی نمی‌کند.

## Production Example

دیسک `app-1` یک‌شبه به ۹۰ درصد رسیده. به‌جای پاک کردن `/var/log`، `sudo ncdu -x /` را باز می‌کنید. مقصر `/var/lib/docker` است نه پایگاه. آن را با روش فصل Docker خلوت می‌کنید. دادهٔ `/var/lib/mysql` دست نخورده می‌ماند چون اصلاً آن پوشه بزرگ نبوده.

همان هفته ارتقای امنیتی را داخل `tmux` شروع می‌کنید. VPN یک بار قطع می‌شود. `tmux attach` کار را همان جا نشان می‌دهد، نه یک قفل dpkg شکسته.

## Security Notes

`iotop` و `lsof` اطلاعات فرایندهای کاربران دیگر را به کسی که root دارد نشان می‌دهند. این ابزار را روی حسابی که sudo ندارد لازم نیست، و حساب سرویس `deploy` نباید برای «راحتی» عضو sudo شود تا htop همه‌کس را ببیند.

`needrestart` سرویس را restart می‌کند اگر شما تأیید کنید. در جلسهٔ مشترک، کسی که فقط نگاه می‌کند نباید Enter را به عادت بزند.

بسته را از مخزن Ubuntu بگیرید. یک `curl | bash` برای نصب htop نشانهٔ این است که منبع را گم کرده‌اید.

## Troubleshooting

| نشانه | کار |
| --- | --- |
| `ncdu: command not found` | بسته نصب نشده یا PATH نشست قدیمی است. `command -v ncdu` |
| `iotop` خالی است یا اجازه نمی‌دهد | با sudo اجرا کنید |
| `needrestart` وسط اسکریپت ایستاده | محیط غیرتعاملی، بعد `needrestart -b` |
| `mtr` به مقصد نمی‌رسد | ICMP ممکن است فیلتر باشد. این خرابی ابزار نیست. از `ss` و `curl -v` در فصل شبکه استفاده کنید |
| بعد از remove هنوز دستور هست | نشست را باز کنید یا `hash -r` بزنید |

## Best Practices

- این فهرست را در ایمیج پایهٔ سازمان بگذارید تا هر ماشین تازه همان ابزار را داشته باشد.
- ابزار را جایگزین خواندن لاگ نکنید. `htop` علت را حدس می‌زند. `journalctl` جملهٔ خطا را دارد.
- هر بستهٔ اضافه‌تر از این فهرست باید یک صفحه یا یک دلیل در یادداشت تغییر داشته باشد.
- `debian-goodies` را با صفحهٔ به‌روزرسانی امن با هم به کار ببرید، نه به عنوان زینت.
