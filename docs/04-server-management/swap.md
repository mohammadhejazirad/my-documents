# افزودن swap بدون دست زدن به داده

## مقدمه

اگر ماشین مجازی بدون swap نصب شده باشد، اولین جهش حافظه می‌تواند فرآیند را با OOM بکشید. اضافه کردن swap به معنی پاک کردن دیسک یا ساختن پارتیشن تازه نیست. یک فایل معمولی روی فایل‌سیستم موجود است، با مجوز محدود، که هسته به عنوان فضای جابه‌جایی استفاده می‌کند.

دادهٔ برنامه سر جایش می‌ماند. تنها هزینه‌اش چند گیگابایت فضای خالی روی همان فایل‌سیستم است. اگر دیسک از قبل پر است، اول جا باز کنید یا دیسک را بزرگ کنید. فایل swap روی دیسکِ صددرصد پر ساخته نمی‌شود.

## مفهوم اصلی

swap حافظهٔ کند روی دیسک است. هسته صفحه‌هایی را که داغ نیستند به این فایل می‌فرستد تا RAM برای کار فوری بماند. این حافظهٔ نامحدود ارزان نیست. اگر برنامه بیشتر از RAM به swap برود، سرور زنده می‌ماند ولی کند می‌شود، گاهی آن‌قدر که از پایین بودن بدتر به نظر برسد.

`vm.swappiness` تعیین می‌کند هسته چقدر زود به swap برود. عدد پیش‌فرض اغلب ۶۰ است. برای سرور برنامه و مخصوصاً پایگاه، عدد پایین‌تر مثل ۱۰ یعنی تا وقتی واقعاً لازم نشده سراغ دیسک نرو. صفر یعنی فقط در آستانهٔ OOM. صفر را روی میزبانی که هیچ جای تخلیه ندارد نگذارید، چون همان OOM است با یک قدم کمتر.

فایل swap جایگزین RAM کافی برای پایگاه نیست. اگر PostgreSQL عمداً بزرگ پیکربندی شده، swap جلوی کشته شدن را می‌گیرد و پنهان می‌کند که پیکربندی از ماشین بزرگ‌تر است. اول اندازه را درست کنید.

## چرا استفاده می‌شود؟

تصویرهای ابری گاهی اصلاً swap نمی‌سازند تا دیسک کوچک را نخورند. روی ماشین ۲ یا ۴ گیگابایتی که هم Nginx دارد هم یک کار گزارش با Chrome، یک گزارش همزمان با بکاپ کافی است تا OOM قاتل Chrome یا حتی پایگاه را انتخاب کند. یک فایل swap به اندازهٔ RAM، یا حداکثر ۴ گیگابایت روی ماشین کوچک، این انتخاب را به تأخیر می‌اندازد.

پارتیشن swap جدا فقط وقتی لازم است که از روز نصب طرح دیسک را خودتان می‌چینید. روی سرور زنده، فایل swap همان نتیجه را دارد و پارتیشن‌بندی را دست نمی‌زند.

## Architecture

```text
فایل‌سیستم ریشه  (ext4 یا xfs)
    /swapfile
    مجوز 0600
    mkswap + swapon
    یک خط در /etc/fstab
            │
            ▼
هسته
    vm.swappiness=10 روی سرور برنامه و پایگاه
```

فایل را داخل `/var/lib/mysql` یا پوشهٔ برنامه نگذارید. جای آن ریشه است، نامش مشخص است، و بکاپ فایلِ عادی نباید آن را به عنوان داده کپی کند. `tar` معمولی اگر از `/` بگیرید ممکن است آن را هم بردارد. در اسکریپت بکاپ آن مسیر را استثنا کنید.

## Installation

اندازه را از RAM بگیرید. ماشین ۴ گیگابایتی، فایل ۴ گیگابایتی معقول است. ماشین ۳۲ گیگابایتی پایگاه، فایل ۴ گیگابایتی به عنوان ضربهٔ آخر کافی است و ۳۲ گیگابایت swap یعنی پذیرفتن کندی طولانی.

فضای خالی را ببینید:

```bash
free -h
df -hT /
swapon --show
```

اگر `swapon` از قبل یک دستگاه نشان داد، دومی نسازید مگر می‌دانید چرا اولی کوچک است. دو فایل swap اشکال فنی ندارد و گیج‌کننده است.

روی ext4 می‌توانید با `fallocate` سریع جا بگیرید. روی xfs و بعضی فایل‌سیستم‌ها `fallocate` برای swap مناسب نیست و باید `dd` بزنید. نوع را از `findmnt -no FSTYPE /` بخوانید.

ext4:

```bash
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
swapon --show
free -h
```

xfs:

```bash
sudo dd if=/dev/zero of=/swapfile bs=1M count=4096 status=progress
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

`mkswap` فقط همان فایل را نشانه‌گذاری می‌کند. بقیهٔ دیسک را دست نمی‌زند. اگر مسیر را اشتباه `/dev/sda` بدهید، آن وقت برچسب swap را روی دیسک خام می‌نویسید. مسیر این صفحه فایل است، با نام `/swapfile`.

## Configuration

تا خط زیر در `fstab` نباشد، بعد از reboot سوییچ خاموش است:

```text
/swapfile none swap sw 0 0
```

فایل را با ویرایشگر باز کنید و یک خط اضافه کنید. خط‌های قبلی دیسک را پاک نکنید.

```bash
printf '%s\n' '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
sudo findmnt --verify
```

`findmnt --verify` خط خراب fstab را قبل از reboot نشان می‌دهد. reboot آزمایشی را وقتی بزنید که کنسول هایپروایزر را دارید، نه به عنوان بخشی اجباری از ساخت swap. `swapon` همین حالا فعالش کرده است.

swappiness برای میزبان برنامه و پایگاه:

```bash
printf '%s\n' 'vm.swappiness=10' | sudo tee /etc/sysctl.d/90-swappiness.conf
sudo sysctl --system
sysctl vm.swappiness
```

عدد در نشست فعلی هم باید ۱۰ شود. فایل زیر `/etc/sysctl.d` از reboot می‌ماند.

## Production Example

`app-1` چهار گیگابایت RAM دارد، swap ندارد، و واحد گزارش با Chrome گاهی همزمان با `mysqldump` اجرا می‌شود. لاگ هسته `Out of memory: Killed process` را برای Chrome نشان داده، نه برای mysqld. یک فایل ۴ گیگابایتی ساخته می‌شود، `fstab` به‌روز می‌شود، swappiness روی ۱۰ می‌ماند.

هفتهٔ بعد اگر `free` نشان داد که swap پر شده و RAM هم ته کشیده، فایل را بزرگ‌تر نکنید به عنوان درمان. یا RAM را در پنل زیاد کنید یا همزمانی Chrome را به یک فرایند محدود کنید. swap پر یعنی ماشین از قبل در ناحیهٔ کندی است.

## Security Notes

مجوز `0600` اجباری است. فایل swap با `0644` ممکن است `swapon` هشدار بدهد یا رد کند، و اگر خواندنی باشد محتوای حافظهٔ فرایندها، از جمله رمزهایی که در RAM بودند، روی دیسک برای هر کاربر محلی قابل خواندن می‌شود. `chmod 600` را بعد از ساختن فراموش نکنید. `ls -l /swapfile` باید `-rw-------` و مالک root باشد.

هستهٔ جدیدتر ممکن است swap را روی فایل با سیاستی محدود کند اگر فایل سوراخ‌دار (sparse) باشد. `fallocate` روی ext4 برای این کار معمولاً بلوک واقعی می‌گیرد. اگر `swapon` گفت فایل سوراخ دارد، فایل را پاک کنید و با `dd` دوباره بسازید. پاک کردن `/swapfile` بعد از `swapoff` دادهٔ برنامه نیست.

```bash
sudo swapoff /swapfile
sudo rm /swapfile
```

خط `fstab` را هم بردارید وگرنه بوت بعدی دنبال فایل نیست و ممکن است طول بکشد یا به حالت اضطراری برود. اول `swapoff`، بعد حذف فایل، بعد ویرایش fstab.

## Troubleshooting

| نشانه | کار |
| --- | --- |
| `swapon failed: Invalid argument` | فایل sparse است یا `mkswap` نشده. با `dd` از نو بسازید |
| `swapon: /swapfile: insecure permissions` | `chmod 600` |
| بعد از reboot سوییچ نیست | خط fstab نیست یا مسیر غلط است. `findmnt --verify` |
| بوت طول می‌کشد و به emergency می‌رود | fstab به فایلی اشاره می‌کند که نیست. از کنسول خط را بردارید. دادهٔ دیسک هنوز هست |
| سیستم خیلی کند و swap پر است | RAM کم است. قاتل را در `dmesg` و `ps` ببینید. فقط فایل را دو برابر نکنید |
| `dd` دیسک را پر کرد | اندازه را بزرگ‌تر از `df` گرفتید. `swapoff` و حذف فایل همان جا را برمی‌گرداند اگر هنوز دستوری نزده‌اید که چیز دیگری پاک کند |

## Best Practices

- یک فایل، یک خط fstab، مجوز ۶۰۰.
- swappiness را روی پایگاه پایین بگذارید و آن را با اضافه کردن swap قاطی نکنید. هر کدام کار خودشان را می‌کنند.
- swap جای بزرگ کردن RAM یا محدود کردن Chrome و بکاپ همزمان نیست.
- فایل swap را در اسکریپت بکاپ فایل‌ها کپی نکنید.
