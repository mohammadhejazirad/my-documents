# دامنه با Cloudflare

## مقدمه

Cloudflare همان دو نقش را دارد که در صفحهٔ ابرآروان گفته شد: DNS، و اگر ابر نارنجی روشن باشد پروکسی جلوی سرور. این صفحه `app.example.com` را به IP عمومی پروکسی می‌بندد. عدد نمونه `203.0.113.10` است. IP واقعی را از پنل شبکهٔ خودتان بگذارید.

اگر دامنه از قبل روی ابرآروان است، برای همین نام Cloudflare را هم‌زمان روشن نکنید. یک لبه کافی است. مقایسهٔ مفهومی در [دامنه پشت IP](./cdn-origin) است.

## مفهوم اصلی

بعد از افزودن سایت در Cloudflare، پنل یک یا چند نیم‌سرور به شکل `*.ns.cloudflare.com` نشان می‌دهد. آن‌ها را در ثبت‌کننده می‌گذارید. تا `dig NS` همان‌ها را نگوید، رکوردهای داخل Cloudflare اثری روی اینترنت ندارند.

رکورد A مقدارش IP سرور است. ستون پروکسی دو حالت دارد. DNS only، ابر خاکستری، یعنی کاربر مستقیم به IP سرور می‌رود. Proxied، ابر نارنجی، یعنی کاربر به IP لبهٔ Cloudflare می‌رود و لبه به origin وصل می‌شود.

حالت SSL را روی Full strict بگذارید وقتی گواهی معتبر روی Nginx دارید. Full بدون strict گواهی خودامضای origin را قبول می‌کند و برای تولید موقت است نه حالت ماندن. Flexible اتصال لبه تا سرور را رمز نمی‌کند. برای سایت واقعی Flexible را نگذارید.

Cloudflare می‌تواند برای origin یک گواهی Origin CA صادر کند که فقط لبه آن را قبول می‌کند، نه مرورگر کاربر اگر کسی پروکسی را دور بزند. اگر این گواهی را روی Nginx بگذارید، حالت Full strict با خود Cloudflare کار می‌کند، ولی `curl` مستقیم به IP سرور خطای نام معتبر برای عموم می‌دهد. این رفتار خواسته است. اگر می‌خواهید حالت مستقیم هم بدون پروکسی قابل تست باشد، Let's Encrypt روی origin مناسب‌تر است.

چالش HTTP-01 با ابر نارنجی به سرور شما نمی‌رسد مگر مسیر چالش را Cloudflare به origin برساند و همان را Certbot دیده باشد. راه کم‌دردسر برای صدور اول: رکورد را خاکستری کنید، Certbot را بزنید، بعد نارنجی کنید. تمدید را یادداشت کنید. اگر نارنجی بماند و تمدید شکست بخورد، سایت یک صبح با گواهی origin منقضی از دید لبه می‌خوابد حتی اگر گواهی لبه هنوز معتبر باشد.

## چرا استفاده می‌شود؟

لبهٔ Cloudflare کش، مخفی کردن نسبی IP، و گواهی بین کاربر و لبه را می‌دهد. برای مخاطبی که از شبکهٔ خارج از کشور می‌آید گاهی پایدارتر از اتصال مستقیم به IP سرور است. برای مخاطب داخل ایران ممکن است برعکس باشد. این انتخاب محصول است نه پیش‌فرض این دانشنامه. اگر کاربر شما عمدتاً داخل ایران است، صفحهٔ ابرآروان را جدی‌تر از این صفحه آزمایش کنید و هر دو را با هم روی یک نام نگذارید.

DNS only هنوز ارزش دارد اگر فقط می‌خواهید DNS را جایی غیر از ثبت‌کننده مدیریت کنید و ترافیک مستقیم به سرور بخورد.

## Architecture

```text
ثبت‌کننده
    نیم‌سرور *.ns.cloudflare.com
            │
            ▼
رکورد A  app → 203.0.113.10
    Proxied (نارنجی) یا DNS only (خاکستری)
            │
            ▼
لبهٔ Cloudflare
    SSL Full strict
            │
            ▼
origin :443
    گواهی Let's Encrypt یا Origin CA
    Nginx  real_ip از بازهٔ IP خود Cloudflare
```

پورت مدیریت را پروکسی نکنید. رکوردی مثل `ssh.app.example.com` اگر ساختید خاکستری بماند و بهتر از آن، SSH اصلاً نام عمومی نداشته باشد.

## Installation

بستهٔ سروری برای Cloudflare لازم نیست. لیست IP لبه را از منبع رسمی همان روز بگیرید، چون ثابت نیست:

```bash
curl -fsSL https://www.cloudflare.com/ips-v4
curl -fsSL https://www.cloudflare.com/ips-v6
```

این فهرست را در کانفیگ Nginx به `set_real_ip_from` تبدیل می‌کنید. یک بار در ماه یا وقتی لاگ پر از IP غریبه شد، فهرست را دوباره بگیرید. اسکریپت کور که هر شب فایروال را از این URL عوض کند، اگر URL در دسترس نباشد ممکن است فایروال را خالی کند. تغییر فایروال را دستی و با کنسول آماده انجام دهید.

## Configuration

ترتیب کار:

1. سایت را در داشبورد اضافه کنید و نیم‌سرور را در ثبت‌کننده بگذارید.
2. رکورد A را با IP سرور بسازید. برای صدور گواهی، اول DNS only.
3. روی سرور Certbot را برای `app.example.com` بزنید. [Let's Encrypt](./ssl-letsencrypt).
4. در پنل SSL/TLS حالت را Full strict کنید.
5. رکورد را Proxied کنید.
6. Always Use HTTPS را وقتی حالت strict سالم بود روشن کنید، نه قبل از اینکه origin اصلاً ۴۴۳ داشته باشد.

نمونهٔ هدر IP واقعی. هر خط `set_real_ip_from` یکی از آدرس‌هایی است که `curl` بالا داده. اینجا فقط شکل فایل است. فهرست کامل را از همان URL بگذارید و این دو خط نمونه را به عنوان تمام فهرست قبول نکنید:

```nginx
real_ip_header CF-Connecting-IP;
# set_real_ip_from <هر خط فایل ips-v4 و ips-v6>;
```

`CF-Connecting-IP` را فقط اگر `set_real_ip_from` به بازهٔ خود Cloudflare محدود شده باور کنید. بدون آن محدودیت، مشتری هدر را جعل می‌کند.

WebSocket اگر برنامه دارد، در پنل شبکهٔ Cloudflare باید مجاز باشد. پیش‌فرض فعلی پروکسی آن را می‌گذارد. اگر ارتقا به WebSocket شکست خورد، اول این کلید را در پنل ببینید بعد Nginx را عوض نکنید.

`proxy_set_header Host $host` روی origin باید نام دامنه را به برنامه برساند، نه نام داخلی لبه را. بلوک Nginx همان بلوک صفحهٔ ابرآروان است و `proxy_pass` به آدرس داخلی `10.10.1.10` است.

## Production Example

تیم تصمیم می‌گیرد کاربر خارج از کشور به لبه برسد. نیم‌سرور Cloudflare ست می‌شود. رکورد اول خاکستری است. Certbot موفق است. `curl -sI https://app.example.com` از لپ‌تاپ گواهی Let's Encrypt را نشان می‌دهد و `dig` همان IP سرور است.

سپس حالت Full strict و ابر نارنجی. `dig` عوض می‌شود و IPهای لبه را نشان می‌دهد. مرورگر گواهی لبه را می‌بیند. از روی سرور، لاگ Nginx بعد از تنظیم `real_ip` آدرس کاربر را نشان می‌دهد نه فقط آدرس لبه.

یک درخواست آزمایشی با کوکی ورود می‌زنید تا مطمئن شوید حلقهٔ بازگشت و کش شدن صفحهٔ خصوصی ندارید. قانون کش را طوری می‌گذارید که HTML ورود کش نشود. فایل ثابت دارای hash می‌تواند کش شود.

## Security Notes

Authenticated Origin Pulls را اگر روشن می‌کنید، گواهی کلاینت لبه را واقعاً روی Nginx الزام کنید. روشن کردن گزینه در پنل بدون تنظیم Nginx فقط حس امنیت است.

قفل شدن پنل Cloudflare یعنی از دست دادن DNS. بیش از یک مدیر با ورود دومرحله‌ای داشته باشید و کد بازیابی را خارج از همان حساب نگه دارید.

API token را به دامنهٔ همان زون و به مجوز DNS محدود کنید اگر اسکریپت تمدید می‌نویسید. توکن سراسری حساب را روی سرور نگذارید.

پنهان بودن IP کامل نیست. ایمیل هدر، رکورد قدیمی، و نشت در لاگ عمومی IP را لو می‌دهد. فایروال origin را بخشی از طراحی بدانید نه تزئین.

## Troubleshooting

| نشانه | کار |
| --- | --- |
| خطای 521 | لبه به origin وصل نمی‌شود. پورت ۴۴۳، UFW، و اینکه وب‌سرور بالا باشد |
| خطای 522 | TCP باز شده ولی جواب نیامده. کندی یا بسته شدن وسط راه. از خود سرور بار را ببینید |
| خطای 525 | TLS تا origin شکست خورده. حالت SSL با گواهی origin نمی‌خواند. Full strict با گواهی منقضی یا نام اشتباه همین است |
| حلقهٔ بازگشت | origin دوباره به نام پروکسی‌شده وصل می‌شود |
| `dig` خاکستری مانده | مرورگر یا resolver کش دارد، یا رکورد را ذخیره نکرده‌اید. `dig @1.1.1.1 app.example.com` |
| Certbot 403 یا timeout | رکورد نارنجی است. خاکستری کنید یا DNS-01 |
| کاربر IP خودش را در لاگ نمی‌بینید | `CF-Connecting-IP` و `set_real_ip_from` ناقص است |

عدد خطا مال خود Cloudflare است. آن را با کد HTTP برنامه قاطی نکنید. ۵۲۱ یعنی لبه سرور شما را ندیده، نه اینکه Laravel خطای ۵۲۱ داده باشد.

## Best Practices

- Full strict وقتی نارنجی می‌کنید. Flexible را برای این دانشنامه حالت تولید ندانید.
- رکورد را برای صدور گواهی خاکستری کنید، بعد نارنجی.
- فهرست IP را از `cloudflare.com/ips-v4` و `ips-v6` بگیرید و تاریخ کپی را کنار فایل بنویسید.
- صفحهٔ ورود و کوکی را کش نکنید.
- این پنل را با ابرآروان برای یک نام همزمان روشن نکنید.
