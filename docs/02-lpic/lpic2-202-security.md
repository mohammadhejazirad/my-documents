# امنیت ۲۰۲

## مقدمه

هدف ۲۱۲ آزمون ۲۰۲ امنیت سرویس است: راهیاب، FTP، SSH پیشرفته، کارهایی مثل پورت‌اسکن و sudo، و آگاهی از VPN. صفحهٔ [امنیت ۱۰۲](/docs/02-lpic/lpic1-102-security) کلید ed25519 و بستن رمز را ساخته است. سخت‌سازی ماندگار SSH، قانون UFW، و Fail2ban هر کدام صفحهٔ خود را دارند: [سخت‌سازی SSH](/docs/10-security/ssh-hardening)، [UFW](/docs/10-security/ufw)، [Fail2ban](/docs/10-security/fail2ban)، [کاربر و فایل](/docs/10-security/users-and-files). اینجا همان‌ها را رونویسی نمی‌کنیم. سناریو این است که یک VM کلون‌شده با سیاست شل به شما رسیده و باید با دستور ثابت کنید چه چیزی هنوز باز است.

FTP و OpenVPN را سرویس این آزمایشگاه نمی‌کنیم. آزمون اسم‌شان را می‌پرسد. راهیاب شدن `app-1` هم خواستهٔ این صفحه نیست؛ جلورانی بسته باید خاموش بماند.

## مفهوم اصلی

امنیت ۲۰۲ یعنی چند کنترل که هر کدام لایهٔ بعدی را فرض می‌کنند. SSH حتی با کلید، اگر روی همهٔ رابط‌ها و بدون سقف تلاش باشد، هزینهٔ پویش را صفر نمی‌کند. فایروال اگر SSH را فقط از `10.10.1.0/24` بپذیرد، پویش از جای دیگر به لاگ هم نمی‌رسد. Fail2ban و `PerSourcePenalties` هر دو بعد از دیدن رفتار بد واکنش نشان می‌دهند؛ یکی از روی لاگ، یکی داخل خود sshd. sudo اگر `ALL` باشد، فایروال و کلید فقط جلوی آدم بیرون را می‌گیرند و یک حساب دزدیده‌شده همه‌کاره است.

اسکن در این هدف یعنی دیدن پورت باز خودتان، نه پیدا کردن آسیب در شبکهٔ دیگران. `ss` روی خود میزبان دقیق‌تر از اسکن است چون فرایند را می‌گوید. `nmap` از دید یک میزبان دیگر همان چیزی را نشان می‌دهد که مهاجم می‌بیند، به شرطی که فایروال بین راه باشد. هر دو لازم‌اند و یکی جایگزین دیگری نیست.

`Match` در sshd سیاست را برای مبدأ یا کاربر عوض می‌کند، بعد از خط‌های سراسری. ترتیب مهم است. یک `Match` خیلی کلی در ته فایل، خط‌های قبلی را برای همان شرط بازنویسی می‌کند.

## چرا استفاده می‌شود؟

کلون VM سیاست SSH و کلید میزبان و گاهی `sudoers` را با خود می‌برد. صفحهٔ معماری هویت ماشین را عوض کرد. این صفحه سیاست دسترسی را حسابرسی می‌کند. بدون این حسابرسی، سرور «تازه» همان رمز و همان `NOPASSWD: ALL` تصویر طلایی را دارد.

دلیل جدا کردن از صفحهٔ UFW این است که آزمون هنوز شکل `iptables` و سوال راهیاب را می‌آورد. اپراتور باید بتواند بگوید UFW مالک قانون است، `nft list ruleset` حقیقت هسته است، و روشن کردن `ip_forward` این میزبان را به راهیاب تبدیل می‌کند حتی اگر کسی اسمش را نگذارد.

## Architecture

```text
ایستگاه مدیر در 10.10.1.0/24
    │
    ▼
UFW: فقط 22 از همین زیرشبکه، 80 و 443 طبق سرویس
    │
    ▼
sshd
    AllowUsers ops
    PasswordAuthentication no
    PermitRootLogin no
    PerSourcePenalties yes
    Match برای بستن فوروارد وقتی لازم است
    │
    ▼
sudoers.d  فرمان محدود، نه ALL
    │
    ▼
برنامه با کاربر deploy، بدون پوستهٔ تعاملی

لایهٔ واکنشی
    PerSourcePenalties داخل sshd
    Fail2ban فقط اگر لاگ را جدا می‌خواهید؛ صفحهٔ خودش
```

هدف ۲۱۲.۱ راهیاب را با جلورانی و NAT توصیف می‌کند. `app-1` برنامه است. `net.ipv4.ip_forward` باید ۰ بماند، همان‌طور که در [کرنل](/docs/02-lpic/lpic2-201-kernel) گذاشتید. NAT را روی این میزبان تمرین نکنید. اگر سؤال آزمون MASQUERADE را آورد، بدانید آن کار مال یک میزبان در لبه است که طراحی و لاگ جدا دارد، نه یک خط اضافه روی سرور برنامه.

هدف ۲۱۲.۲ سرور FTP را می‌شناسد. FTP رمز را جدا از کانال فرمان نمی‌فرستد مگر FTPS یا جایگزینی مثل SSH. ما به‌جای FTP از SSH استفاده می‌کنیم و سرویس `vsftpd` را نصب نمی‌کنیم. هدف ۲۱۲.۵ OpenVPN را در حد آگاهی می‌خواهد. تونل این آزمایشگاه ساخته نمی‌شود؛ اگر سازمان VPN دارد، همان درگاه رسمی است نه یک سرور آزمایشی روی `app-1`.

## Installation

بستهٔ تازهٔ اجباری فقط اگر اسکن از خود میزبان لازم است `nmap` است. Fail2ban را اینجا نصب نکنید مگر صفحهٔ خودش را خوانده باشید و زندان تکراری با sshd نسازید.

```bash
sudo apt update
sudo apt install nmap
nmap --version | head -n 1
sudo sshd -T | awk 'BEGIN{IGNORECASE=1} $1=="persourcepenalties" || $1=="passwordauthentication" || $1=="permitrootlogin"'
```

اگر سه مقدار مطلوب صفحهٔ ۱۰۲ را ندارید، اول همان را درست کنید. این صفحه روی درِ باز، قفل اضافه نمی‌گذارد.

UFW باید قبل از هر اسکن «از بیرون» تصمیم داشته باشد. وضعیت را بخوانید:

```bash
sudo ufw status verbose
```

اگر `inactive` است، فعال‌سازی را از [UFW](/docs/10-security/ufw) انجام دهید و قانون SSH آزمایشگاه را همان‌جا بگذارید، بعد به این صفحه برگردید. فعال کردن وسط این صفحه بدون آن قانون، همان سناریوی قفل شدن است.

## Configuration

یک تکهٔ SSH که صفحهٔ ۱۰۲ نبود: بستن فوروارد تعاملی برای کاربر عادی، سقف تلاش، و جریمهٔ مبدأ که صریح نوشته شده تا ارتقای بعدی به پیش‌فرض نانوشته تکیه نکند. فایل را جدا از `10-ops.conf` بگذارید.

```bash
sudo tee /etc/ssh/sshd_config.d/20-hardening.conf >/dev/null <<'EOF'
MaxAuthTries 3
ClientAliveInterval 300
ClientAliveCountMax 2
X11Forwarding no
AllowTcpForwarding no
PerSourcePenalties yes
PerSourcePenaltyExemptList 10.10.1.0/24
EOF
sudo sshd -t && sudo systemctl reload ssh
```

`PerSourcePenaltyExemptList` یعنی از داخل آزمایشگاه خودتان را برای یک اشتباه پیکربندی مدت‌دار قفل نکنید. از اینترنت، اگر این میزبان اصلاً آنجا دیده شود، جریمه سر جایش است. فهرست معافیت را به شبکهٔ خانهٔ شخصی گسترش ندهید.

`AllowTcpForwarding no` تونل را می‌بندد. آزمون تونل SSH را در سطح ۱ می‌شناسد و در تولید این تیم تونل روی سرور برنامه خاموش است. اگر روزی برای یک عیب‌یابی کوتاه لازم شد، یک `Match User` موقت با تاریخ انقضا در تیکت بسازید و همان روز بردارید. شکل بدون باز کردن برای همه:

```text
Match User ops Address 10.10.1.0/24
    AllowTcpForwarding local
```

این بلوک را در فایل دائمی نگذارید مگر تیکت باز دارد. `Match` تا انتهای فایل یا تا `Match` بعدی ادامه دارد. ته فایل، بعد از Match، گزینهٔ سراسری ننویسید چون فقط داخل همان شرط اثر می‌کند و شما فکر می‌کنید سراسری است.

sudo محدود برای کار ظرفیت. اگر فایل صفحهٔ ۱۰۲ فقط `df` و `du` بود، اینجا شکل آزمون با `Cmnd_Alias` را نشان می‌دهیم. ویرایش فقط با visudo.

```bash
sudo visudo -f /etc/sudoers.d/ops-capacity
```

محتوا:

```text
Cmnd_Alias CAPACITY = /usr/bin/df, /usr/bin/du, /usr/bin/uptime
ops ALL=(root) NOPASSWD: CAPACITY
```

مسیر فرمان باید خروجی `command -v df` باشد. اگر کسی `df` را با مسیر دیگر در sudoers بنویسد، sudo رد می‌کند یا بدتر، فرمان دیگری اجرا می‌شود اگر `PATH` را در sudoers دستکاری کرده باشید. `secure_path` پیش‌فرض را دست نزنید.

اثبات:

```bash
sudo -l -U ops
sudo df -hT /
```

خط `NOPASSWD: ALL` اگر در خروجی `sudo -l` بود، از تصویر کلون آمده و باید حذف شود. `sudo visudo -f` روی همان فایل، نه پاک کردن `/etc/sudoers` اصلی که گروه `sudo` را برای مدیریت کامل با رمز نگه می‌دارد. فرق این دو را در تیکت بنویسید: گروه sudo با رمز برای مدیر، alias بدون رمز فقط برای سه فرمان.

## Production Example

VM تازه‌کلون `app-1` را قبل از دادن به تیم با این چهار شاهد تحویل بگیرید.

شاهد پورت، از خود میزبان:

```bash
sudo ss -lntup
```

انتظار: `sshd` روی ۲۲، و اگر فصل وب را تمام کرده‌اید `nginx` روی ۸۰. نبودن `apache2` همزمان. نبودن ۲۱ و ۲۳ و ۳۱۲۸. هر خط اضافه یعنی سرویس را شناسایی کنید: `sudo systemctl status نام` و بعد disable، نه kill بی‌نام.

شاهد از دید شبکه، فقط به همین میزبان و فقط پورت‌های مشخص. این اسکن مجاز آزمایشگاه است.

```bash
sudo nmap -sT -Pn -p 22,80,443,21,23 10.10.1.10
```

`-sT` اتصال کامل TCP است و به خام بودن سوکت نیاز ندارد. `-Pn` یعنی اگر ICMP بسته باشد میزبان را مرده حساب نکن. خروجی `closed` برای ۲۱ و ۲۳ مطلوب است. `filtered` یعنی فایروال جواب را دور ریخته. `open` روی ۲۱ یعنی FTP واقعاً بالاست و با «در آزمون خواندم» فرق دارد.

شاهد sudo و SSH را در یادداشت تغییر بچسبانید: خروجی `sudo -l -U ops` و سه خط `sshd -T`. شاهد فایل حساس:

```bash
sudo find /etc /usr/local /opt -xdev -perm -002 -type f 2>/dev/null
```

فایل نوشتنی برای دیگران در `/etc` حادثه است. نمونهٔ بد، اسکریپت پشتیبان با حالت ۶۶۶ است. `chmod o-w` کافی نیست تا صاحب و محتوا را نفهمید؛ اول `ls -l` و بستهٔ مالک `dpkg -S`.

Fail2ban را وقتی اضافه کنید که لاگ احراز هویت را یک سیستم دیگر باید ببیند یا سیاست سازمان زندان زمانی صریح می‌خواهد. sshd با `PerSourcePenalties` خودش منبع بد را برای مدتی رد می‌کند. دو مکانیزم با هم، اگر هر دو روی یک آستانه باشند، عیب‌یابی «چرا IP من بلاک است» را دو جا می‌کند. انتخاب و فایل زندان در [Fail2ban](/docs/10-security/fail2ban) است. اینجا فقط تصمیم را بنویسید: یا جریمهٔ خود OpenSSH، یا Fail2ban، و اگر هر دو، آستانه‌ها و فهرست سفید آزمایشگاه در هر دو ثبت شود.

## Security Notes

`PerSourcePenaltyExemptList` را خالی نگذارید اگر از داخل همان سرور با اسکریپت به SSH خودش وصل می‌شوید، و آن را برابر `0.0.0.0/0` نکنید چون جریمه را بی‌اثر می‌کند.

اسکن را به `10.10.1.10` یا فهرست میزبان‌های همین سند محدود کنید. `nmap` روی زیرشبکهٔ بزرگ، حتی مال سازمان، بدون پنجرهٔ تغییر، آلارم امنیتی است و این صفحه مجوز آن را نمی‌دهد. گزینهٔ اکسپلویت و اسکریپت آسیب‌شناسی `nmap` مال این تمرین نیست.

`sudo -l` را برای کاربر دیگر با `sudo -l -U` بزنید. عوض کردن کاربر با `su` فقط برای دیدن sudo، رد اضافی در لاگ و خطر ماندن در پوستهٔ غلط است.

کلید خصوصی را برای «اسکن از جای دیگر» روی سرور کپی نکنید. اسکن آزمایشگاه از خود `app-1` به آدرس خودش کافی است.

## Troubleshooting

علامت: بعد از reload، SSH از بیرون آزمایشگاه باز است و از داخل بسته. `AllowUsers` یا معافیت جریمه را برعکس نوشته‌اید، یا UFW فقط رابط اشتباه را باز کرده. `sudo sshd -T` و `sudo ufw status verbose` را کنار هم بگذارید. قانون UFW شمارهٔ پورت را می‌گوید؛ sshd می‌گوید بعد از رسیدن بسته، چه کسی حق ورود دارد. بسته می‌تواند به sshd برسد و باز هم `AllowUsers` رد کند. آن وقت nmap پورت را `open` نشان می‌دهد و ورود شکست می‌خورد. این تناقض طبیعی است.

علامت: `sshd -t` خطای `Directive 'X' is not allowed within a Match block`. گزینه‌ای را زیر `Match` گذاشته‌اید که فقط سراسری مجاز است. بلوک Match را موقتاً بردارید، `-t` را سبز کنید، بعد گزینه را خط به خط برگردانید.

علامت: `sudo -l` فرمان CAPACITY را نشان نمی‌دهد. فایل `/etc/sudoers.d/ops-capacity` حالتش غلط است. sudo تکه‌ای را که برای دیگران نوشتنی است نادیده می‌گیرد. `sudo chmod 440` روی همان فایل و `sudo visudo -c` برای کل مجموعه.

علامت: nmap همه را `filtered` نشان می‌دهد در حالی که از خود سرور `ss` شنونده دارد. فایروال دارد کار می‌کند. اگر خود شما هم نمی‌توانید SSH کنید، قانون منبع `10.10.1.0/24` را از کنسول اصلاح کنید، نه با باز کردن پورت روی همه.

## Best Practices

- سیاست SSH را در دو فایل کوچک نگه دارید، نه یک فایل بزرگ که Match تهش اثر سراسری را دزدیده باشد.
- UFW مالک قانون شبکه بماند. این صفحه ruleset موازی بار نمی‌کند. دیدن با `nft list ruleset` در [شبکهٔ ۲۰۱](/docs/02-lpic/lpic2-201-networking) است.
- sudo بدون رمز فقط برای فرمان با مسیر کامل. `NOPASSWD: ALL` را در خروجی کلون حذف کنید.
- یک مکانیزم جریمهٔ SSH را صاحب بدانید و دومی را فقط با دلیل اضافه کنید.
- FTP و OpenVPN و NAT را چون در عنوان آزمون هستند روی `app-1` روشن نکنید.
- اسکن را کوتاه، مشخص، و داخل آزمایشگاه نگه دارید.

## تمرین

سناریو: تصویر کلون این خروجی را داده است. شما باید بگویید کدام خط را قبل از تحویل عوض می‌کنید و کدام را دست نمی‌زنید.

```text
passwordauthentication yes
permitrootlogin prohibit-password
persourcepenalties yes
```

و `sudo -l -U ops` خط `NOPASSWD: ALL` دارد. `ss` پورت ۲۱ را هم باز نشان می‌دهد.

دستورهای اثبات بعد از اصلاح:

```bash
sudo sshd -T | awk 'BEGIN{IGNORECASE=1} $1=="passwordauthentication" || $1=="permitrootlogin"'
sudo -l -U ops
sudo ss -lntup | awk '/:21|:22/'
```

سؤال‌ها:

1. چرا `nmap` پورت ۲۲ را open نشان می‌دهد ولی ورود با رمز شکست می‌خورد؟
2. `Match` اگر وسط فایل باشد چه بلایی سر گزینه‌های بعد از خودش می‌آورد؟
3. چرا `ip_forward=1` روی `app-1` پاسخ «سرور امن‌تر» نیست؟

## پاسخ تمرین

رمز باید `no` شود و ورود ریشه `no`، با همان روش صفحهٔ ۱۰۲ و یک نشست کنسول باز. `prohibit-password` را به‌خاطر این که «بهتر از yes است» رها نکنید؛ سیاست این دانشنامه ورود ریشه از SSH را کلاً نمی‌خواهد. `PerSourcePenalties yes` را دست نزنید.

خط `NOPASSWD: ALL` را از فایل drop-in مربوط حذف کنید. گروه `sudo` با رمز می‌تواند بماند. سپس alias ظرفیت را اگر لازم دارید جدا بسازید. `sudo -l -U ops` دیگر نباید `ALL` بدون رمز نشان دهد.

پورت ۲۱ را با شناسایی واحد سرویس ببندید: `systemctl disable --now` روی همان واحد، بعد `ss` دیگر `:21` نشان ندهد. بسته را همان لحظه purge نکنید تا بدانید چه کسی خواسته‌اش.

1. چون nmap فقط دست‌دادن TCP را می‌بیند. احراز هویت لایهٔ بعد است. پورت باز یعنی sshd گوش می‌دهد، نه این که رمز قبول است.
2. گزینه‌های بعد از `Match` تا Match بعدی فقط وقتی شرط آن بلوک درست باشد اعمال می‌شوند. اگر فکر کنید هنوز سراسری‌اند، یا سیاستتان برای بقیهٔ کاربران اصلاً بار نمی‌شود یا فقط برای همان آدرس بار می‌شود.
3. چون میزبان را به راهیاب تبدیل می‌کند و ترافیکی که مال این برنامه نیست ممکن است از آن عبور کند. امنیت `app-1` یعنی جلورانی خاموش، نه NAT آزمایشی. راهیاب واقعی طراحی لبه می‌خواهد.
