# دستورهای GNU

## مقدمه

هدف ۱۰۳ بخش بزرگی از آزمون ۱۰۱ است: خط فرمان، فیلتر متن، فایل، لوله (pipe) و تغییر مسیر (redirect)، فرایند، اولویت، عبارت منظم، و ویرایشگر vi. مرجع تک‌دستور این دانشنامه جای دیگری است و این صفحه آن را کپی نمی‌کند. برای معنی هر دستور به [فایل](/docs/01-linux/commands-files)، [متن](/docs/01-linux/commands-text)، [فرایند](/docs/01-linux/commands-process)، [آرشیو و انتقال](/docs/01-linux/commands-archive-transfer)، [دیسک](/docs/01-linux/commands-disk) و [شبکه](/docs/01-linux/commands-network) بروید.

کار این صفحه ترکیب دستورهاست، به‌علاوهٔ تله‌ای که بین GNU coreutils روی Ubuntu و چیزی که نمونه سؤال از یونیکس عمومی یا BSD آورده فرق می‌کند. اگر فقط یک دستور را بلدید و نمی‌توانید خروجی‌اش را به دستور بعدی بدهید، هم آزمون را سخت می‌دهید و هم شیفت را.

## مفهوم اصلی

هر فرایند سه جریان استاندارد دارد: ورودی ۰، خروجی ۱، و خطا ۲. لوله خروجی استاندارد یک فرایند را به ورودی بعدی می‌دهد و خطا را عبور نمی‌دهد، مگر خودتان ۲ را هم وصل کنید. تغییر مسیر با فایل سروکار دارد. این دو را با هم عوض نکنید: `sort file` آرگومان است، `sort < file` ورودی استاندارد است، و برای `sort` نتیجه یکی است ولی برای دستوری که آرگومان فایل را جور دیگری معنی می‌کند یکی نیست.

پوسته قبل از اجرا بسط می‌دهد. ستاره را هسته نمی‌بیند؛ bash آن را به فهرست فایل تبدیل می‌کند. به همین دلیل `rm *` خطرناک است و به همین دلیل دستور را بعد از دیدن `echo` همان الگو اجرا می‌کنیم وقتی حذف گسترده است.

روی Ubuntu و Debian، `/bin/ls` و `cp` و `sed` و `grep` نسخهٔ GNU هستند، حتی اگر مسیر واقعی‌شان زیر `/usr` باشد. پیاده‌سازی BusyBox روی بعضی ایمیج‌های کوچک، فلگ بلند GNU را ندارد. اگر روی سرور `ls --time-style=long-iso` خطا داد، اول بپرسید coreutils نصب است یا یک جعبهٔ محدود.

`/bin/sh` اینجا bash نیست. dash است. این موضوع در [شل](/docs/02-lpic/lpic1-102-shell) باز می‌شود. دستورهای این صفحه را در bash تعاملی بزنید.

## چرا استفاده می‌شود؟

گزارش دیسک و لاگ و فرایند را ابزار گرافیکی روی سرور بدون میزکار نمی‌دهد. یک خط که `du` را به `sort` بدهد همان کاری را می‌کند که هدف آزمون «فیلتر جریان متن» می‌نامد، و همان کاری است که قبل از پاک کردن لاگ باید بکنید.

دلیل دوم تفاوت فلگ است. `sed -i` بدون پسوند پشتیبان روی GNU کار می‌کند و روی BSD بدون آرگومان اضافه خطا می‌دهد یا فایل را خراب تفسیر می‌کند. سرور ما GNU است. اسکریپتی که از مک کپی شده را قبل از اجرا روی تولید با `sed --version` محک بزنید.

## Architecture

جریان یک بررسی واقعی «کدام لاگ بزرگ است» این شکل را دارد:

```text
du -h /var/log
    │  خروجی استاندارد
    ▼
sort -h          مرتب‌سازی انسانی GNU
    │
    ▼
tail -n 5        پنج تای آخر
    │
    ├─► stdout ترمینال
    └─► tee /tmp/big-logs.txt   کپی همزمان روی دیسک
```

خطاهای `du`، مثل مجوز نخواندن یک دایرکتوری، از این لوله رد نمی‌شوند و مستقیم به ترمینال می‌آیند. اگر بخواهید در فایل باشند باید `2>` داشته باشید.

ابزارهایی که آزمون در هدف ۱۰۳ اسم می‌برد و ترکیب‌شان اینجاست، نه معرفی دوبارهٔ هر کدام: `cut`، `sort`، `uniq`، `tr`، `wc`، `head`، `tail`، `tee`، `xargs`، `find`، `tar`، `nice`، `grep`، و vi. `egrep` و `fgrep` هنوز در سؤال هستند و روی GNU فقط پوستهٔ `grep -E` و `grep -F` اند. در اسکریپت تازه همان شکل صریح را بنویسید.

## Installation

coreutils و findutils و grep و sed و gawk بخشی از سیستم پایهٔ Ubuntu Server هستند. بستهٔ جدا برای «دستور GNU» نگذارید. ویرایشگر پیش‌فرض آزمون vi است. روی سرور حداقلی ممکن است فقط `vim.tiny` باشد.

```bash
sed --version | head -n 1
grep --version | head -n 1
type vi vim nano
```

خروجی مورد انتظار شبیه این است:

```text
sed (GNU sed) 4.9
grep (GNU grep) 3.12
vi is /usr/bin/vi
```

شمارهٔ کوچک مهم نیست. کلمهٔ GNU مهم است. اگر `vi` نبود: `sudo apt install vim-tiny`. برای کار روز، nano کافی است و آزمون همچنان vi می‌خواهد. متغیر `EDITOR` را برای ابزارهایی مثل `visudo` و `crontab` صریح بگذارید.

```bash
sudo update-alternatives --display editor
```

## Configuration

تاریخچه در حافظهٔ نشست است و هنگام خروج تمیز در `~/.bash_history` می‌نشیند. اگر نشست با قطع SSH بمیرد، آخرین خط‌ها ممکن است نرسند. `history` را برای یادداشت شیفت کافی ندانید؛ دستوری که اثر تولیدی دارد باید در تیکت باشد.

`PATH` تعیین می‌کند نام فرمان کجا حل شود. `type` بهتر از `which` است چون می‌گوید alias یا تابع یا دودویی. آزمون هر دو را نام می‌برد.

```bash
type ls ps grep
echo "$PATH"
```

روی Ubuntu، `ls` اغلب alias به `ls --color=auto` است. در اسکریپت alias وجود ندارد مگر `shopt -s expand_aliases` کرده باشید. پس رنگ و ستون اضافه را در اسکریپت فرض نکنید. `ls -l --time-style=long-iso` خروجی را برای بریدن با `awk` پایدار می‌کند. این فلگ GNU است.

اولویت پیش‌فرض فرایند صفر است، یعنی ستون NI در `ps` صفر است. عدد nice بالاتر یعنی مودب‌تر و کندتر. بازهٔ معمول ۱۹ تا ۲۰- است. کاربر عادی فقط می‌تواند اولویت را بدتر کند. بهتر کردن اولویت root می‌خواهد.

```bash
ps -o pid,ni,comm -p $$
```

## Production Example

دیسک `/var` روی `app-1` به ۸۰ درصد رسیده. قبل از حذف، باید دانست کدام دایرکتوری بزرگ است و آیا فایل در همین لحظه در حال رشد است. این ترکیب، مرجع `du` را تکرار نمی‌کند؛ تصمیم شیفت را می‌سازد.

```bash
du -xh /var 2>/dev/null | sort -h | tail -n 8
du -xh /var/log 2>/dev/null | sort -h | tail -n 5
find /var/log -type f -size +50M -printf '%s %p\n' | sort -n
```

`find -printf` افزونهٔ GNU findutils است و در POSIX پیدا نیست. روی این سرور درست است. اگر بخواهید اسکریپت قابل‌حمل باشد، `-printf` را برندارید به محیط غیر GNU.

خروجی فرضی:

```text
52428800 /var/log/nginx/access.log.1
104857600 /var/log/journal
```

قدم بعدی حذف دستی لاگ فعال نیست. لاگ باز را برنامه هنوز گرفته است. یا `logrotate` را بفهمید یا journal را با ابزار خودش کوچک کنید. آن کار در [مدیریت ۲۰۱](/docs/02-lpic/lpic2-201-administration) و [مدیریت لاگ](/docs/12-monitoring/log-management) است. اینجا فقط پیدا کردن است.

یک لولهٔ متن که آزمون و لاگ هر دو دوست دارند، شمردن نشانی‌هایی است که زیاد به nginx خورده‌اند:

```bash
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -nr | head
```

اگر فایل وجود ندارد، nginx نصب نیست یا مسیر لاگ فرق دارد. دستور را با مسیر خیالی «تا خطا بدهد» تکرار نکنید.

برای فشردن همان گزارش و بردنش به ایستگاه مدیر، GNU tar:

```bash
tar -C /tmp -czf /tmp/top-ips.tgz top-ips.txt
sha256sum /tmp/top-ips.tgz
```

`tar -czf` یعنی ساختن آرشیو gzip. ترتیب حرف در بعضی tarهای قدیمی مهم بود. GNU با این ترتیب مشکلی ندارد اگر `f` درست قبل از نام فایل باشد. `dd` را برای کپی دیسک در همین صفحه تبلیغ نمی‌کنیم؛ یک اشتباه در `of=` دیسک را پاک می‌کند. وقتی واقعاً لازم شد، در سند تغییر و با `lsblk` نوشته می‌شود.

کار پس‌زمینه که آزمون می‌پرسد: `&`، `jobs`، `fg`، `bg`، `nohup`، و `tmux`. برای یک کار طولانی روی SSH، `tmux` از `nohup` قابل‌فهم‌تر است چون خروجی را بعداً می‌بینید. `nohup` خروجی را به `nohup.out` می‌ریزد و اگر در دایرکتوری خانهٔ شلوغ باشد فراموش می‌شود.

```bash
tmux new -s diskcheck
```

جدا شدن از نشست `Ctrl-b` سپس `d` است. برگشت: `tmux attach -t diskcheck`.

vi در حدی که هدف ۱۰۳.۸ نمره می‌دهد: `i` درج، `Esc` بازگشت به حالت فرمان، `dd` حذف خط، `yy` کپی خط، `p` چسباندن، `/کلمه` جستجو، `:w` ذخیره، `:q` خروج، `ZZ` ذخیره و خروج، `:q!` خروج بی‌ذخیره. `nano` را بشناسید و اگر `EDITOR` خالی است، `visudo` ممکن است vi باز کند. در vi گیر کردید `Esc` سپس `:q!`.

## Security Notes

`xargs` بدون `-0` روی نام فایل دارای فاصله می‌شکند و ممکن است فایل دیگری را به دستور حذف بدهد. ترکیب امن پیدا کردن و عمل کردن، وقتی حذف لازم است:

```bash
find /tmp/lab-empty -type f -print0 | xargs -0 -r ls -l
```

تا وقتی `ls` را ندیده‌اید `rm` را جای `ls` نگذارید. `-r` در GNU xargs یعنی اگر ورودی خالی بود دستور را اجرا نکن.

`grep -R` روی `/` به‌خاطر `/proc` و `/sys` کند و گاهی گمراه‌کننده است. جستجوی رمز را به دایرکتوری کانفیگ محدود کنید. خروجی را در تیکت عمومی نچسبانید.

تغییر اولویت به ۲۰- برای یک `find` روی تولید، CPU را از سرویس می‌گیرد. جهت را برعکس نکنید: کار تعمیراتی باید nice مثبت بگیرد، مثلاً `nice -n 15`.

## Troubleshooting

علامت: `grep` چیزی پیدا نمی‌کند در حالی که در فایل هست.

اول نوع عبارت منظم را بسنجید. بدون `-E`، علامت `+` و `?` و پرانتز معمولی‌اند مگر پشته شوند. آزمون فرق BRE و ERE را می‌خواهد.

```bash
printf 'error\nerror\nwarn\n' | grep -c 'error'
printf 'aab\n' | grep -E 'a+' 
```

علامت دوم: لوله وسط کار «متوقف» است. اغلب دستور بعدی منتظر ورودی است چون دستور اول هنوز stdout را نبسته، یا خودتان `head` را فراموش کرده‌اید و `sort` باید کل جریان را ببیند تا خروجی بدهد. `sort` تا EOF مرتب نمی‌کند. این خرابی نیست.

علامت سوم: `ps aux | grep nginx` خود خط grep را هم نشان می‌دهد. برای تصمیم عملیاتی به‌جایش از ابزار فرایند استفاده کنید.

```bash
pgrep -a nginx || echo 'nginx not running'
ps -eo pid,ni,comm --sort=-ni | head
```

اگر `pgrep` خالی بود و echo خودتان چاپ شد، سرویس بالا نیست. بروید سراغ `systemctl status nginx`، نه یک grep تهاجمی‌تر.

## Best Practices

- مرجع فلگ هر دستور در فصل لینوکس است. اینجا لوله را تا وقتی خروجی‌اش تصمیم را عوض می‌کند ادامه دهید و بعد متوقف شوید.
- فلگ GNU را در اسکریپت تولید استفاده کنید فقط اگر شِبنگ bash یا محیط Ubuntu/Debian را قفل کرده‌اید. `sed --version` را در شک تشخیص بگذارید.
- `type` را به `which` ترجیح دهید. alias را در اسکریپت فرض نکنید.
- پیش از `find ... -delete` یا `xargs rm`، همان دستور را با `ls` یا `-print` ببینید.
- vi را در حد خروج امن بلد باشید حتی اگر روزمره nano می‌نویسید. `EDITOR` را در پروفایل `ops` صریح کنید تا `visudo` سورپرایز نباشد. پروفایل در [شل](/docs/02-lpic/lpic1-102-shell) است.

## تمرین

روی `app-1` یک فایل تمرین بسازید و با لوله خلاصه‌اش کنید. چیزی را خارج از `/tmp/lpic-text` حذف نکنید.

```bash
mkdir -p /tmp/lpic-text
printf '10.10.1.5 ok\n10.10.1.10 fail\n10.10.1.10 fail\n10.10.1.20 ok\n' > /tmp/lpic-text/checks.txt
awk '{print $2}' /tmp/lpic-text/checks.txt | sort | uniq -c
grep -E 'fail$' /tmp/lpic-text/checks.txt | tee /tmp/lpic-text/fails.txt | wc -l
nice -n 15 wc -l /tmp/lpic-text/checks.txt
```

سؤال کوتاه:

1. چرا خطای مجوز `du` داخل `sort` نمی‌رود؟
2. `grep -E` معادل کدام فرمان قدیمی آزمون است؟
3. در vi، ذخیره و خروج یک‌ضرب کدام فرمان حالت فرمان است؟

## پاسخ تمرین

`uniq -c` باید دو بار `ok` و دو بار `fail` را نشان دهد، چون دو خط fail مربوط به `10.10.1.10` است و awk فقط ستون دوم را داده. `wc -l` باید `2` باشد. `nice` عدد را عوض نمی‌کند؛ `wc` همان یک خط فایل را می‌شمارد و فقط اگر `ps` را همزمان دیده باشید NI برابر ۱۵ روی آن فرایند کوتاه ظاهر می‌شود. ممکن است آن‌قدر زود تمام شود که نبینید؛ این شکست تمرین نیست.

1. لوله فقط جریان ۱ را وصل می‌کند. خطا جریان ۲ است و همچنان به ترمینال می‌رود مگر `2>&1` قبل از لوله آمده باشد.
2. `egrep`. در اسکریپت جدید همان `grep -E` را بنویسید. `fgrep` هم معادل `grep -F` است، یعنی الگوی ثابت نه عبارت منظم.
3. `ZZ`. معادل دو مرحله‌ای‌اش `:w` و `:q` است. `:q!` ذخیره نمی‌کند.
