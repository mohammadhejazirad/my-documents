# ذخیره‌سازی پیشرفته

## مقدمه

هدف ۲۰۴ آزمون ۲۰۱ یعنی RAID، تنظیم دسترسی به دستگاه، و LVM فراتر از ساخت یک حجم. ساخت سادهٔ PV و VG و LV و همچنین fstab در [دیسک ۱۰۱](/docs/02-lpic/lpic1-101-disk) است. اینجا گسترش آنلاین، snapshot، آرایهٔ نرم mdadm، و این که LUKS چیست می‌آید. رمزنگاری دیسک را به‌صورت یک سرور کامل رمزشده قالب نمی‌کنیم. دستور `cryptsetup luksOpen` را با هشدار نشان می‌دهیم چون یک اشتباه دستگاه، داده را غیرقابل‌خواندن می‌کند نه این که «یک کانفیگ دیگر» باشد.

دیسک‌های مثال `/dev/sdb` و `/dev/sdc` و `/dev/sdd` هستند و باید خالی باشند. ریشه روی `/dev/vda` فرض شده است. `lsblk` حرف آخر را می‌زند.

## مفهوم اصلی

LVM به شما اجازه می‌دهد حجم را بدون جابه‌جا کردن جدول پارتیشن مهمان، بزرگ کنید، به دیسک تازه منتقل کنید، یا یک snapshot برای پشتیبان کوتاه بگیرید. snapshot فضای کپی-هنگام-نوشتن است. اگر پر شود، snapshot از بین می‌رود و حجم اصلی سالم می‌ماند. snapshot جای پشتیبان خارج از میزبان را نمی‌گیرد.

RAID نرم با mdadm داده را بین چند دیسک بلوکی تکرار یا پخش می‌کند، بدون کنترلر سخت اختصاصی. RAID ۱ آینه است: دو دیسک، تحمل یک خرابی، ظرفیت برابر یکی از آن‌ها. RAID ۰ سرعت و ظرفیت جمع است و با اولین خرابی همهٔ داده می‌رود؛ در این آزمایشگاه ساخته نمی‌شود. RAID جایگزین پشتیبان نیست. حذف تصادفی فایل روی هر دو دیسک آینه هست.

LUKS لایهٔ رمز روی دستگاه بلوکی است. تا وقتی با گذرواژه یا کلید باز نشود، دستگاه mapper وجود ندارد و فایل‌سیستم دیده نمی‌شود. `luksOpen` داده را پاک نمی‌کند. `luksFormat` پاک می‌کند و سرآیند رمز را از نو می‌نویسد. این دو فعل را در تیکت و در انگشت اشتباه نگیرید.

## چرا استفاده می‌شود؟

پر شدن `/var` روی حجم LVM، اگر در گروه فضای خالی باشد، بدون برگرداندن ماشین از پشتیبان حل می‌شود: گسترش LV و سپس گسترش فایل‌سیستم. این تفاوت سرور ۲۰۱ با تمرین ۱۰۱ است.

دیسک تکی بدون هشدار می‌میرد. RAID ۱ زمان می‌خرد تا دیسک جایگزین همگام شود. اگر کسی خرابی را در `/proc/mdstat` نبیند، دیسک دوم هم که مرد آرایه تمام است. پایش بخشی از ساخت RAID است، نه کار اضافه.

رمز تمام‌دیسک برای لپ‌تاپ دزدیده‌شده معنی دارد. برای سرور اتاق، تا وقتی کلید بوت حل نشده باشد، فقط یک reboot دور از اپراتور ماشین را بالا‌نیامدنی می‌کند. اینجا LUKS را روی یک حجم دادهٔ جدا تمرین می‌کنیم، نه روی ریشه.

## Architecture

```text
دیسک فیزیکی sdb, sdc
    │
    ├─ mdadm ── /dev/md0     RAID 1
    │              │
    │              ▼
    └─ یا مستقیم ── PV ── VG vgdata ── LV lvbackup ── ext4 ── /srv/backup
                                    └── LV lvsecret ── LUKS ── mapper/secure-data

وضعیت زنده
    /proc/mdstat
    pvs vgs lvs
    lsblk -f
    dmsetup ls
```

ترتیب مرسوم تولید برای دادهٔ مهم: دیسک‌ها زیر RAID، RAID به‌عنوان PV، سپس LV. روی تمرین می‌توانید RAID و LVM را جدا بسازید تا هر هدف آزمون روشن بماند. روی یک دیسک هر دو را روی هم نگذارید و اسمش را تحمل خرابی نگذارید.

فایل پیکربندی آرایه `/etc/mdadm/mdadm.conf` است. بدون آن، بوت بعدی ممکن است آرایه را با نام دیگری جمع کند یا اصلاً نیاورد، مگر initramfs خودش اسکن کند. بعد از تغییر، initramfs را بازسازی کنید.

## Installation

```bash
sudo apt update
sudo apt install lvm2 mdadm cryptsetup
```

`mdadm` هنگام نصب گاهی می‌پرسد آرایه را در بوت استارت کند. جواب بله برای سروری که ریشه روی RAID است معنی دارد. برای آزمایشگاه که ریشه روی `vda` است، روشن بودن سرویس `mdadm` اشکالی ندارد به شرطی که دیسک سیستم را وارد آرایه نکنید.

```bash
systemctl is-enabled mdmonitor 2>/dev/null || systemctl is-enabled mdadm 2>/dev/null || true
which mdadm cryptsetup lvs
```

## Configuration

فضای خالی گروه را ببینید. اگر صفحهٔ ۱۰۱ را انجام داده‌اید، `vgdata` هست. اگر نیست، یک PV فقط روی دیسک خالی بسازید و این بخش گسترش را رد کنید تا دیسک داشته باشید.

```bash
sudo vgs
sudo lvs -o lv_name,vg_name,lv_size,data_percent,lv_attr
```

گسترش حجم و فایل‌سیستم ext4 در حال سوار. `lvextend` با `-r` فایل‌سیستم را هم بزرگ می‌کند اگر ابزارش باشد.

```bash
findmnt -no FSTYPE /srv/backup
sudo lvextend -L +2G -r /dev/vgdata/lvbackup
df -hT /srv/backup
```

اگر `-r` نبود: برای ext4 دستور `sudo resize2fs /dev/vgdata/lvbackup` بعد از گسترش LV، در حالت سوار هم برای بزرگ کردن مجاز است. برای XFS به‌جای resize2fs از `sudo xfs_growfs /srv/backup` استفاده کنید و مسیر سوارشده را بدهید نه دستگاه را. XFS را با این ابزارها کوچک نمی‌کنند.

snapshot کوتاه برای یک کپی سازگار. اندازه را دست‌کم به اندازهٔ تغییراتی که حین پشتیبان می‌نویسید بگیرید، نه به اندازهٔ کل حجم.

```bash
sudo lvcreate -L 1G -s -n lvbackup-snap /dev/vgdata/lvbackup
sudo lvs vgdata
sudo mkdir -p /mnt/snap
sudo mount -o ro /dev/vgdata/lvbackup-snap /mnt/snap
```

بعد از تمام شدن کپی:

```bash
sudo umount /mnt/snap
sudo lvremove -y /dev/vgdata/lvbackup-snap
```

ماندن snapshot فراموش‌شده گروه را پر می‌کند و سپس خود snapshot می‌میرد.

RAID ۱ روی دو دیسک خالی. این دستور جدول و دادهٔ `sdb` و `sdc` را از بین می‌برد. اگر این دیسک‌ها همان LVM تمرین هستند، RAID را روی آن‌ها نسازید. دو دیسک دیگر انتخاب کنید یا LVM را عمداً جمع کنید. برای آزمایشگاه تازه:

```bash
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc
cat /proc/mdstat
sudo mdadm --detail /dev/md0
```

همگام‌سازی اولیه طول می‌کشد. تا وقتی `/proc/mdstat` به `[UU]` نرسیده، خرابی تمرینی نسازید. ماندگار کردن:

```bash
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
if command -v dracut >/dev/null 2>&1; then
  sudo dracut -f --kver "$(uname -r)"
else
  sudo update-initramfs -u
fi
```

فایل conf را دو بار الحاق نکنید. قبلش `grep md0 /etc/mdadm/mdadm.conf` را ببینید.

فایل‌سیستم روی آرایه، مثل دیسک معمولی است: `sudo mkfs.ext4 /dev/md0` فقط وقتی که عمداً دادهٔ قبلی md0 را نمی‌خواهید.

## Production Example

دیسک `/dev/sdb` در آرایه خراب شده و پایش فقط ایمیل نفرستاده، چون کسی `mdadm --detail` را در شیفت نگاه نمی‌کند. علامت در سیستم:

```text
md0 : active raid1 sdc[1] sdb[0](F)
      20954112 blocks super 1.2 [2/1] [_U]
```

`[2/1]` یعنی از دو دستگاه یکی سالم است. `(F)` یعنی failed. داده هنوز روی `sdc` است. دیسک را خارج کنید و جایگزین را، بعد از دیدن `lsblk`، اضافه کنید. نام `/dev/sdd` را با دیسک نو عوض کنید.

```bash
sudo mdadm --manage /dev/md0 --fail /dev/sdb
sudo mdadm --manage /dev/md0 --remove /dev/sdb
sudo mdadm --manage /dev/md0 --add /dev/sdd
watch -n 2 cat /proc/mdstat
```

`watch` را با Ctrl-C تمام کنید. اگر `--add` گفت دستگاه کوچک‌تر است، دیسک جایگزین از عضو سالم کوچک‌تر است و آرایه قبولش نمی‌کند. دیسک بزرگ‌تر اشکالی ندارد؛ ظرفیت آرایه را دیسک کوچک‌تر اولیه تعیین کرده است.

LUKS روی یک دیسک جدا که فایل‌سیستم تولید روش نیست. `luksFormat` مخرب است.

:::danger قالب کردن LUKS
`cryptsetup luksFormat` سرآیند دستگاه را عوض می‌کند و دادهٔ قبلی آن دستگاه دیگر با کلید قبلی خوانده نمی‌شود. دستگاه را دو بار از `lsblk` بخوانید. این دستور را روی `vda` یا روی `md0` دارای داده نزنید. گذرواژه را در تاریخچهٔ پوسته ننویسید؛ خود ابزار می‌پرسد.
:::

```bash
sudo cryptsetup luksFormat /dev/sdd
sudo cryptsetup luksOpen /dev/sdd secure-data
sudo mkfs.ext4 /dev/mapper/secure-data
sudo mkdir -p /srv/secure
sudo mount /dev/mapper/secure-data /srv/secure
```

بستن، بعد از umount:

```bash
sudo umount /srv/secure
sudo cryptsetup luksClose secure-data
```

باز کردن دوباره فقط `luksOpen` است و گذرواژه را می‌پرسد. بدون گذرواژه یا کلید ثبت‌شده در slot، داده تمام است. نسخهٔ گذرواژه را در مدیر رمز تیم بگذارید، نه در فایل کنار دیسک و نه در این دانشنامه.

برای سوار شدن در بوت، `/etc/crypttab` یک خط دارد و fstab به `/dev/mapper/secure-data` اشاره می‌کند. روی سرور بدون حضور انسان، بوت منتظر گذرواژه می‌ماند. برای حجم دادهٔ غیرریشه این یعنی سرویس بالا می‌آید و این مسیر نه، مگر کلید فایل با مجوز ۶۰۰ داشته باشید. کلید فایل خودش راز است. ریشهٔ رمزشدهٔ بدون نظارت، طراحی جدا می‌خواهد و این صفحه آن طراحی را انجام نمی‌دهد.

نمونهٔ خط crypttab، بدون فعال کردنش روی تولید تا وقتی کلید را ندارید:

```text
secure-data UUID=PUT-LUKS-UUID none luks
```

`none` یعنی گذرواژه پرسیده شود. UUID را `blkid` روی خود دستگاه قفل، نه روی mapper، می‌دهد.

## Security Notes

آرایهٔ تخریب‌شده را با `--create` دوباره نسازید به امید برگشتن داده. `--assemble` برای جمع کردن عضوهای موجود است. ساختن از نو فراداده را عوض می‌کند.

```bash
sudo mdadm --assemble /dev/md0 /dev/sdb /dev/sdc
```

snapshot را روی شبکه‌ای که نسخهٔ فقط‌خواندنی لازم دارد به صورت خواندنی-نوشتنی سوار نکنید. فراموش کردنش یعنی دو نسخه واگرا.

گذرواژهٔ LUKS را در متغیر پوسته و در واحد systemd به صورت متن ساده نگذارید. `cryptsetup` را با لوله از `echo` تغذیه نکنید؛ آن خط در `ps` دیده می‌شود.

مجوز `/srv/secure` بعد از mount باید محدود باشد. نقطهٔ سوار خالی را قبل از mount با `chmod 700` ببندید تا وقتی حجم باز نیست، کسی داخل دایرکتوری خالی فایل جا نگذارد و بعد mount آن را پنهان کند.

## Troubleshooting

علامت: `lvextend` می‌گوید فضای گروه کم است. `vgs` ستون آزاد را نشان می‌دهد. یا LV را کمتر بزرگ کنید یا PV تازه از دیسک جدید به همان VG اضافه کنید: `sudo vgextend vgdata /dev/sdX1`. دیسک را اول با `pvcreate` آماده کنید و مطمئن شوید مال آرایه یا سوارشده نیست.

علامت: بعد از گسترش LV، `df` هنوز اندازهٔ کهنه را نشان می‌دهد. فایل‌سیستم بزرگ نشده. ext4 با `resize2fs`، XFS با `xfs_growfs`. LVM فقط دستگاه بلوکی را بزرگ کرده است.

علامت: `/proc/mdstat` آرایه را `inactive` نشان می‌دهد. `sudo mdadm --detail /dev/md0` و `dmesg` را بخوانید. اغلب یک عضو را زودتر `--create` کرده‌اید یا conf خراب دو تعریف دارد. تا وقتی داده مهم است، `--create` نزنید.

علامت: `luksOpen` می‌گوید دستگاه LUKS نیست. یا روی دستگاه اشتباه هستید، یا `luksFormat` نشده، یا سرآیند آسیب دیده. `sudo cryptsetup luksDump /dev/sdd` سرآیند را بدون باز کردن نشان می‌دهد. اگر dump هم شکست خورد، آن دستگاه نسخهٔ LUKS این تمرین نیست.

علامت: بوت منتظر رمز می‌ماند و کنسول دور است. این نتیجهٔ crypttab روی دستگاهی است که کلید ندارد. از کنسول وارد شوید یا خط crypttab را از مدیا زنده بردارید. پیشگیری‌اش این است که ریشه را در این تمرین رمز نکنید.

## Best Practices

- RAID و LVM را جایگزین بکاپ خارج از میزبان نکنید. بکاپ در [بکاپ سرور](/docs/10-security/backup) است.
- snapshot را کوتاه‌عمر نگه دارید و اندازه‌اش را از روی نرخ نوشتن بگیرید.
- قبل از `mdadm --create` و قبل از `luksFormat`، `lsblk` را در تیکت بچسبانید.
- وضعیت آرایه را پایش کنید. `mdadm --detail` یا نامهٔ `mdmonitor`. آرایهٔ degraded هفته‌ها سالم به نظر می‌رسد تا دیسک دوم بمیرد.
- XFS و ext4 را با ابزار خودشان بزرگ کنید. دستور را از روی نوع `findmnt` انتخاب کنید نه از روی عادت.
- LUKS ریشه را بدون برنامهٔ کلید و کنسول تمرین نکنید.

## تمرین

سناریو: حجم `/srv/backup` روی `vgdata` پر شده و `vgs` چهار گیگ آزاد نشان می‌دهد. فایل‌سیستم ext4 است و سوار است. همزمان در لاگ دیروز یک دیسک RAID علامت failed داشته و کسی remove نکرده.

بخش اجباری اگر محیط تمرین را ساخته‌اید: دو گیگ به `lvbackup` اضافه کنید و با `df -h` ثابت کنید فایل‌سیستم هم بزرگ شده است. اگر محیط را نساخته‌اید، فقط سؤال‌ها را از روی این صفحه جواب دهید و دستور مخرب نزنید.

```bash
sudo vgs vgdata
findmnt -no SOURCE,FSTYPE,SIZE /srv/backup
cat /proc/mdstat 2>/dev/null || echo 'no-md'
```

سؤال‌ها:

1. snapshot پر شود چه می‌میرد، حجم اصلی یا snapshot؟
2. `[2/1] [_U]` در mdstat یعنی چه؟
3. کدام دستور LUKS داده را از بین می‌برد و کدام فقط باز می‌کند؟

## پاسخ تمرین

اگر فضای آزاد واقعاً هست:

```bash
sudo lvextend -L +2G -r /dev/vgdata/lvbackup
df -hT /srv/backup
```

ستون اندازه باید حدود دو گیگ بیشتر از `findmnt` قبلی باشد. اگر `-r` خطا داد و نوع ext4 بود، `sudo resize2fs /dev/vgdata/lvbackup` را جدا بزنید و دوباره `df` بگیرید. اگر `vgs` فضای آزاد نداشت، گسترش نکنید و همان را به‌عنوان مانع در یادداشت بنویسید.

برای دیسک failed، تا دیسک جایگزین را با مدل و اندازه ندیده‌اید `--add` نزنید. fail و remove فقط وقتی دستگاه همان عضوی است که mdstat گفته، نه وقتی اسم `sdb` در این صفحه آمده.

1. snapshot از بین می‌رود یا نامعتبر می‌شود. حجم اصلی سر جایش می‌ماند. پشتیبان آن شب را از دست داده‌اید.
2. آرایه دو عضوه است و فقط یکی سالم است. `_` عضو خراب یا غایب است و `U` عضو سالم. داده هنوز روی عضو سالم است و شما در حالت degraded کار می‌کنید.
3. `cryptsetup luksFormat` مخرب است و سرآیند را از نو می‌نویسد. `cryptsetup luksOpen` دستگاه mapper را می‌سازد و داده را پاک نمی‌کند. بستن با `luksClose` است.
