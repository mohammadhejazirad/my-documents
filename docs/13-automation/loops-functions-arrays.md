# حلقه، تابع و آرایه

## مقدمه

بکاپ بیش از یک مبدأ دارد. سلامت بیش از یک سرویس را نگاه می‌کند. استقرار بیش از یک نسخهٔ قدیمی را از روی دیسک برمی‌دارد. هر سه یعنی حلقه. حلقه‌ای که نام فایل را با فاصله یا با newline بشکند، همان شبی است که فایل اشتباه را پاک می‌کند.

این صفحه سه ابزار Bash را با همان محدودیتی که در تولید لازم است می‌گوید: `for`،‏ `while`، تابع با متغیر محلی، و آرایه. مثال غلط `ls` را هم کامل نشان می‌دهد تا فقط به صورت ضرب‌المثل نماند. تمرین روی `app-1` و مسیر `/opt/apps` است. پاک کردن واقعی نسخهٔ قدیمی مال اسکریپت استقرار است؛ اینجا فقط می‌شماریم و چاپ می‌کنیم.

شکل گسترش آرایه آکولاد دارد و فقط داخل بلوک کد آمده است.

## مفهوم اصلی

### for

`for` روی یک فهرست از قبل آماده می‌گردد. فهرست می‌تواند چند کلمه، یک glob، یا عضوهای یک آرایه باشد. بدنه با `do` شروع می‌شود و با `done` تمام می‌شود.

```bash
for unit in nginx ssh; do
  printf 'check %s\n' "${unit}"
done
```

Glob را پوسته قبل از ورود به حلقه گسترش می‌دهد. اگر هیچ فایلی نخورد، پیش‌فرض Bash خود الگو را به‌عنوان یک کلمه می‌دهد و حلقه یک دور با نامی که وجود ندارد می‌چرخد. `shopt -s nullglob` الگو را به فهرست خالی تبدیل می‌کند. `failglob` به‌جایش خطا می‌دهد. در اسکریپت پاک‌سازی، خالی بودن نتیجهٔ طبیعی است و `nullglob` مناسب است. در اسکریپتی که نبودن فایل یعنی حادثه، `failglob` یا آزمون جدا بهتر است.

```bash
shopt -s nullglob
for archive in /var/backups/files/*.tar.gz; do
  printf '%s\n' "${archive}"
done
shopt -u nullglob
```

`nullglob` را بعد از حلقه خاموش کنید تا بقیهٔ اسکریپت یک الگوی بی‌ربط را بی‌صدا حذف نکند.

شکل شمارنده برای عدد است، نه برای فایل:

```bash
for (( i = 0; i < 3; i++ )); do
  printf 'i=%s\n' "${i}"
done
```

این شکل زیر `set -e` وقتی شرط وسط نادرست شود حلقه را تمام می‌کند و اسکریپت را نمی‌کشد. از آن برای ایندکس آرایه استفاده می‌کنیم، نه برای راه رفتن روی نام فایل.

`break` از حلقه بیرون می‌آید. `continue` دور بعدی را شروع می‌کند. هر دو فقط مال همین حلقهٔ نزدیک‌اند مگر شماره بدهید، و شماره دادن خواندن را سخت می‌کند. اگر به `break 2` نیاز پیدا کردید، بدنه را تابع کنید.

### while و زیرپوسته

`while` تا وقتی شرط موفق است تکرار می‌کند. خواندن خط به خط این شکل است:

```bash
while IFS= read -r line; do
  printf '%s\n' "${line}"
done < /etc/hostname
```

`IFS=` خالی یعنی فاصلهٔ اول و آخر خط حفظ شود. `read -r` بک‌اسلش را خاص نکند. بدون این دو، نام فایل و خط لاگ آرام خراب می‌شوند.

اگر به‌جای هدایت فایل، خروجی را با لوله به `while` بدهید، Bash حلقه را در زیرپوسته اجرا می‌کند. متغیری که داخل حلقه عوض شده بعد از `done` به مقدار قبلی برمی‌گردد. این باگ مورد علاقهٔ اسکریپت‌هایی است که «می‌شمارند» و ته کار صفر چاپ می‌کنند.

```bash
count=0
printf '%s\n' a b | while IFS= read -r line; do
  count=$((count + 1))
done
printf 'count_after_pipe=%s\n' "${count}"
```

انتظار غلط این است که عدد ۲ بماند. روی Bash این دانشنامه مقدار بعد از لوله ۰ است. درمان، هدایت ورودی یا جایگزینی فرایند است، نه `set +e` و نه فایل موقت بی‌دلیل:

```bash
count=0
while IFS= read -r line; do
  count=$((count + 1))
done < <(printf '%s\n' a b)
printf 'count_after_redirect=%s\n' "${count}"
```

برای نام فایلی که خود newline دارد، خط به خط کافی نیست. `find` با جداکنندهٔ تهی و `read -d ''` همان قرارداد اسکریپت‌های این فصل است. نمونهٔ کامل پایین‌تر، کنار توضیح `ls`، آمده است.

`until` برعکس `while` است و در این فصل لازم نمی‌شود. شرط را مثبت بنویسید تا خواننده نفی مضاعف حل نکند.

### تابع، متغیر محلی، مقدار بازگشت

تابع یک نام است برای چند دستور. محیط و متغیرهای سراسری را با فراخواننده شریک است مگر `local` بگویید. آرگومان تابع، آرگومان موقعیتی خود تابع است و آرگومان اسکریپت را موقتاً سایه می‌زند.

```bash
need_dir() {
  local dir="$1"
  [[ -n "${dir}" ]] || return 2
  [[ -d "${dir}" ]] || return 1
  return 0
}
```

`local` را در همان تابع و قبل از استفاده بنویسید. متغیر بدون `local` از تابع نشت می‌کند و حلقهٔ بعدی را آلوده می‌کند. به‌خصوص نام‌های عمومی مثل `i` و `f` و `rc`.

مقدار بازگشت تابع وضعیت خروج است، یعنی ۰ تا ۲۵۵، نه یک رشته. `return 0` موفقیت است. `return` بدون عدد، وضعیت آخرین دستور داخل تابع است. برای پس دادن رشته، `printf` کنید و در فراخواننده بگیرند:

```bash
short_host() {
  local raw
  raw="$(hostname -s)"
  printf '%s\n' "${raw}"
}
host="$(short_host)"
```

انتساب و `local` را در یک دستور قاطی نکنید. این شکل شکست دستور داخل جایگزینی را قایم می‌کند و `set -e` دیگر محافظ نیست:

```bash
bad_local() {
  local raw="$(false)"
  printf 'still here raw=%s\n' "${raw}"
}
```

روی Bash 5.3 این آزمایشگاه، تابع بالا پیام `still here` را چاپ می‌کند و وضعیت کلش موفق است، در حالی که `false` شکست خورده است. شکل درست جدا کردن است. شکست `false` آن‌وقت اسکریپت را متوقف می‌کند:

```bash
good_local() {
  local raw
  raw="$(false)"
  printf 'still here\n'
}
```

رشته را با `return` برنگردانید. `return` فقط عدد کوچک می‌پذیرد و عدد بزرگ‌تر از ۲۵۵ برش می‌خورد. مسیر فایل را echo منطقی کنید، یعنی `printf`.

خروجی تابع را اگر مسیر است نقل‌قول کنید وقتی می‌گیریدش: `dir="$(need_something)"`. خود تابع نباید پیام لاگ را با دادهٔ برگشتی قاطی کند. لاگ برود روی خطای استاندارد یا فایل لاگ، داده برود روی خروجی استاندارد. اگر هر دو روی خروجی استاندارد باشند، فراخواننده پیام را جزو مسیر حساب می‌کند.

تابع را قبل از اولین فراخوانی تعریف کنید. Bash اجازه می‌دهد تابع پایین فایل باشد فقط اگر اجرای واقعی‌اش بعد از خواندن کل فایل باشد. تعریف را بالای `main` بگذارید و آخر فایل فقط `main "$@"` باشد تا ترتیب خواندن با ترتیب اجرا قاطی نشود. اسکریپت‌های این فصل همین کار را می‌کنند.

### آرایه

فهرست سرویس‌ها و فهرست مبدأهای بکاپ کلمهٔ تنها نیستند. رشتهٔ جدا شده با فاصله هم نیستند، چون مسیر فاصله‌دار را می‌شکند. آرایهٔ اندیسی Bash هر عضو را جدا نگه می‌دارد.

```bash
sources=(/opt/apps /etc)
sources+=("/var/backups/my files")
printf '%s\n' "${#sources[@]}"
printf '%s\n' "${sources[@]}"
```

خط اول تعداد عضو است. خط دوم هر عضو را جداگانه به `printf` می‌دهد، پس فاصله داخل نام حفظ می‌شود. گسترش بدون نقل‌قول، یا شکلی که همه را در یک کلمه می‌چسباند، همان اشکال نقل‌قول صفحهٔ قبل است. در حلقه فقط شکل نقل‌قول‌شدهٔ «همهٔ عضوهای جدا» را به کار ببرید، همان که در بلوک زیر است:

```bash
for src in "${sources[@]}"; do
  if [[ ! -d "${src}" ]]; then
    printf 'missing %s\n' "${src}" >&2
    exit 1
  fi
done
```

عضو تهی داخل آرایه مجاز است و با این حلقه یک دور با رشتهٔ خالی می‌سازد. بالای اسکریپت چنین عضوی نگذارید. افزودن با `+=` یک عضو جدید می‌سازد. انتساب عادی `sources="/opt/apps"` آرایه را خراب می‌کند و به رشته تبدیل می‌کند.

آرایهٔ انجمنی (`declare -A`) برای نگاشت نام به مسیر به‌درد می‌خورد ولی اسکریپت‌های این فصل به آن نیاز ندارند. فهرست مرتب سرویس و مبدأ با آرایهٔ معمولی روشن‌تر است. اگر روزی نگاشت خواستید، `declare -A` را محلی در تابع نگه دارید تا به پوستهٔ فراخواننده نشت نکند.

کپی آرایه عضو‌به‌عضو است، نه با انتساب رشته:

```bash
copy=("${sources[@]}")
```

### چرا حلقه روی ls غلط است

`ls` خروجی را برای چشم انسان می‌چیند. قرارداد پایداری برای ماشین ندارد. این حلقه سه بار می‌شکند:

```bash
# Wrong. Do not ship this.
for f in $(ls /opt/apps); do
  printf 'got [%s]\n' "${f}"
done
```

اول، جایگزینی دستور، newline را به فاصله تبدیل می‌کند و بعد کلمه‌ها را می‌شکند. پوشهٔ `my app` دو دور حلقه می‌شود: `my` و `app`. دوم، اگر نام فایل نویسهٔ glob داشته باشد، بعد از شکستن دوباره گسترش می‌یابد. سوم، `ls` ممکن است alias شده باشد و ستون رنگی و پسوند نشانگر نوع فایل به نام بچسباند. خطاهای `ls` هم وارد فهرست می‌شوند اگر کسی stderr را قاطی کرده باشد.

جای درست برای یک پوشهٔ کم‌عمق، glob با `nullglob` است. جای درست برای درخت، `find` با جداکنندهٔ تهی است تا newline داخل نام هم عضو را نشکند:

```bash
while IFS= read -r -d '' path; do
  printf 'got [%s]\n' "${path}"
done < <(find /opt/apps -mindepth 1 -maxdepth 1 -print0 | sort -z)
```

`sort -z` رکورد تهی را می‌فهمد و مال GNU است. Ubuntu و Debian همین را دارند. خروجی را به `while` لوله نکنید اگر بعد از حلقه به متغیر نیاز دارید؛ همان مشکل زیرپوسته برمی‌گردد. هدایت از جایگزینی فرایند، حلقه را در پوستهٔ فعلی نگه می‌دارد.

`ls` را برای نگاه انسانی در ترمینال نگه دارید. داخل اسکریپت تولید نه برای فهرست، نه برای شمردن، نه برای فهمیدن «خالی بودن» پوشه.

## چرا استفاده می‌شود؟

نگهداری هفت نسخه یعنی فهرست آرشیوها، مرتب‌سازی بر اساس زمان، و حذف از سر قدیمی. اگر این فهرست با شکستن کلمه ساخته شود، آرشیوی که در نامش خط تیره یا نقطه است معمولاً سالم می‌ماند و شما گول می‌خورید که روش درست است. روزی که نام میزبان یا مسیر فاصله داشته باشد، `rm` آرگومان اضافه می‌گیرد. آزمایشگاه نام‌ها را ساده نگه داشته تا مثال‌ها خوانا باشند، نه تا اسکریپت حق داشته باشد نام را ناامن فرض کند.

تابع هم برای این است که قفل و لاگ و آزمون فایل در هر اسکریپت تکرار شود بدون اینکه یک فایل مشترک اجباری باشد. هر اسکریپت این فصل خودش کامل است. تابع‌ها داخل همان فایل‌اند تا کپی به سرور یک فایل باشد، نه یک کتابخانه که کسی یادش برود.

## Architecture

```text
فهرست امن
  ├── آرایهٔ نوشته‌شده در خود اسکریپت     مبدأ بکاپ، نام سرویس
  ├── glob با nullglob                   یک پوشه، نام بدون newline
  └── find -print0 | sort -z            درخت یا نام دلخواه

        │
        ▼
for یا while در پوستهٔ فعلی، نه پشت لوله
        │
        ▼
تابع با local
  ├── return برای وضعیت
  └── printf برای رشته
```

زیرپوسته فقط جایی ساخته می‌شود که عمداً اثر محیط را نمی‌خواهیم، مثل یک `cd` موقت برای `npm` در اسکریپت استقرار. پرانتز یک زیرپوسته می‌سازد. آکولاد بلوک در همان پوسته است و در اسکریپت‌ها فقط جایی آمده که وضعیت لوله را همان‌جا بررسی می‌کنیم. بیرون از فنس کد، آن نحو را در جمله تکرار نمی‌کنیم.

## Installation

ابزار اضافه نیست. `find` و `sort` از بسته‌های پایه می‌آیند. برای تمرین، یک درخت کوچک با نام فاصله‌دار بسازید تا حلقهٔ غلط را ببینید بدون اینکه به `/opt` دست بزنید.

```bash
demo="$(mktemp -d)"
mkdir -p "${demo}/my app" "${demo}/plain"
printf '%s\n' demo > "${demo}/my app/note.txt"
printf 'demo dir %s\n' "${demo}"
```

پوشه را ته کار پاک کنید. `mktemp` حالت را محدود می‌سازد. از `/tmp/demo` ثابت استفاده نکنید؛ نام قابل حدس در `/tmp` محل شرط‌بندی روی symlink است.

اگر `/opt/apps/app/releases` از صفحهٔ استقرار مانده، همان درخت واقعی را فقط بخوانید. نوشتن و حذف مال این صفحه نیست.

## Configuration

`nullglob` و `failglob` را سراسری در `~/.bashrc` روشن نکنید. رفتار glob تعاملی را عوض می‌کند و همکار فکر می‌کند الگو «غیب شده» است. فقط داخل اسکریپت و دور همان حلقه.

جداکنندهٔ `find` را در تیم یکی نگه دارید: `-print0` با `read -d ''`. مخلوط کردن `-print` و `read` یعنی برگشت به همان اشکال newline. اسکریپت پاک‌سازی و هرس نسخه هر دو تهی را استفاده می‌کنند.

عمق `find` را بنویسید. `-maxdepth 1` برای نسخهٔ استقرار و برای آرشیو بکاپ درست است. بدون آن، هرس وارد پوشهٔ یک انتشار می‌شود و فایل داخلی را با آرشیو اشتباه می‌گیرد.

## Production Example

اسکریپت زیر انتشارهای `/opt/apps/app/releases` را می‌شمارد، نام فاصله‌دار را یک عضو حساب می‌کند، و اگر پوشه نباشد وضعیت ۱ می‌دهد. چیزی حذف نمی‌کند. مقایسهٔ ذهنی با حلقهٔ `ls` همان بلوک بخش مفهوم است؛ اینجا شکل قابل اجراست.

```bash
#!/usr/bin/env bash
set -euo pipefail

export LC_ALL=C
export PATH="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"

RELEASES="/opt/apps/app/releases"

die() {
  printf '%s\n' "$*" >&2
  exit 1
}

list_releases() {
  local dir="$1"
  local count=0
  local path
  if [[ ! -d "${dir}" ]]; then
    die "missing releases dir: ${dir}"
  fi
  if [[ -L "${dir}" ]]; then
    die "refusing symlink releases dir: ${dir}"
  fi
  while IFS= read -r -d '' path; do
    count=$((count + 1))
    printf 'release=%s\n' "${path}"
  done < <(find "${dir}" -mindepth 1 -maxdepth 1 -type d -print0 | sort -z)
  printf 'count=%s\n' "${count}"
}

main() {
  list_releases "${RELEASES}"
  exit 0
}

main "$@"
```

نصب و اجرا با `deploy`. اگر پوشه هنوز ساخته نشده، خروج ۱ رفتار درست است نه یک استثنا که با `|| true` خاموشش کنید.

```bash
sudo install -d -o deploy -g deploy -m 0755 /opt/apps/app/releases
sudo install -d -o deploy -g deploy -m 0755 "/opt/apps/app/releases/v1.0.0" "/opt/apps/app/releases/v1.1.0"
sudo install -m 0750 -o root -g deploy /dev/null /usr/local/sbin/list-releases.sh
sudoedit /usr/local/sbin/list-releases.sh
bash -n /usr/local/sbin/list-releases.sh
sudo -u deploy /usr/local/sbin/list-releases.sh
```

باید دو خط `release=` ببینید و `count=2`. یک پوشهٔ آزمایشی با فاصله بسازید و دوباره بشمارید:

```bash
sudo -u deploy mkdir -p "/opt/apps/app/releases/bad name"
sudo -u deploy /usr/local/sbin/list-releases.sh
sudo -u deploy rmdir "/opt/apps/app/releases/bad name"
```

شمارش باید ۳ باشد و نام `bad name` در یک خط بماند. حلقهٔ غلط `ls` همان نام را دو تا نشان می‌داد.

برای دیدن نشت متغیر محلی، تابع `bad_local` را فقط در یک پوستهٔ تعاملی آزمایشی اجرا کنید، نه داخل این فایل. اگر پیام `still here` را دیدید، همان باگی است که بخش تابع گفت. اسکریپت تولید حق ندارد آن شکل را «چون کار می‌کند» نگه دارد.

## Security Notes

حلقهٔ حذف خطرناک‌ترین حلقهٔ سرور است. قبل از `rm` مسیر را با پیشوند ثابت مقایسه کنید: فقط زیر `/var/backups/files` یا فقط زیر `/opt/apps/app/releases`. مقایسه را روی نتیجهٔ `realpath` بگذارید اگر ورودی از بیرون آمده. اسکریپت پاک‌سازی لاگ این کار را می‌کند چون مسیر را آرگومان می‌گیرد. هرس بکاپ مسیر را از بیرون نمی‌گیرد و باز هم پیشوند را چک می‌کند، چون باگ فهرست‌گیری نباید به `rm` آزاد برسد.

`find` را با `-exec rm` روی مسیری که کاربر داده وصل نکنید مگر همان محدودهٔ `realpath` برقرار باشد. `-delete` عمل `find` است و اگر آزمون مسیر را اشتباه نوشته باشید سریع‌تر از حلقه خراب می‌کند. در این فصل حذف داخل حلقهٔ پوسته است تا هر مسیر قبل از حذف یک‌بار دیگر در لاگ بیاید.

تابع `die` را طوری ننویسید که آرگومانش را بدون `%s` به `printf` بدهد. متن مسیر ممکن است درصد داشته باشد. همهٔ چاپ‌های این صفحه فرمت ثابت دارند.

خروجی `list-releases` نام پوشه است، نه محتوا. اگر روزی داخل انتشار فایل محیطی هست، این اسکریپت آن را باز نمی‌کند. اسکریپت شمارش را به `root` در cron وصل نکنید؛ کار عملیاتی نیست و فقط تمرین است. بعد از تمرین می‌تواند بماند، به شرطی که چیزی پاک نکند.

## Troubleshooting

| نشانه | علت | کار |
| --- | --- | --- |
| شمارنده بعد از حلقه صفر است | `while` پشت لوله در زیرپوسته بوده | هدایت از فایل یا از جایگزینی فرایند |
| یک دور حلقه با خود الگوی `*.tar.gz` | پوشه خالی است و `nullglob` خاموش است | `shopt -s nullglob` دور همان حلقه |
| `bad name` دو عضو شده | شکستن کلمه، اغلب خروجی `ls` | glob یا `find -print0` |
| متغیر تابع در بیرون مقدار دارد | `local` فراموش شده | `local` در اول تابع |
| `local var=$(false)` ادامه پیدا می‌کند | وضعیت انتساب داخل `local` قایم می‌شود | دو خط جدا، بعد تکیه بر `set -e` |
| `return` مسیر را بریده | بازگشت فقط وضعیت است | `printf` و گرفتن در متغیر |
| `count` با `set -u` می‌میرد | داخل تابع مقدار اولیه نخورده و بیرون هم نیست | `local count=0` |
| حذف بیشتر از حد انتظار | `find` بدون `-maxdepth` | عمق را بنویسید و پیشوند مسیر را قبل از `rm` بسنجید |

اگر `find` را با `sudo` اجرا کنید و اسکریپت را بدون آن، مجموعهٔ فایل فرق می‌کند. تمرین و cron باید همان کاربر را داشته باشند. برای این اسکریپت کاربر `deploy` است، چون مالک `/opt/apps` است.

## Best Practices

- روی خروجی `ls` حلقه نزنید. برای چشم انسان `ls` بماند، برای اسکریپت نماند.
- لوله به `while read` ندهید اگر به متغیر بعد از حلقه نیاز دارید.
- `IFS= read -r` برای خط، و `read -d ''` برای رکورد تهی.
- `local` و انتساب دستور را در یک خط ننویسید.
- از تابع رشته برنگردانید. وضعیت با `return`، متن با `printf '%s\n'`.
- آرایه را با شکل نقل‌قول‌شدهٔ گسترش همهٔ عضوهای جدا پیمایش کنید. شکل چسباندن در یک کلمه را برای مسیر استفاده نکنید.
- قبل از هر `rm` در حلقه، مسیر را به یک ریشهٔ ثابت محدود کنید و نام حذف‌شده را لاگ کنید.
- تابع را داخل همان اسکریپت نگه دارید تا اجرا به فایل دوم وابسته نباشد.
