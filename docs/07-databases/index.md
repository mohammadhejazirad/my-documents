# نقشهٔ دیتابیس

## مقدمه

این فصل چهار موتور را برای همان آزمایشگاه بقیهٔ دانشنامه توضیح می‌دهد. سرور دیتابیس `db-1.example.internal` با آدرس `10.10.1.20` است. برنامه فقط از `app-1.example.internal` با آدرس `10.10.1.10` وصل می‌شود. میزبان Docker، اگر موتور را کانتینر کنید، `docker-1.example.internal` با آدرس `10.10.1.30` است. بکاپ زیر `/var/backups` می‌ماند. نام دیتابیس نمونه `app` و کاربر برنامه `app_user` است. رمز نمونه همیشه `change-me` است و قبل از هر چیز واقعی باید عوض شود.

صفحهٔ حاضر موتور را انتخاب می‌کند. نصب هر موتور صفحهٔ خودش را دارد و آن صفحه بدون این نقشه هم قابل اجراست. هر جا نمونهٔ Compose در فصل Docker هست، اینجا هم دستور را تکرار کرده‌ایم و فقط برای مدل شبکه و volume به آن فصل لینک داده‌ایم.

## مفهوم اصلی

موتور را از روی شکل داده و از روی کسی که در ساعت سه بامداد جوابگوست انتخاب کنید، نه از روی اسمی که در یک کنفرانس شنیده‌اید.

| معیار | MySQL 8.4 LTS | PostgreSQL 18 | MongoDB Community 8.0 | Redis 8 |
| --- | --- | --- | --- | --- |
| شکل داده | جدول و سطر | جدول، قید، و JSONB | سند | کلید و مقدار در حافظه |
| تراکنش | InnoDB، تراکنش محلی | تراکنش و قید قوی | چندسندی فقط بعد از replica set | روی یک نود، جایگزین دیتابیس ثبت نیست |
| بسته در Ubuntu 26.04 | `mysql-server` در universe | `postgresql` در main، کلاستر `18/main` | در مخزن Ubuntu نیست؛ `repo.mongodb.org` | `redis-server` در universe |
| پشتیبانی Canonical | جامعه (universe). MariaDB 11.8 در main محصول دیگری است | بستهٔ اصلی توزیع | ندارد؛ خود MongoDB | ندارد. Valkey 9 در main پروتکل Redis را حرف می‌زند |
| شنود در این فصل | `127.0.0.1` و در حالت جدا بودن سرورها فقط کارت `10.10.1.20` | `localhost` و فقط در صورت نیاز `10.10.1.20` | `127.0.0.1` و در صورت نیاز `10.10.1.20` | `127.0.0.1` |
| بکاپ روزمره | `mysqldump` و آزمون بازیابی | `pg_dump` و `pg_restore` | `mongodump` | فایل RDB و AOF، نه دامپ جدول |
| اشتباه رایج | روشن کردن `mysql_native_password` یا `bind` روی همهٔ کارت‌ها | کپی عدد `shared_buffers` از یک مقاله | سند منعطف به‌جای مدل رابطه‌ای، بدون احراز هویت | `allkeys-lru` روی تنها نسخهٔ سفارش‌ها |

MariaDB 11.8 که در کامپوننت main هست جایگزین دستورهای این فصل نیست. فصل MySQL فقط Oracle MySQL 8.4 است. Redis را هم با Valkey قاطی نمی‌کنیم: دستورها برای `redis-server` نوشته شده‌اند و مسیر پشتیبانی Canonical جدا، در همان صفحه، نصب `valkey-server` است.

## چرا استفاده می‌شود؟

برنامهٔ نمونه به یک محل ماندگار برای سفارش نیاز دارد و به یک محل سریع برای نشست، محدودیت نرخ، و کش. این دو کار یکی نیستند. سفارش اگر فقط داخل Redis باشد با سیاست اخراج حافظه یا با خاموشی بدون دیسک از بین می‌رود. سفارش اگر فقط داخل MongoDB باشد و replica set نداشته باشید، تراکنش چندسندی و change stream را ندارید. جدول رابطه‌ای را هم نباید بهزور به شکل سند درآورید فقط چون اسکیما هنوز نهایی نشده؛ PostgreSQL با JSONB همان تردید را تحمل می‌کند و قید را هم نگه می‌دارد.

انتخاب پیش‌فرض این دانشنامه برای دادهٔ سفارشی که اسکیما دارد PostgreSQL 18 است. اگر برنامه از قبل با MySQL نوشته شده، MySQL 8.4 LTS روی همین Ubuntu کافی است و لازم نیست مخزن Oracle را اضافه کنید. MongoDB را وقتی سند واقعاً شکل متغیر دارد و تیم هزینهٔ replica را قبول کرده. Redis یا Valkey را کنار یکی از این‌ها برای کش، نه به‌جای آن‌ها.

هر چهار موتور را روی `db-1` نصب نکنید. دیسک، RAM و پورت با هم دعوا می‌کنند و بکاپ نیمه‌کاره می‌ماند. یک موتور ثبت انتخاب کنید. اگر کش لازم است Redis را با سقف حافظه کنارش بگذارید.

## Architecture

```text
app-1  10.10.1.10
   │
   │  فقط اگر موتور روی db-1 نصب بسته‌ای است
   │  و فایروال فقط همین مبدأ را به پورت دیتابیس راه داده
   ▼
db-1   10.10.1.20
   ├── mysqld      3306    سوکت محلی برای ops
   ├── postgres    5432    سوکت محلی برای کاربر سیستم postgres
   ├── mongod      27017   فقط بعد از روشن کردن authorization
   └── redis       6379    پیش‌فرض فقط 127.0.0.1

docker-1  10.10.1.30
   └── کانتینر دیتابیس
         پورت منتشرشده فقط روی 127.0.0.1 میزبان
         برنامهٔ هم‌کامپوز با نام سرویس وصل می‌شود، نه با IP عمومی
```

مسیر بسته‌ای برای برنامهٔ روی `app-1` است: شنونده به `10.10.1.20` محدود است و کاربر دیتابیس فقط از `10.10.1.10` قبول می‌شود. مسیر Docker برای برنامه‌ای است که کنار همان Compose روی `docker-1` است. پورت `127.0.0.1` روی میزبان Docker یعنی `app-1` از شبکه به آن نمی‌رسد. این محدودیت عمدی است؛ برای باز کردنش این فصل را دور نزنید و موتور را روی `db-1` نصب کنید.

بکاپ منطقی هر موتور زیر `/var/backups` و در پوشهٔ همان موتور نوشته می‌شود: `mysql`، `postgresql` یا `mongodb`. Redis کش است و به‌جای دامپ جدول، فایل RDB و AOF دارد. بکاپ را روی همان دیسک داده، تنها نسخه حساب نکنید. کپی بیرون از سرور کار [بکاپ سرور](/docs/10-security/backup) است؛ اینجا خود دامپ و آزمون برگرداندن آن ساخته می‌شود.

## Installation

روی `db-1` قبل از نصب، نسخهٔ توزیع و حافظه را ببینید. عددهای تنظیم این فصل برای یک ماشین فرضی ۴ گیبیابایت نوشته شده‌اند و اگر `free -h` چیز دیگری گفت نباید کپی شوند.

```bash
lsb_release -ds
free -h
df -h / /var /var/lib
```

خروجی قابل قبول این محیط شبیه این است. شمارهٔ patch و حجم دقیق دیسک مال ماشین شماست.

```text
Ubuntu 26.04.1 LTS
               total        used        free
Mem:           3.8Gi       400Mi       3.2Gi
```

بستهٔ هر انتخاب:

| انتخاب | فرمان نصب | صفحه |
| --- | --- | --- |
| MySQL | `sudo apt install mysql-server` | [MySQL روی سرور](./mysql-server.md) |
| PostgreSQL | `sudo apt install postgresql` | [PostgreSQL روی سرور](./postgresql-server.md) |
| MongoDB | مخزن `resolute/mongodb-org/8.0` و بستهٔ `mongodb-org` | [MongoDB روی سرور](./mongodb-server.md) |
| Redis | `sudo apt install redis-server` | [Redis روی سرور](./redis-server.md) |
| Valkey به‌جای Redis | `sudo apt install valkey-server` | همان صفحهٔ Redis، زیربخش Canonical |

Docker Engine را اینجا نصب نمی‌کنیم. اگر روی `docker-1` نیست، اول [نصب Docker](/docs/05-docker/installation) و [مدل Compose](/docs/05-docker/compose) را انجام دهید. بعد یکی از صفحه‌های Docker همین فصل را اجرا کنید.

قبل از اینکه انتخاب را قطعی کنید، ببینید آرشیو همین ماشین چه نسخه‌ای پیشنهاد می‌کند. شمارهٔ patch را از این خروجی بردارید و در صفحهٔ موتور همان را ملاک بدانید.

```bash
apt-cache policy mysql-server postgresql postgresql-18 redis-server valkey-server
```

انتظار روی Ubuntu 26.04: `mysql-server` خط 8.4 از universe، `postgresql-18` از main، `redis-server` خط 8 از universe، `valkey-server` خط 9 از main. `mongodb-org` در این فهرست نیست چون هنوز منبعش اضافه نشده؛ آن را فقط اگر MongoDB را انتخاب کرده‌اید، با دستور صفحهٔ خودش ببینید.

قبل از نصب بررسی کنید پورت گرفته نشده باشد.

```bash
sudo ss -lptn 'sport = :3306 or sport = :5432 or sport = :27017 or sport = :6379'
```

اگر شنونده‌ای هست، موتور دوم را روی همان پورت نصب نکنید. MariaDB و MySQL هر دو پورت ۳۳۰۶ می‌خواهند و با هم روی یک میزبان در این فصل پشتیبانی نمی‌شوند.

## Configuration

تصمیم را در یک فایل متنی کنار سیستم تیکت بنویسید تا ماه بعد کسی موتور دوم را «برای احتیاط» کنارش نصب نکند. حداقل این چهار خط را پر کنید.

```text
engine: postgresql
host: db-1.example.internal
bind: 10.10.1.20
client: 10.10.1.10
database: app
user: app_user
backup_dir: /var/backups/postgresql
backup_test: restore into app_restore, compare counts, drop app_restore
```

رمز را در این فایل ننویسید. رمز در فایلی با مجوز `0600` روی خود سرور است، یا در مدیر رمز تیم. `change-me` فقط داخل مثال‌های همین فصل است تا دستور بدون یک رمز ساختگی قابل خواندن بماند.

اگر برنامه و دیتابیس روی یک میزبان‌اند، شنونده را روی localhost بگذارید و کاربر را به همان میزبان محدود کنید. باز کردن `10.10.1.0/24` وقتی فقط یک برنامه روی `10.10.1.10` دارید لازم نیست. خط فایروال و کاربر را برای همان یک آدرس بنویسید.

منطقهٔ زمانی سیستم `Asia/Tehran` است. خود موتور را UTC نگه دارید تا ساعت تابستانی و گزارش مالی به منطقهٔ سیاسی گره نخورد. تبدیل منطقه کار برنامه است.

## Production Example

فرض کنید سرویس سفارش از نو نوشته می‌شود، اسکیما مشخص است، گزارش SQL لازم است، و تیم Ubuntu 26.04 را بدون مخزن اضافه می‌خواهد. انتخاب PostgreSQL 18 روی `db-1` است. برنامه روی `app-1` با کاربر `app_user` فقط به دیتابیس `app` وصل می‌شود. کش سبد خرید، اگر واقعاً لازم شد، Redis روی همان `db-1` با `maxmemory` کوچک و سیاست `allkeys-lru` است و سفارش نهایی هرگز فقط آنجا نوشته نمی‌شود.

ترتیب اجرا:

1. [PostgreSQL روی سرور](./postgresql-server.md) را تا ساخت `app` و `app_user` جلو ببرید.
2. [بکاپ و کارایی PostgreSQL](./postgresql-backup-performance.md) را همان روز اجرا کنید. دامپ بدون یک بار `pg_restore` بکاپ نیست.
3. اگر کش اضافه شد، [Redis روی سرور](./redis-server.md) را بعد از دیتابیس نصب کنید و سقف حافظه‌اش را از RAM باقی‌مانده حساب کنید، نه از یک عدد آماده.
4. اگر استقرار با Compose است و برنامه کنار کانتینر دیتابیس نیست، به مسیر Docker این فصل نروید. پورت منتشرشده به `app-1` نمی‌رسد.

اگر کد موجود `mysqli` یا SQL مخصوص MySQL است و بازنویسی در این فصل نمی‌گنجد، به‌جای بند ۱ و ۲ صفحه‌های MySQL را اجرا کنید. بقیهٔ منطق شبکه همان است.

نشانه‌ای که انتخاب را تمام‌شده می‌کند این چهار مورد است، نه نصب بسته:

```bash
sudo ss -lptn 'sport = :5432'
sudo ufw status | head
sudo -u postgres psql -d app -c "SELECT count(*) FROM orders;"
sudo ls -l /var/backups/postgresql
```

`ss` باید `10.10.1.20:5432` را نشان دهد و `0.0.0.0:5432` را نه. UFW باید ۵۴۳۲ را فقط از `10.10.1.10` باز کرده باشد. شمارش سطر بعد از آزمون بازیابی در صفحهٔ کارایی با نسخهٔ `app_restore` یکی بوده و آن نسخه حذف شده است. اگر به‌جای PostgreSQL موتور دیگری را انتخاب کرده‌اید، پورت و کاربر سیستم عوض می‌شود ولی شکل آزمون همان است: شنوندهٔ محدود، یک کاربر برنامه، یک شمارش سطر، یک فایل بکاپ که یک‌بار برگشته.

نقشهٔ خواندن بقیهٔ فصل:

| اگر انتخاب شما این است | این صفحه‌ها را به ترتیب بخوانید |
| --- | --- |
| PostgreSQL روی `db-1` | [سرور](./postgresql-server.md) سپس [بکاپ و کارایی](./postgresql-backup-performance.md) |
| MySQL روی `db-1` | [سرور](./mysql-server.md) سپس [بکاپ](./mysql-backup-restore.md) |
| MongoDB روی `db-1` | [سرور](./mongodb-server.md) سپس [replica و بکاپ](./mongodb-replica-backup.md) |
| فقط کش | [Redis](./redis-server.md). Valkey را فقط اگر main اجباری است |
| برنامه داخل Compose روی `docker-1` | صفحهٔ Docker همان موتور. سرور بسته‌ای را هم‌زمان روی همان پورت نصب نکنید |

## Security Notes

- هیچ موتوری را روی `0.0.0.0` منتشر نکنید. کارت مشخص `10.10.1.20` به‌علاوهٔ localhost برای مدیریت، حداکثر چیزی است که این آزمایشگاه لازم دارد.
- کاربر برنامه روی MySQL میزبان `10.10.1.10` است، نه `%`. روی PostgreSQL خط `pg_hba` همان `/32` است. روی MongoDB محدودیت `clientSource` همان آدرس است. روی Redis تا وقتی فقط localhost است رمز جداگانه دارید و اگر شنود را باز کردید فایروال هنوز فقط `10.10.1.10` است.
- `mysql_native_password` را فعال نکنید. پلاگین برنامه `caching_sha2_password` است.
- Redis در universe است. اگر سیاست سازمان فقط بستهٔ main را می‌پذیرد، Valkey 9 را نصب کنید و پروتکل را همان فرض کنید، ولی دستور این فصل را با نام باینری Valkey تطبیق دهید.
- MongoDB بدون `authorization: enabled` یک سوکت باز بدون رمز است، حتی روی localhost، برای هر کاربر سیستم.
- فایل بکاپ دادهٔ واقعی است. مجوز دایرکتوری `0750` و فایل `0600`. آن را در گیت نگذارید.

دیوار آتش جزئیاتش در [UFW](/docs/10-security/ufw) است. اینجا فقط قانون همان پورت را می‌آوریم تا صفحه تنها هم اجرا شود.

## Troubleshooting

| نشانه | معنی محتمل | کجا بروید |
| --- | --- | --- |
| برنامه از `10.10.1.10` تایم‌اوت می‌گیرد | شنونده هنوز localhost است، یا UFW پورت را از آن مبدأ باز نکرده | صفحهٔ سرور همان موتور، بخش کانفیگ |
| `Access denied` با رمز درست | کاربر برای میزبان دیگری ساخته شده. در MySQL `localhost` و `127.0.0.1` و `10.10.1.10` سه حساب متفاوت‌اند | همان صفحه، ساخت کاربر |
| کانتینر سالم است ولی `app-1` وصل نمی‌شود | پورت Docker فقط روی `127.0.0.1` میزبان `docker-1` است | صفحهٔ Docker همان موتور |
| تراکنش MongoDB خطا می‌دهد | نود replica نیست | [Replica و بکاپ](./mongodb-replica-backup.md) |
| بعد از پر شدن حافظه کلید Redis نیست | `allkeys-lru` کار خودش را کرده | [Redis روی سرور](./redis-server.md) |
| دامپ هست و بازیابی امتحان نشده | هنوز بکاپ ندارید | صفحهٔ بکاپ همان موتور |

کندی عمومی را با [دیتابیس کند](/docs/14-troubleshooting/database-slow) ادامه دهید. پر شدن دیسک را با [دیسک پر](/docs/14-troubleshooting/disk-full). این صفحه جای تکرار آن سناریوها نیست.

## Best Practices

- یک موتور ثبت برای `app`. موتور دوم فقط با نقش جدا (کش) و با سقف منبع.
- عدد RAM و دیسک را از `free -h` و `df -h` همان میزبان بگیرید. مثال ۴ گیبیابایتی این فصل مجوز کپی به سرور ۶۴ گیبیابایتی یا VM یک گیبیابایتی نیست.
- کاربر اجرا `app_user` است و مالک اسکیما یا مدیر کل نیست، مگر صفحه‌ای خلافش را با دلیل نوشته باشد.
- هر بکاپ را حداقل یک‌بار در هفته به یک دیتابیس با نام `app_restore` برگردانید، تعداد سطر را مقایسه کنید، بعد `app_restore` را حذف کنید. مقایسه را در تیکت بنویسید.
- ساعت موتور UTC. ساعت سیستم `Asia/Tehran`.
- رمز نمونه را در تاریخچهٔ شل، در `git`، و در آرگومان قابل دیدن `ps` رها نکنید. روش هر موتور در صفحهٔ خودش آمده است.
- ترتیب خواندن اگر PostgreSQL را انتخاب کرده‌اید: همین صفحه، سرور، بکاپ و کارایی. Docker را فقط وقتی بخوانید که محل اجرا `docker-1` است.
