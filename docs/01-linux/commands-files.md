# دستورهای فایل و جستجو

## مقدمه

این صفحه مرجع دستورهایی است که درخت فایل را نشان می‌دهند یا عوض می‌کنند: `ls`، `cd`، `cp`، `mv`، `rm` و `find`. هر شش تا از `coreutils` و `findutils` روی Ubuntu Server 26.04 می‌آیند. نسخه را از بسته بخوانید:

```bash
ls --version | head -n 1
find --version | head -n 1
```

خطر این خانواده در فلگ (flag) کمیاب نیست. خطر در مسیر است. متغیر خالی، ستاره‌ای که پوسته قبل از دستور باز می‌کند، یا `find` که از `/` شروع شده، روی `app-1` سرویس را برمی‌دارد و روی `db-1` دایرکتوری داده را. ترتیب کار این است: اول نگاه (`ls` و `find` بدون حذف)، بعد کپی، بعد تغییر نام روی همان فایل‌سیستم، و حذف فقط بعد از دیدن مسیر.

آزمایشگاه ثابت است. برنامه روی `app-1.example.internal` با آدرس `10.10.1.10` زیر `/opt/apps/shop` است. کاربر سرویس `deploy` است و مدیر `ops`. بکاپ زیر `/var/backups` است. بیت‌های مجوز در [مجوز فایل](/docs/01-linux/permissions) است و نوع فایل‌سیستم در [فایل‌سیستم](/docs/01-linux/filesystems).

خروجی‌ها با locale انگلیسی‌اند. اگر تاریخ شمسی شد، دستور را با `LC_ALL=C` تکرار کنید. خروجی `ls` را در اسکریپت پارس نکنید. نام فایل می‌تواند فاصله داشته باشد.

## ls

### توضیح

`ls` فهرست را چاپ می‌کند و چیزی را عوض نمی‌کند. شکل کاری این دانشنامه `ls -la` است.

- `-l` قالب بلند است: نوع، مجوز، تعداد پیوند، مالک، گروه، اندازه به بایت، mtime، نام.
- `-a` نام‌های نقطه‌دار را هم نشان می‌دهد. بدون آن `.env` دیده نمی‌شود.
- `-h` اندازه را خوانا می‌کند. در تیکت هم `-la` را بگذارید هم در صورت نیاز `-lh` را.
- `-d` خود دایرکتوری یا خود پیوند را نشان می‌دهد، نه محتوا را. `ls -la` روی یک دایرکتوری داخلش را باز می‌کند.

| ستون | معنی |
| --- | --- |
| نوع و مجوز | ده نویسه. اولی نوع است، نه تای بعدی مجوز مالک و گروه و دیگران |
| پیوند | برای فایل معمولی معمولاً ۱. برای دایرکتوری حداقل ۲، به‌علاوهٔ یکی به‌ازای هر زیردایرکتوری |
| مالک و گروه | سرویس ما `deploy` است، نه `root` |
| اندازه | برای فایل، بایت محتوا. برای دایرکتوری، اندازهٔ خود فهرست است نه جمع محتوا. جمع کار `du` است |
| زمان | mtime |
| نام | اگر پیوند نمادین باشد هدف بعد از فلش می‌آید |

نویسهٔ اول: `-` فایل، `d` دایرکتوری، `l` پیوند نمادین، `b` دستگاه بلوکی، `c` دستگاه نویسه‌ای، `s` سوکت، `p` لوله. اگر به‌جای `x` حرف `s` دیدید، setuid یا setgid است. جزئیاتش در صفحهٔ مجوز است.

### مثال واقعی

```bash
LC_ALL=C ls -la /opt/apps/shop
LC_ALL=C ls -ld /opt/apps/shop/current
LC_ALL=C ls -la /opt/apps/shop/shared
```

```text
total 20
drwxr-xr-x 4 deploy deploy 4096 Sep 23 02:14 .
drwxr-xr-x 3 root   root   4096 Sep  1 09:00 ..
lrwxrwxrwx 1 deploy deploy   32 Sep 23 02:14 current -> releases/20260923-0210
drwxr-xr-x 5 deploy deploy 4096 Sep 23 02:10 releases
drwxr-x--- 2 deploy deploy 4096 Sep 23 02:12 shared
lrwxrwxrwx 1 deploy deploy 32 Sep 23 02:14 /opt/apps/shop/current -> releases/20260923-0210
total 12
drwxr-x--- 2 deploy deploy 4096 Sep 23 02:12 .
drwxr-xr-x 4 deploy deploy 4096 Sep 23 02:14 ..
-rw-r----- 1 deploy deploy  640 Sep 23 02:12 .env
```

بدون `-a` خط `.env` نیست. بدون `-d`، `ls` از روی پیوند `current` می‌رود داخل انتشار و شما فکر می‌کنید `current` خودش درخت جداست. برای یک فایل، ستون پایدار را از `stat` بگیرید نه از پارس `ls`:

```bash
stat -c '%U %G %a %s %y %n' /opt/apps/shop/shared/.env
```

```text
deploy deploy 640 640 2026-09-23 02:12:08.000000000 +0330 /opt/apps/shop/shared/.env
```

### کاربرد Production

شب حادثه روی `app-1` اول ببینید `current` به کدام انتشار اشاره می‌کند. اگر انتشار جدید کپی شده ولی پیوند هنوز قبلی است، استقرار نیمه‌کاره است. دوم، حالت `.env` باید مثل `640` و مالک `deploy` باشد. `644` یعنی رمز پایگاه برای هر کاربر محلی خواناست. اصلاح در صفحهٔ مجوز است. اینجا فقط واقعیت را برمی‌دارید.

روی `db-1` (`10.10.1.20`) داخل `/var/lib/postgresql/18/main` با `ls -la` گشت نزنید. خروجی بزرگ است و دیسک را بی‌جهت می‌خواند. آنجا [df و du](/docs/01-linux/commands-disk) مناسب‌ترند.

### وقتی خراب می‌شود

```text
ls: cannot open directory '/opt/apps/shop/shared': Permission denied
ls: cannot access '/opt/apps/shop/current': No such file or directory
```

اولی مجوز است، نه نبودن مسیر. `ops` اگر در گروه `deploy` نباشد پوشهٔ `750` را باز نمی‌کند. `sudo ls -la` برای دیدن کافی است. دومی یا مسیر نیست، یا اگر با `ls -ld` روی والد نگاه کنید پیوند شکسته است.

پارس `ls` در اسکریپت با نام فایلِ دارای فاصله می‌شکند. alias مثل `ll` در پوستهٔ تعاملی هست و در `cron` نیست.

## cd

### توضیح

`cd` دایرکتوری جاری پوسته را عوض می‌کند و builtin خود bash است، نه یک باینری. برای همین `sudo cd /root` اثری روی پوستهٔ شما ندارد. `sudo` فرایند جدا می‌سازد و همان‌جا تمام می‌شود.

- بدون آرگومان، یا با `~`، به خانه می‌رود.
- `cd -` به مقدار `OLDPWD` برمی‌گردد و مسیر جدید را چاپ می‌کند.
- شکست `cd` با `set -e` اسکریپت را قطع می‌کند. این را می‌خواهیم. ادامه بعد از `cd` ناموفق یعنی دستور بعدی در مسیر غلط است.
- `cd` داخل خط لوله در زیرپوسته است و والد را جابه‌جا نمی‌کند.

### مثال واقعی

```bash
cd /var/log/nginx
pwd
cd /opt/apps/shop
pwd
cd -
pwd
```

```text
/var/log/nginx
/opt/apps/shop
/var/log/nginx
/var/log/nginx
```

خط سوم را خود `cd -` چاپ می‌کند. یک بار دیگر `cd -` برمی‌گردد به `/opt/apps/shop`. اگر مقصد قبلی پاک شده باشد، یا هنوز هیچ `cd` موفقی نبوده:

```text
bash: cd: /tmp/build-old: No such file or directory
bash: cd: OLDPWD not set
```

### کاربرد Production

روی `app-1` بین `/var/log/nginx` و `/opt/apps/shop/current` با `cd -` جابه‌جا شوید تا مسیر بلند را غلط تایپ نکنید. قبل از دستور مخرب `pwd` را ببینید. در اسکریپت استقرار:

```bash
cd /opt/apps/shop/releases/20260923-0210 || exit 1
pwd
```

`|| exit 1` حتی بدون `set -e` جلوی ادامه در مسیر غلط را می‌گیرد. اسکریپت از `cron` یا CI روی `10.10.1.10` دایرکتوری تعاملی شما را به یاد ندارد.

### وقتی خراب می‌شود

`Permission denied` یعنی بیت اجرا روی یکی از دایرکتوری‌های مسیر نیست. `No such file or directory` یعنی جزئی از مسیر نیست. این دو یکی نیستند.

اگر دیسک داده mount نشده باشد، `cd` به پوشهٔ خالی mountpoint روی دیسک ریشه می‌رود و خطا نمی‌دهد. قبل از نتیجه‌گیری که داده پاک شده، [findmnt](/docs/01-linux/commands-disk) را ببینید. اگر `cd` به جای غیرمنتظره رفت، `CDPATH` را در پروفایل `ops` چک کنید. روی سرور Production این متغیر نباید ست باشد.

## cp

### توضیح

`cp -a` شکل کپی درخت سرویس است. در coreutils گنو `-a` همان `--archive` و معادل `-dR --preserve=all` است: بازگشتی، حفظ پیوند نمادین به‌صورت پیوند (بدون باز کردن هدف)، و حفظ حالت، مالکیت، زمان، پیوند سخت، xattr و context تا جایی که اجازه باشد.

`-r` خالی این‌ها را کامل حفظ نمی‌کند. اگر مقصد از قبل دایرکتوری باشد، مبدأ داخلش کپی می‌شود. `cp -a /opt/apps/shop /var/backups` نتیجه را در `/var/backups/shop` می‌گذارد و اگر آن پوشه باشد یک لایهٔ تودرتو می‌سازد. کاربر غیر root اغلب مالکیت را حفظ نمی‌کند و کد خروج غیرصفر می‌شود، حتی اگر بایت‌ها رسیده باشند. `cp` اتمیک نیست. فایل مقصد در میانهٔ کار ناقص دیده می‌شود. جایگزینی فایل زنده کار `mv` است.

### مثال واقعی

```bash
sudo cp -a /opt/apps/shop/releases/20260923-0210 /var/backups/shop-20260923-0210
sudo ls -ld /var/backups/shop-20260923-0210
stat -c '%d %n' /opt/apps/shop /var/backups
```

```text
drwxr-xr-x 8 deploy deploy 4096 Sep 23 02:10 /var/backups/shop-20260923-0210
2049 /opt/apps/shop
2049 /var/backups
```

اگر عدد دستگاه فرق داشت، کپی بین‌دیسکی است. بدون `sudo`، وقتی مالک حفظ نشود:

```text
cp: preserving ownership for '/var/backups/shop.env.20260923': Operation not permitted
```

فایل هست، کد خروج ۱ است، و `set -e` اسکریپت را می‌خواباند. یا با `sudo` کپی کنید یا آگاهانه این خطا را دور نریزید.

### کاربرد Production

قبل از تعویض انتشار روی `app-1` یک کپی آرشیوی از انتشار فعلی در `/var/backups` بگیرید تا برگشت فقط به git وابسته نباشد. نام مقصد تاریخ دارد تا روی بکاپ دیروز ننویسید. بعد `du -sh` مبدأ و مقصد را مقایسه کنید. اختلاف زیاد یعنی کپی ناقص.

روی `db-1` دایرکتوری زندهٔ `/var/lib/postgresql/18/main` را با `cp -a` بر ندارید. فایل‌های باز کپی ناسازگار می‌سازند. بکاپ پایگاه ابزار خودش را دارد. `cp -a` برای درخت برنامه، پیکربندی، و دامپ از قبل بسته‌شده است.

### وقتی خراب می‌شود

```text
cp: cannot create regular file '/opt/apps/shop/shared/.env': Permission denied
cp: cannot stat '/opt/apps/missing': No such file or directory
cp: error writing '/var/backups/shop-20260923-0210/app.js': No space left on device
```

سومی درخت را نیمه می‌سازد. مقصد ناقص بکاپ سالم نیست. فضا را با `df -h` ببینید، ناقص را بردارید، دوباره کپی کنید. `-i` فقط در پوستهٔ انسان برای فایل حساس است. در اسکریپت مقصد را با نام یکتا بسازید. `-L` پیوند را باز می‌کند. یک پیوند اشتباه به دایرکتوری بزرگ، کپی را به جایی می‌برد که قصد نداشتید. برای درخت سرویس `-a` بماند.

## mv

### توضیح

اگر مبدأ و مقصد روی یک فایل‌سیستم باشند، `mv` یک `rename` است و اتمیک است. دیگران یا فایل قدیمی را می‌بینند یا جدید را، نه محتوای نیمه‌نوشته. اگر دو فایل‌سیستم باشند، `mv` کپی می‌کند و بعد مبدأ را پاک می‌کند. دستور آخرش موفق است ولی میانه اتمیک نیست و گنو این را با خطا اعلام نمی‌کند. عدد دستگاه را با `stat -c '%d'` مقایسه کنید. قاعده: فایل موقت را در همان دایرکتوری مقصد بسازید.

`-T` مقصد را دایرکتوری فرض نمی‌کند تا فایل داخل یک پوشهٔ هم‌نام قایم نشود. `-n` روی موجود نمی‌نویسد. `-i` می‌پرسد و مال اسکریپت نیست.

### مثال واقعی

```bash
install -o deploy -g deploy -m 640 /dev/null /opt/apps/shop/shared/.env.new
stat -c '%d %n' /opt/apps/shop/shared /opt/apps/shop/shared/.env.new
sudo mv -T /opt/apps/shop/shared/.env.new /opt/apps/shop/shared/.env
sudo ln -s /opt/apps/shop/releases/20260923-0210 /opt/apps/shop/current.new
sudo mv -T /opt/apps/shop/current.new /opt/apps/shop/current
ls -ld /opt/apps/shop/current
```

عدد دستگاه هر دو مسیر باید یکی باشد. `install` حالت را از اول درست می‌گذارد تا بین ساخت و `mv` یک فایل خوانا برای همه وجود نداشته باشد. `ln -sfn` روی هر سیستمی اتمیک نیست. پیوند موقت کنار قبلی و `mv -T` در همان دایرکتوری اتمیک است.

### کاربرد Production

روی `app-1` این الگو برای `shared/.env` و برای پیوند `current` اجباری است. انتشار جدید اول زیر `releases/20260923-0210` کامل می‌شود. تا `mv` نشده ترافیک روی قبلی می‌ماند. برگشت، `mv` در جهت عکس است، به شرطی که انتشار قبلی را پاک نکرده باشید.

روی `db-1` فایل جدول را با `mv` «کنار نزنید». برای لاگ، اگر فرایند هنوز فایل را باز دارد فضا آزاد نمی‌شود. توضیحش در صفحهٔ دیسک است.

### وقتی خراب می‌شود

```text
mv: cannot move '/opt/apps/shop/shared/.env.new' to '/opt/apps/shop/shared/.env': Permission denied
mv: error writing '/var/backups/.env': No space left on device
```

اولی معمولاً یعنی دایرکتوری والد برای شما قابل نوشتن نیست. دومی مال جابه‌جایی بین‌دیسکی است: مقصد ناقص است و مبدأ شاید هنوز باشد. قبل از تلاش دوباره هر دو مسیر را با `ls -l` ببینید. برای فایل زنده، موقت را همان‌جا بسازید تا این حالت پیش نیاید.

## rm

### توضیح

`rm` ورودی دایرکتوری را برمی‌دارد. `-r` بازگشتی است و `-f` پرسش را خاموش می‌کند. ترکیب `-rf` همان حادثه است.

گنو `rm` پیش‌فرض `--preserve-root` دارد و این یکی را رد می‌کند:

```bash
rm -rf /
```

```text
rm: it is dangerous to operate recursively on '/'
rm: use --no-preserve-root to override this failsafe
```

حفاظ فقط خود `/` است. `rm -rf /*` را نگه نمی‌دارد، چون پوسته ستاره را به نام‌های سطح اول باز می‌کند. متغیر خالی هم خطرناک است: اگر مسیر بکاپ ست نشده باشد و `set -u` خاموش باشد، الگوی «محتوای این متغیر» به `/*` تبدیل می‌شود. `--no-preserve-root` را به اسکریپت اضافه نکنید.

تفاوت با `find`: `rm` فقط نام‌هایی را می‌گیرد که پوسته همین حالا داده. هزاران فایل با ستاره، قبل از اجرای `rm` به سقف آرگومان می‌خورد. `find` درخت را خودش می‌رود و می‌شود اول فهرست را دید. برای «قدیمی‌تر از سی روز» ابزار `find` است نه ستاره.

`rm` خود پیوند را برمی‌دارد نه هدف را. ته مسیر اگر اسلش باشد، پیوند دایرکتوری دنبال می‌شود. `rm -rf /opt/apps/shop/current` فقط پیوند را برمی‌دارد. همان مسیر با اسلش ته، محتوای انتشار فعال را پاک می‌کند. ستاره هم هدف را باز می‌کند: پوسته محتوای انتشار را به `rm` می‌دهد و پیوند سر جایش می‌ماند.

### مثال واقعی

```bash
ls -ld /opt/apps/shop/current
ls -ld /opt/apps/shop/releases/20260801-0900
sudo rm -rf /opt/apps/shop/releases/20260801-0900
```

```text
lrwxrwxrwx 1 deploy deploy 32 Sep 23 02:14 /opt/apps/shop/current -> releases/20260923-0210
drwxr-xr-x 8 deploy deploy 4096 Aug  1 09:00 /opt/apps/shop/releases/20260801-0900
```

انتشار فعال در دستور نیست. اگر ستاره را به انبوه لاگ بدهید، `rm` اصلاً شروع نمی‌شود:

```text
bash: /usr/bin/rm: Argument list too long
```

خطا مال bash است. راه‌حل، `find` پایین است نه بالا بردن سقف آرگومان.

### کاربرد Production

روی `app-1` سه انتشار آخر می‌مانند. قدیمی‌تر فقط با نام کامل پوشه پاک می‌شود، بعد از `ls -ld` روی `current`. ستاره داخل `releases/` ممنوع است. اسکریپت باید `set -u` داشته باشد، مسیر را نقل‌قول کند، و اگر مسیر زیر `releases` نبود بایستد.

روی `db-1` دستور `rm -rf` زیر `/var/lib/postgresql` در کار روزمره جایی ندارد. فضای پر با نگهداری خود PostgreSQL 18 کم می‌شود. حذف فایل جدول یعنی خاموشی یا خرابی کلاستر.

### وقتی خراب می‌شود

```text
rm: cannot remove '/var/log/nginx/access.log': Permission denied
rm: cannot remove '/var/backups/dump': Device or resource busy
```

دومی را روی نقطهٔ mount یا فایل درگیر می‌بینید. تکرار `-rf` درمان نیست. با `lsof` و `fuser` ببینید چه کسی مسیر را گرفته، مثل `umount` در صفحهٔ دیسک.

`rm` فایل باز را از فهرست حذف می‌کند ولی فضا تا بستن توصیف‌گر آزاد نمی‌شود. `df` تکان نمی‌خورد. دوباره حذف نکنید. دنبال فرایند بگردید. پاک کردن `.env` تا ری‌استارت بعدی سرویس را ظاهراً زنده نگه می‌دارد و ری‌استارت بعدی بالا نمی‌آید. برگشت از `/var/backups` است. سطل زباله وجود ندارد.

## find

### توضیح

`find` درخت را می‌رود و عبارت را از چپ به راست با «و» ضمنی امتحان می‌کند. اقدام هم یک آزمون است. اگر اقدام قبل از فیلتر باشد، فیلتر دیر می‌رسد. مسیر شروع را مشخص بنویسید. `find /` کار سرور نیست. `-xdev` از فایل‌سیستم جاری بیرون نمی‌رود.

- `-type f` فایل معمولی است. `-name` الگوی پوسته است نه عبارت منظم. الگو را نقل‌قول کنید وگرنه پوسته ستاره را باز می‌کند.
- `-mtime -7` سن کمتر از هفت شبانه‌روز ۲۴ساعته، `+30` قدیمی‌تر از سی روز. کسر روز دور ریخته می‌شود. برای ساعت، `-mmin -120`. خود `-mtime 7` یعنی دقیقاً همان روز و معمولاً اشتباه است.
- `-size +100M` بزرگ‌تر از ۱۰۰ مبی‌بایت است، نه مگابایت ده‌دهی. بایت دقیق پسوند `c` دارد.
- `-user deploy` مالک را محدود می‌کند.
- اول `-print` یا `-printf`. حذف بعد از خواندن همان فهرست است.
- `-delete` حذف می‌کند و `-depth` را هم روشن می‌کند. هرگز قبل از آزمون‌ها نگذاریدش.
- `-exec` با نقطه‌ویرگول برای هر فایل یک‌بار اجرا می‌کند. شکل `+` چند مسیر را در یک اجرا جمع می‌کند و به سقف آرگومان احترام می‌گذارد. هر دو شکل را در نمونهٔ پایین ببینید.

`cp -a` زمان فایل را حفظ می‌کند. داخل انتشار امروز فایل با mtime ماه پیش طبیعی است. برای پاک کردن انتشار کهنه، پوشهٔ سطح اول را با نام تاریخ انتخاب کنید، نه هر فایلی که mtime قدیمی دارد.

پیدا نشدن فایل کد ۰ است. کد غیرصفر یعنی خطا در راه‌رفتن، مثلاً مجوز، حتی اگر چند مسیر چاپ شده باشد. این برعکس `grep` است که در [پردازش متن](/docs/01-linux/commands-text) کد ۱ را برای «چیزی نبود» برمی‌گرداند.

### مثال واقعی

```bash
sudo find /var/log/nginx -xdev -type f -name 'access.log.*.gz' -mtime +30 -printf '%TY-%Tm-%Td %10s %p\n'
sudo find /var/log -xdev -type f -size +100M -printf '%10s %p\n' | sort -n
sudo find /opt/apps/shop -xdev -type f -user deploy -mtime -1 -printf '%u %p\n'
```

```text
2026-07-01    1048576 /var/log/nginx/access.log.20260701.gz
 157286400 /var/log/nginx/access.log
deploy /opt/apps/shop/shared/.env
```

حذف فقط با همان آزمون‌ها، بعد از خواندن فهرست:

```bash
sudo find /var/log/nginx -xdev -type f -name 'access.log.*.gz' -mtime +30 -delete
sudo find /var/log/nginx -xdev -type f -name 'error.log.*.gz' -mtime +30 -exec rm -v {} \;
sudo find /var/log/nginx -xdev -type f -name 'error.log.*.gz' -mtime +14 -exec rm -v {} +
```

این یکی غلط است. `-delete` اولین اقدام است و همه‌چیز زیر مسیر شروع را برمی‌دارد، بعد تازه نام را امتحان می‌کند:

```bash
find /var/log/nginx -delete -name '*.gz'
```

این خط را کپی نکنید. ترتیب درست: مسیر، `-xdev`، نوع، نام، سن، و آخر اقدام.

انتشارها را از روی نام سطح اول ببینید، نه mtime فایل داخلی:

```bash
sudo find /opt/apps/shop/releases -mindepth 1 -maxdepth 1 -type d -printf '%TY-%Tm-%Td %p\n' | sort
```

```text
2026-08-01 /opt/apps/shop/releases/20260801-0900
2026-09-23 /opt/apps/shop/releases/20260923-0210
```

بعد فقط پوشه‌ای که `current` نشان نمی‌دهد با `rm -rf` و مسیر کامل برداشته می‌شود.

### کاربرد Production

نگهداری لاگ nginx روی `app-1` با همین `find` در تایمر systemd است، با مسیر ثابت `/var/log/nginx`. قبل از گذاشتن `-delete` در تایمر، یک بار `-printf` را دستی اجرا کنید و خروجی را در تیکت بگذارید. تایمر از `/` شروع نکند و `-L` نداشته باشد. `-L` پیوند را دنبال می‌کند و با حذف، خارج از درخت مورد نظر هم پاک می‌کند.

فایل بزرگ را با `-size +100M` زیر `/var` و `/opt/apps` پیدا کنید. دامپ اشتباهی داخل `releases/` را با دست بردارید، نه با قاعدهٔ سنی. روی `db-1` جست‌وجوی اندازه در `/var/backups` مجاز است. `-delete` زیر `/var/lib/postgresql/18/main` مجاز نیست.

### وقتی خراب می‌شود

```text
find: ‘/var/log/private’: Permission denied
find: cannot delete ‘/var/log/nginx/access.log.1.gz’: Permission denied
```

اولی کد خروج را غیرصفر می‌کند و با `set -e` اسکریپت را می‌کشد حتی اگر چند خط چاپ شده باشد. برای لاگ از `sudo` استفاده کنید. `|| true` خطای مسیر غلط را هم قورت می‌دهد. دومی یعنی آزمون درست بوده و اجازه نه.

`Argument list too long` مال شکل `+` از `-exec` نیست. هنوز دارید ستاره را به `rm` می‌دهید. شکست بی‌صدا: `-mtime` روی درخت `cp -a` فایل انتشار امروز را هم «قدیمی» نشان می‌دهد. اگر ماژول امروز غیب شده، علت همین حذف بوده است.

## Best Practices

- قبل از حذف، همان دستور را بدون `-delete` و بدون `rm` اجرا کنید. چند خط اول و آخر را در تیکت بگذارید.
- `ls -la` برای `.env` و `ls -ld` برای خود `current`. درخت را با `cp -a` کپی کنید. فایل زنده را در همان دایرکتوری موقت بنویسید و با `mv -T` عوض کنید، بعد از یکی بودن عدد `stat -c '%d'`.
- `rm -rf` فقط با مسیر کامل. `set -u` روشن باشد. ته مسیر روی پیوند `current` اسلش نگذارید. `--no-preserve-root` و ستاره روی `/` ممنوع.
- `find` را از ریشهٔ مشخص با `-xdev` شروع کنید، نام را نقل‌قول کنید، و `-delete` را آخر عبارت بگذارید. mtime داخل انتشاری که با `-a` کپی شده معیار پاک‌کردن آن انتشار نیست.
- خطای `Argument list too long` را با `find` و اقدام انتهایی حل کنید، نه با بالا بردن سقف آرگومان پوسته.
- اگر بعد از حذف `df` تکان نخورد، فایل هنوز باز است. سراغ [دیسک و اتصال](/docs/01-linux/commands-disk) بروید.
