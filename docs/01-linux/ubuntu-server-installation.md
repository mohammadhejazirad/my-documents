# نصب Ubuntu Server

## مقدمه

این صفحه یک Ubuntu Server 26.04 LTS را از ISO تا اولین ورود SSH بالا می‌آورد. نقطهٔ مرجع 26.04.1 است. نام رمز توزیع Resolute Raccoon است و در فایل مخزن به‌صورت `resolute` دیده می‌شود. اگر ماشین هنوز ساخته نشده، اول [ساخت ماشین مجازی](/docs/01-linux/virtual-machine) را انجام دهید و با ISO همان صفحه برگردید. طرح پارتیشن را از [پارتیشن‌بندی](/docs/01-linux/partitioning) برمی‌داریم و این‌جا فقط همان تصمیم را داخل نصب‌کننده اعمال می‌کنیم.

نصب‌کنندهٔ سرور Subiquity است و روی کنسول متنی یا سریال کار می‌کند. زبان رابط را English بگذارید. لاگ بسته و پیام systemd انگلیسی می‌مانند و با بقیهٔ دانشنامه یکی می‌شوند. منطقهٔ زمانی جداگانه `Asia/Tehran` است. محلی که بسته و مرتب‌سازی با آن کار می‌کنند `en_US.UTF-8` می‌ماند.

Debian 13 با همین ISO نصب نمی‌شود. debian-installer صفحهٔ دیگری دارد. بعد از نصب، دستورهای APT و systemd این دانشنامه روی هر دو صدق می‌کند، به شرطی که نام suite و مسیر فایل مخزن را از صفحهٔ [مخزن APT](/docs/01-linux/apt-repository-mirror) بردارید.

## مفهوم اصلی

ISO لایو است. سیستم‌عاملی که بعد از ری‌بوت بالا می‌آید روی دیسک کپی شده، نه خود ISO. تا وقتی رسانه را جدا نکرده‌اید ممکن است دوباره وارد نصب‌کننده شوید و فکر کنید نصب خراب است. ترتیب بوت بعد از پایان کار باید دیسک باشد، نه CD.

نصب‌کننده سه جور خروجی به جا می‌گذارد که بعداً دست می‌خورند: جدول پارتیشن و LVM، فایل Netplan زیر `/etc/netplan`، و کاربر اولیه که عضو گروه `sudo` است. OpenSSH فقط اگر در همان نصب انتخاب شود روی سیستم مقصد فعال است. SSH خود محیط نصب‌کننده چیز دیگری است. ISO سرور گاهی برای کمک از راه دور یک نشست نصب با رمز تصادفی چاپ‌شده روی کنسول باز می‌کند. آن رمز مال همان بوت نصب است، در سیستم نصب‌شده کپی نمی‌شود، و نباید در مستند یا چت بماند.

کاربر اولیهٔ این آزمایشگاه `ops` است. نام سرور برنامه `app-1` و FQDN آن `app-1.example.internal` است. IP ثابت `10.10.1.10/16` است. دروازهٔ نمونه `10.10.0.1` است. اگر در شبکهٔ شما دروازه فرق دارد فقط همان یک عدد را عوض کنید.

## چرا استفاده می‌شود؟

نصب تعاملی را یک بار کامل یاد می‌گیرید تا بدانید هر انتخاب نصب‌کننده روی دیسک چه فایلی می‌سازد. سرور دوم به بعد را می‌شود با cloud image یا autoinstall تکرار کرد. آن میانبرها در صفحهٔ ماشین مجازی آمده‌اند و طرح LVM این صفحه را خودبه‌خود نمی‌سازند. برای `app-1` و `db-1` نصب از ISO با طرح سفارشی انتخاب این دانشنامه است.

به‌روزرسانی بلافاصله بعد از اولین بوت اجباری است. ISO نقطهٔ 26.04.1 تصویر روز انتشار همان نقطه است، نه تصویر امروز آرشیو. بین ساخت ISO و امروز شما بستهٔ امنیتی آمده است. `apt update` فقط فهرست را تازه می‌کند. خود به‌روزرسانی دستور جداست و در [مدیریت بسته با APT](/docs/01-linux/apt-package-management) معنی تفاوت `upgrade` و `full-upgrade` آمده است. شب نصب، اگر هسته عوض شد، یک ری‌بوت برنامه‌ریزی‌شده بدهید تا میزبان واقعاً روی هستهٔ جدید باشد.

## Architecture

```text
لپ‌تاپ مدیر                         میزبان نصب
ssh-keygen (ed25519)                ISO 26.04.1 روی CD مجازی
        |                                  |
        |                            Subiquity
        |                              |  شبکهٔ ثابت 10.10.1.10/16
        |                              |  دیسک: EFI + /boot + LVM
        |                              |  کاربر ops در گروه sudo
        |                              |  OpenSSH + کلید عمومی
        |                                  |
        +-------- SSH به ops@10.10.1.10 ---+
                                           |
                                    apt update && apt upgrade
                                           |
                                    ری‌بوت اگر هسته عوض شد
```

رسانهٔ نصب به اینترنت یا به آینهٔ `mirror.example.internal` نیاز دارد تا در طول نصب به‌روزرسانی امنیتی را بگیرد. اگر هیچ‌کدام در دسترس نیست، نصب را با آرشیو داخل ISO تمام کنید و همان شب، قبل از شنیدن سرویس روی شبکه، صفحهٔ آینه را اجرا کنید. سرور با بستهٔ کهنه را به امید «بعد از رفتن به تولید» رها نکنید.

## Installation

ISO را از فهرست رسمی همان انتشار بگیرید، نه از لینک بازنشرشده در یک وبلاگ. مبنای این متن:

```text
https://releases.ubuntu.com/26.04/ubuntu-26.04.1-live-server-amd64.iso
```

اگر در آن پوشه نقطهٔ جدیدتری از 26.04 منتشر شده، همان live-server مخصوص amd64 را بردارید و نام فایل را در یادداشت تغییر بدهید. فایل `SHA256SUMS` همان پوشه را هم بگیرید. چک‌سام را از حافظه ننویسید.

```bash
sha256sum ubuntu-26.04.1-live-server-amd64.iso
grep ubuntu-26.04.1-live-server-amd64.iso SHA256SUMS
```

دو رشته باید یکی باشند. اگر نیستند فایل را پاک کنید و دوباره بگیرید. امضای `SHA256SUMS.gpg` را با کلید آرشیو Ubuntu بررسی کنید اگر ابزار GPG را روی ایستگاه مدیر دارید. ISO بدون تطابق چک‌سام نصب نمی‌شود.

رسانه را به VM وصل کنید. بوت را روی UEFI بگذارید. Secure Boot در آزمایشگاه خاموش باشد تاfirmware جلوی اولین بوت را نگیرد. Ubuntu 26.04 خودش Secure Boot را پشتیبانی می‌کند. در تولیدی که سیاست سازمان Secure Boot می‌خواهد، shim امضاشدهٔ همان ISO را استفاده کنید و این میانبر آزمایشگاه را کپی نکنید.

در منوی بوت، Install Ubuntu Server را بزنید. اگر صفحه خالی ماند، کنسول گرافیکی VM را ببینید. نصب با `console=ttyS0` فقط وقتی صفحه دارد که سریال را هم به نصب‌کننده داده باشید. مسیر ساده برای نصب تعاملی، کنسول گرافیکی یا VNC روی localhost است. آن را به `0.0.0.0` باز نکنید.

انتخاب‌ها به ترتیب صفحه‌های Subiquity:

1. زبان English. صفحه‌کلید همان چیدمانی که واقعاً وسط رمز از آن استفاده می‌کنید. رمز را با دو چیدمان مختلف تایپ نکنید.
2. نوع نصب Ubuntu Server. نسخهٔ minimized ابزار روزمره مثل صفحات man را ندارد. برای میزبان آزمایشگاه نوع معمولی را بگذارید.
3. شبکه. نام رابط را یادداشت کنید. DHCP آزمایشگاه آدرس `10.10.1.10` را تضمین نمی‌کند. رابط را ویرایش کنید: آدرس `10.10.1.10/16`، دروازه `10.10.0.1`، دی‌ان‌اس همان رزولوری که نام `example.internal` را حل می‌کند. اگر چنین رزولوری روی `proxy.example.internal` نیست، IP واقعی DNS را بگذارید و بعد از بوت فایل میزبان‌ها را هم بنویسید.
4. پروکسی. اگر تنها خروجی شبکه `10.10.1.5` است مقدار `http://10.10.1.5:3128` را بدهید. وگرنه خالی بگذارید. پروکسی دارای رمز را در این صفحه با رمز واقعی پر نکنید اگر آن رمز در لاگ نصب می‌ماند. شکل فایل پروکسی بعد از نصب در صفحهٔ آینه است.
5. آینه. پیش‌فرض `http://archive.ubuntu.com/ubuntu` است. اگر آرشیو از این شبکه تایم‌اوت می‌دهد همان‌جا `http://mirror.example.internal/ubuntu` را بگذارید، به شرطی که آینه واقعاً suite به نام `resolute` را با امضای رسمی داشته باشد.
6. دیسک. Use an entire disk را با تیک LVM فقط وقتی بپذیرید که بعداً پارتیشن جدا برای `/var` نمی‌خواهید. برای سرور این دانشنامه Custom storage layout را باز کنید و طرح صفحهٔ پارتیشن را بسازید: EFI حدود ۱ گیگ، `/boot` حدود ۲ گیگ از جنس ext4 بیرون از LVM، بقیهٔ دیسک یک physical volume، و روی آن logical volume برای `/` و swap و `/var` و `/home`. سیستم‌فایل `/` و `/boot` در این نصب ext4 است. رمزنگاری LUKS را در آزمایشگاه خاموش بگذارید مگر کنسول فیزیکی برای وارد کردن passphrase بوت دارید. بدون آن passphrase، ری‌بوت یعنی قطع دسترسی.
7. پروفایل. نام شما، نام سرور `app-1`، نام کاربر `ops`، رمز اولیه. این رمز همان `change-me` مستند نیست اگر نصب‌کننده رمز قوی‌تر بخواهد. هرچه گذاشتید بعد از اولین ورود عوض می‌شود و در تیکت نوشته نمی‌شود. این کاربر عضو گروه `sudo` ساخته می‌شود. حساب روت جدا برای ورود ساخته نمی‌شود و همین درست است.
8. Ubuntu Pro را در آزمایشگاه Skip کنید. بدون توکن، فعال‌کردنش نصب را معطل می‌کند.
9. SSH. Install OpenSSH server را روشن کنید. کلید عمومی `ed25519` را وارد کنید اگر از قبل دارید. Import از GitHub شخصی را برای سرور سازمان استفاده نکنید. هیچ snap اضافه‌ای را برای میزبان پایه انتخاب نکنید.
10. نصب را شروع کنید. در پایان Reboot Now. ISO را جدا کنید. اگر دوباره منوی نصب آمد، بوت هنوز روی رسانه است.

اگر بوت بعدی به shell اضطراری افتاد، UUID در fstab با دیسک یکی نیست. از صفحهٔ [فایل‌سیستم](/docs/01-linux/filesystems) ادامه دهید. نصب را از نو شروع نکنید تا `blkid` را ندیده‌اید.

## Configuration

اولین ورود از کنسول VM با کاربر `ops` است. اگر کلید را در نصب گذاشته‌اید، از ایستگاه مدیر:

```bash
ssh -i ~/.ssh/id_ed25519 ops@10.10.1.10
```

اگر کلید هنوز ندارید، روی ایستگاه مدیر و نه روی سرور:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -C "ops@admin"
```

عبارت عبور برای کلید بگذارید. کلید بدون عبارت عبور فقط برای آزمایشگاهی است که دیسک لپ‌تاپ خودش رمز دارد، و حتی آنجا هم ترجیح با عبارت عبور است. کلید خصوصی را به سرور کپی نکنید. فقط خط `.pub` مجاز است. نصب کلید روی سرور:

```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub ops@10.10.1.10
```

اگر `ssh-copy-id` رمز خواست و رمز ورود را بسته‌اید، از کنسول خود VM خط عمومی را در `/home/ops/.ssh/authorized_keys` بگذارید. حالت پوشه `0700` و حالت فایل `0600` و هر دو مال `ops` باشند. وگرنه sshd کلید را نادیده می‌گیرد.

منطقهٔ زمانی و نام میزبان:

```bash
timedatectl
sudo timedatectl set-timezone Asia/Tehran
sudo timedatectl set-ntp true
hostnamectl
sudo hostnamectl set-hostname app-1.example.internal
```

خروجی سالم `timedatectl` منطقهٔ `Asia/Tehran` و `System clock synchronized: yes` را نشان می‌دهد. اگر NTP منفی ماند، دروازه یا پروکسی ساعت را بسته است. تا وقتی ساعت غلط است امضای APT و گواهی بعداً به شکل خطای عجیب رد می‌شوند.

فایل `/etc/hosts` را با این محتوا جایگزین کنید. IP میزبان‌های دیگر آزمایشگاه ثابت است.

```text
127.0.0.1 localhost
10.10.1.5 proxy.example.internal proxy
10.10.1.10 app-1.example.internal app-1
10.10.1.20 db-1.example.internal db-1
10.10.1.30 docker-1.example.internal docker-1
10.10.1.40 mon-1.example.internal mon-1
10.10.1.50 gitlab.example.internal gitlab
10.10.1.60 mirror.example.internal mirror
```

روی `db-1` همان فایل را بگذارید. فقط یادتان باشد نام کوتاه خود آن میزبان باید در خط IP واقعی خودش باشد، نه روی `127.0.0.1`.

Netplan نصب‌کننده معمولاً اینجاست:

```bash
ls /etc/netplan
ip -br addr
```

اگر آدرس `10.10.1.10/16` روی رابط بالا نیست، فایل را درست کنید. نام فایل رایج `00-installer-config.yaml` است. نام رابط را از `ip -br link` بردارید. نمونه برای libvirt:

```yaml
network:
  version: 2
  ethernets:
    enp1s0:
      dhcp4: false
      addresses:
        - 10.10.1.10/16
      routes:
        - to: default
          via: 10.10.0.1
      nameservers:
        addresses:
          - 10.10.1.5
```

`10.10.1.5` در این بلوک فقط وقتی رزولور است که DNS آزمایشگاه واقعاً آنجا گوش بدهد. وگرنه IP رزولور سازمان را بگذارید. اعمال تنظیم با مهلت بازگشت:

```bash
sudo netplan try
```

اگر Enter را نزنید تنظیم قبلی برمی‌گردد. `sudo netplan apply` بدون `try` وقتی دروازه غلط باشد جلسهٔ SSH را قطع می‌کند و فقط کنسول VM می‌ماند. روی Proxmox اگر نام رابط `ens18` است همان را در کلید Netplan بگذارید. کلید اشتباه یعنی فایل معتبر است ولی هیچ رابطی آن آدرس را نمی‌گیرد. `netplan try` در این حالت اغلب هشدار می‌دهد که تعریف استفاده نشد.

شناسهٔ سیستم نصب‌شده:

```bash
cat /etc/os-release
```

شکل سالم:

```text
PRETTY_NAME="Ubuntu 26.04.1 LTS"
NAME="Ubuntu"
VERSION_ID="26.04"
VERSION_CODENAME=resolute
```

اگر `VERSION_CODENAME` چیز دیگری است، بقیهٔ مثال‌های APT این فصل را کور اجرا نکنید.

## Production Example

به‌روزرسانی اولین بوت، قبل از ساخت کاربر اضافه و قبل از کپی برنامه:

```bash
sudo apt update
sudo apt upgrade
```

`apt update` باید خط `Hit` یا `Get` برای suiteهای `resolute` و `resolute-updates` و `resolute-security` بدهد. خط `noble` روی این میزبان یعنی آینه یا فایل منابع مال انتشار قبلی است. نمونهٔ موفقیت، کوتاه‌شده:

```text
Hit:1 http://archive.ubuntu.com/ubuntu resolute InRelease
Hit:2 http://archive.ubuntu.com/ubuntu resolute-updates InRelease
Hit:3 http://security.ubuntu.com/ubuntu resolute-security InRelease
Reading package lists... Done
```

اگر به‌جای این متن تایم‌اوت یا `404 Not Found` دیدید، به [مخزن، آینه و پروکسی APT](/docs/01-linux/apt-repository-mirror) بروید. `upgrade` را روی فهرست خراب تکرار نکنید.

وقتی `upgrade` هسته یا `linux-image` را عوض کرد:

```bash
sudo reboot
```

بعد از برگشتن:

```bash
uname -r
systemctl is-active ssh.socket ssh.service
ss -lptn 'sport = :22'
id ops
```

خروجی `id` باید گروه `sudo` را نشان بدهد. `ss` باید شنونده روی `0.0.0.0:22` یا `*:22` نشان بدهد. یکی از دو واحد `ssh.socket` یا `ssh.service` باید `active` باشد. معمولی روی این نسل Ubuntu سوکت است. اگر هر دو `inactive` هستند، OpenSSH در نصب انتخاب نشده:

```bash
sudo apt install openssh-server
sudo systemctl enable --now ssh.socket
```

اگر `enable` روی سوکت در نسخهٔ شما واحد را بالا نیاورد، همان دستور را برای `ssh.service` بزنید و دوباره `ss` را ببینید. حدس نزنید کدام واحد شنونده است.

ورود آزمایشی `sudo`:

```bash
sudo -v
sudo -l
```

باید رمز `ops` را بپرسد و بعد دستورهای مجاز را به‌صورت `(ALL : ALL) ALL` برای گروه sudo نشان بدهد. اگر بدون رمز روت شد، یک فایل در `/etc/sudoers.d` از محیط نصب مانده است. آن رفتار مال کاربر نصب‌کنندهٔ لایو است و نباید روی سیستم نصب‌شده بماند. صفحهٔ [sudo](/docs/01-linux/sudo) را قبل از ادامه باز کنید.

گام بعدی ساخت کاربر سرویس و طرح مجوز است: [مدیریت کاربر و گروه](/docs/01-linux/user-management). اگر `df -h` نشان داد همه‌چیز روی یک فایل‌سیستم `/` است و `/var` جدا نیست، قبل از کپی داده صفحهٔ پارتیشن را اجرا کنید. جدا کردن `/var` بعد از پر شدن دیسک بسیار سخت‌تر از ساختن LV در نصب است.

## Security Notes

- رمز روت برای SSH نگذارید و `PermitRootLogin yes` ننویسید. OpenSSH این توزیع حول 10.2 است. ورود مدیر با کلید `ed25519` است.
- رمز اولیهٔ نصب را همان روز عوض کنید: `passwd`. رمز را در فایل world-readable یا در تاریخچهٔ عمومی شل ذخیره نکنید.
- نشست SSH خود ISO، اگر استفاده شد، با خاموش شدن نصب‌کننده می‌میرد. رمز تصادفی چاپ‌شده روی کنسول را عکس نگیرید و در تیکت نگذارید.
- VNC نصب را به شبکهٔ اداری باز نکنید. اگر از ایستگاه مدیر می‌بینید، از تونل SSH تا `127.0.0.1` هایپروایزر استفاده کنید.
- سرور تازه را قبل از `apt upgrade` پشت یک نام عمومی مثل `app.example.com` قرار ندهید.
- گروه `sudo` یعنی روت با رمز. `ops` را بین چند نفر مشترک نکنید. هر انسان یک حساب جدا می‌خواهد و بعداً با همان گروه اضافه می‌شود.

## Troubleshooting

| نشانه | علت محتمل | کار |
| --- | --- | --- |
| بعد از ری‌بوت دوباره منوی ISO می‌آید | ترتیب بوت هنوز CD است | رسانه را جدا کنید و دیسک را اول بگذارید |
| `ssh: connect timed out` | IP یا دروازه غلط، یا VM پشت NAT است | از کنسول `ip -br addr` و صفحهٔ شبکهٔ VM |
| رمز قبول است ولی SSH می‌گوید Permission denied | کلید یا حالت فایل `authorized_keys` | `ls -ld ~/.ssh ~/.ssh/authorized_keys` باید `700` و `600` باشد |
| `sudo: ops is not in the sudoers file` | کاربر اولیه عوضی ساخته شده | با کنسول روت یا نشست باقی‌مانده `usermod -aG sudo ops` |
| `apt update` می‌گوید Release file is not valid yet | ساعت سیستم عقب است | `timedatectl` و NTP، بعد دوباره `apt update` |
| بوت می‌ماند روی `emergency mode` | fstab یا LV بالا نیامده | `journalctl -b -p err` از همان شل، سپس صفحهٔ فایل‌سیستم |
| پورت ۲۲ بسته است ولی بسته نصب است | سوکت enable نشده | `systemctl status ssh.socket ssh.service` |

اگر `netplan try` برگشت و چیزی نگفت، YAML را با فاصلهٔ خراب ذخیره کرده‌اید. تب را با فاصله عوض نکنید. Netplan تب را در فایل YAML دوست ندارد. از ویرایشگر همان فاصلهٔ نمونه را نگه دارید.

لاگ خود نصب روی سیستم نصب‌شده اینجاست:

```bash
ls /var/log/installer
```

وقتی نصب «تمام شد» ولی بسته‌ای که انتخاب کرده بودید نیست، این پوشه را ببینید قبل از اینکه نصب را پاک کنید و از صفر شروع کنید.

## Best Practices

- یک بار نصب تعاملی را تا `apt upgrade` و ورود با کلید تمام کنید. میانبر cloud image را برای میزبانی استفاده کنید که از دست رفتن دیسک‌ش مهم نیست، یا وقتی طرح LVM را جای دیگری تضمین کرده‌اید.
- زبان سرور English بماند، منطقهٔ زمانی تهران باشد، و نام میزبان FQDN آزمایشگاه باشد نه `ubuntu`.
- OpenSSH را در خود نصب روشن کنید. نصب بعدی بسته از روی کنسول ابری، وقتی کنسول هم خراب باشد، راه برگشت ندارد.
- ISO را بعد از بوت موفق جدا کنید. بوت تصادفی به نصب‌کننده روی دیسک پر، یک انتخاب اشتباه تا پاک شدن داده فاصله دارد.
- چک‌سام ISO را از `SHA256SUMS` همان دایرکتوری رسمی بخوانید. عدد داخل ویکی یا چت را معیار نگیرید.
- اولین دستور مدیریتی بعد از ورود `sudo apt update` است، نه کپی کردن برنامه در `/opt`.
